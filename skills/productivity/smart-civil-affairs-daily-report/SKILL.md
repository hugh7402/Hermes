# 陕西智慧民政项目日报智能体

## 功能说明

收到"陕西智慧民政项目双周任务和问题清单-YYYYMMDD.xlsx"后，自动完成：
1. 从文件名提取日期
2. 解析Excel数据，仅统计完成日期<=该日期的任务
3. 按负责人分组统计，拆分曾祥发/高凯悦
4. 提取延期/风险任务的问题描述
5. 生成Word日报，格式完全匹配样例文档

## 触发条件

1. **文件触发**：用户发送文件 `陕西智慧民政项目双周任务和问题清单-<日期>.xlsx`
2. **名称唤起**：用户说"启动陕西智慧民政项目日报"、"启动 smart-civil-affairs-daily-report"、"给我出一版日报"、"生成日报"
3. **微信场景**：用户通过微信发送触发词时，需先确认 Excel 文件是否存在（检查 `/opt/data/cache/documents/` 下最新 xlsx），然后自动处理

## 工作流程

### 第1步：读取文件与提取日期
- 文件路径：用户发送的文件缓存在 `/opt/data/cache/documents/` 下
- 从文件名正则提取日期：`r'双周任务和问题清单-(\d{8})'`
- 目标日期 = 该日期 23:59:59

### 第2步：解析Excel数据
- 读取Sheet1（双周任务清单），遍历每行
- 列映射：D=系统名称, F=任务内容, I=板块负责人, J=完成日期, K=完成状态, L=现存问题(**延期/风险用此列**), M=月份标签(6月/7月占位), N=推进措施
- ❗ M列仅存"6月"/"7月"等月份占位符，**实际问题在L列（"现存问题"）**，只从L列读取延期/风险问题的描述
- 读取Sheet2（任务完成统计透视）获取**权威负责人映射**（A=系统名称, B=负责人），优先于Sheet1的I列
- 筛选：完成日期(J列) <= 提取的日期，且系统名称不为空
- 统计各状态数量，按系统+负责人分组

### 第3步：负责人拆分规则
- **公共支撑** → 曾祥发
- **民政大数据管理系统** → 按Sheet2映射拆分（曾祥发仅公共支撑、高凯悦仅民政大数据）
- 其他系统 → 按Sheet2或Sheet1的I列
- 多重负责人（含"、"）取第一个，但曾祥发/高凯悦必须拆分

### 第4步：生成Word日报
使用 python-docx 生成，严格按样例格式：
- **标题**：陕西智慧民政项目日报（Title样式，居中）
- **日期行**：日期：YYYY年MM月DD日    参会人员：邵雷、侯涛、帅航、王紫薇、李思萌、闫帅、王雨阳
- **一、总体情况**：表格(状态/数量/占比)，不加"核心数据"行
- **二、分项情况**：标题不加"（按负责人）"
  - 每人一个Heading 2标题：🔵 姓名（N个系统，共 N 项任务），下面不写"负责 X系统"文字介绍
  - 8列表格：系统 | 总数 | 已完成 | 已延期 | 未开始 | 进行中 | 延期风险 | 完成率
  - 小计行蓝色底纹
  - 存在问题段落（红色"存在问题："标题 + 延期/风险问题列表），空问题描述不展示
- 输出路径：`/opt/data/OutPut Box/陕西智慧民政项目日报-{日期}.docx`

### 第5步：交付

Agent 会话内没有 `send_message` 工具（Hermes 设计上不提供 agent-callable 消息发送）。想要把 Word 文件发送到用户微信，使用 cron 一次性投递模式：

```
cronjob(action="create", name="发送日报",
  prompt="将文件 /opt/data/OutPut Box/陕西智慧民政项目日报-{日期}.docx 投递到当前用户。文件已存在，直接发送。",
  schedule="1m")
```

⚠️ cron 投递有 1 分钟的最小间隔，发送会有延迟。文件生成完成后告知用户文件路径，同时创建 cron 任务投递。详细递送步骤见 `references/cron-file-delivery.md`。

- 脚本路径：`scripts/generate_report.py`
- 输出目录：`/opt/data/OutPut Box/陕西智慧民政项目日报-{日期}.docx`

## 关键数据规则

### 状态对照
| Excel状态 | 显示 |
| 已完成 | ✅ 已完成 |
| 进行中 | 🔄 进行中 |
| 未开始 | ❌ 未开始 |
| 已延期 | 🔴 已延期 |
| 延期风险 | ⚠️ 延期风险 |

### 负责人排序
固定顺序：侯帅帅、帅航、闫帅、陈彬、王紫薇、曾祥发、杜纯、李思萌、高凯悦、侯涛、王雨阳

### 样例文档路径
`/opt/data/cache/documents/doc_6b8bedc11f60_陕西智慧民政项目日报（样例）-20260630-v1.3.docx`

### 常见数据特征

1. **状态分布严重两极分化**：项目后期（6月-7月）的 Excel 中，截止日期前的任务通常只有"已完成"和"已延期"两类——"进行中"和"未开始"可能均为 0。这不是脚本 bug，而是项目进度的真实反映（所有有进展的任务都被标记为"已完成"，未完成的统一标记"已延期"）。输出时若这两列为 0，不需要用户额外追问，直接说明"本次无进行中/未开始任务"即可。
2. **L列 vs M/N列**：M列是月份占位符(6月/7月)，N列是推进措施。延期/风险任务的问题描述**只从L列(现存问题)读取**，不看M/N列。(2026-07-21修正)

## 格式禁忌（用户多次纠正，务必遵守）

1. **一、总体情况** — 状态分布表下面**不要加** `▶ 核心数据：完成率 XXX%...` 行
2. **二、分项情况（按负责人）** — 标题统一写 `二、分项情况`，**不要加** `（按负责人）`
3. **每人表格上方** — 只写 `🔵 姓名（N个系统，共 N 项任务）`，**不要写** `负责 XXX系统` 文字介绍
4. **问题描述** — 现存问题描述为空的行**不要展示**（不要显示 "（未记录具体问题）"）
5. **样例参照** — 格式必须参照 `/opt/data/cache/documents/doc_6b8bedc11f60_陕西智慧民政项目日报（样例）-20260630-v1.3.docx`
6. **曾祥发/高凯悦拆分** — 公共支撑→曾祥发，民政大数据按实际 I 列值拆分

> 2026-07-04 修正：以上 1-4 条是用户**上一次生成日报时逐条纠正**的格式要求。

## Humanizer 去AI味说明

本 skill 产出以表格数据为主，自然语言极少，humanizer 作用于以下环节：

| 环节 | 需检查的文本 | humanizer 要点 |
|:----|:-----------|:--------------|
| 总体情况段 | "截至今日...前完成的任务共 N 项，分布如下" | 已尽可能简洁，保持就好 |
| 存在问题描述 | 延期/风险问题的叙述 | Excel L列原文为主，不加"值得注意的是"等AI引导 |
| 汇报时的附加说明 | 你向用户解释数据时的文字 | 不写"从数据可以看出/整体来看/总体而言"等套话，直接说数据 |

执行日报任务时，生成的任何附加说明文字（非表格/非Excel原文）都要过一遍 humanizer 14项检查清单，特别留意"值得注意的是""从数据可以看出""总体而言""综上所述"等AI套话。
