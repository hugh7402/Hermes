# 个人季度/年度绩效汇报：数据源检索与责任书拆解

场景：用户要「编制我的三季度/年度重点工作完成情况」，要求常为
「结合年度岗位责任书、部门总监及副职临时交办的任务，突出成效，300字以内」。

## 1. 先拆岗位责任书（考核基线）

用户贴出的责任书往往是「指标 + 两个时间节点」结构，先做成三列表再动笔：

| 指标 | 年底目标（考核口径） | 半年节点 |
|---|---|---|
| 指标一 · 规划与标准 | 完成省份或重点行业规划 1 个、课题标准 1 个 | 相关行业规划 1 个、课题标准 1 个 |
| 指标二 · 重点项目支撑 | 在重点/重大攻坚项目的总架构规划、项目总体统筹方面取得成果 | 支撑北京仿真实验室二期等重点项目交付，做好规划和架构支撑 |
| 指标三 · 新行业突破（SJ/公检法/农业） | 新行业方面取得突破 | 锁定公安部、国家消防救援局等商机 |

**季度总结对「年底目标」说进展**，不对半年节点说 —— 否则三季度显得没推进。

## 2. 找本人岗位定位（责任书之外的锚点）

知识库/文档库里按此顺序搜：

```bash
# 搜文件名
find <vault> -iname "*岗位责任书*" -o -iname "*责任书*" -o -iname "*季度*"
# 搜正文里的本人姓名（定位到具体分管/角色）
grep -rn "<本人姓名>" concepts/ 01-WeiXin/ | head -25
```

实测有效的定位点：**《…2026年建设推进工作方案》附件2 责任人清单**里的「联系人员」一栏
（形如「杨杉（咨询规划）、邵雷（架构师）、侯涛（交付）、闫帅（运维）」）→ 本人角色 = 架构师。

⚠️ 单独的《责任人清单》附件文件可能只转出一个标题（markitdown 会把表格吃掉）—— 别就此下结论，去正文工作方案里找同一张表。

## 3. 本季度素材源

| 素材 | 取什么 |
|---|---|
| 双周/月度工作汇报 | 项目口径数字：任务总数、当期完成数、完成率、累计进度、延期构成 |
| 平台月度报告 | 运行量：账号数、登录次数、数据共享/归集量 |
| 本人本季发来的文件 | 真正经手的产出物（方案、成果材料、清单、模板） |
| 项目任务清单 | 本人名下的正式任务条目 |

⚠️ **知识库文件 mtime 不是可靠信号** —— 批量导入会把几百个文件刷成同一天，
用 mtime 反推"本季度做了什么"会得到错误结论。以**文件内容里的姓名/角色**和**用户实际发来的文件**为准。

## 4. 样例：一次真实检索的结果

- 责任书：用户直接贴出（知识库里没有）→ 拆成上表三项。
- 责任人清单：《陕西省智慧民政项目责任人清单》只有空标题；改查《陕西省"智慧民政"一体化平台2026年建设推进工作方案》第 247 行找到本人角色。
- 三季度可用素材：7月平台月报（账号 6.98 万、登录 535.8 万次、13 个核心板块）、8/7–8/23 双周汇报（本双周推进 43 项、当期完成 5 项；累计 246 项完成 109 项、进度 44%、延期 38 项）。
- **缺口（须向用户要）**：三季度任务清单、9 月进展（8/23 之后无记录）、总监/副职临时交办的任务、涉投标工作能否写入及怎么写。

## 5. 字数与措辞

300 字内 ≈ 每项指标 1–2 句。模板：

```
<动词：主导/牵头/推动/支撑> + <具体事项> + <量化结果>
```

不要"参与/协助/完成了…"式流水账；每项先说成果再说做法。
写完对照 humanizer 清单过一遍：套话开头、空洞拔高、"展望未来"式结尾全删。

## 6. 读「本人任务清单」：待办导出的 .xls（2026-10-11 实战）

用户会把待办 App 的导出直接发来，文件名形如 `todoListExport_2026-10-11_<数字>.xls`。
**这是真 BIFF（OLE2）格式，不是伪装的 HTML 表格**：

- 看文件头是不是 `D0 CF 11 E0`（OLE2 魔数）—— 本机**没有 `file` 命令**，别靠它判断格式。
- **markitdown 能读**（转成 markdown 表格，快速看一眼够用）；
- **要按日期/分类筛行就得用 `xlrd`**（已装），能拿到全部行。

列名固定：`taskId | 日期 | 分类 | 事件内容 | 描述 | 子任务 | 是否完成 | 工作量 | 提醒时间`。

⚠️ **两个必踩的坑**（本次都中了）：

1. **不能只筛 `分类 == '工作'`** —— 导出里**有空分类行**（本次 2 条陕西智慧民政条目分类为空），
   按严格等于筛会**静默丢掉真实工作项**。改法：排除明确的非工作分类（如 `生活`），其余全留。
2. **这份清单不是全集，不能当唯一依据**。本次导出共 99 条、跨 4–9 月，而用户**三季度投入最大的一块**
   （涉投标的高保真原型迭代）**一条记录都没有** —— 待办 App 只记他自己想记的事。
   → **必须交叉验证**：微信落盘文件（`/opt/data/cache/documents/`）、知识库 `01-WeiXin/` 的产出物、
   双周/月度报告。把清单当"索引"不当"账本"，**并在交付时说明哪些是从别处补的**。

直接跑：`scripts/todo_export_digest.py <todo.xls> --start 2026-07-01 --end 2026-09-30`

## 7. 字数三口径与压缩手法

「300 字以内」有两种读法，**按含标点的严口径写**，交付时把三个数都报给用户：

| 口径 | 本次定稿 |
|---|---|
| 含标点（≈ Word 的"字符数(不计空格)"） | 正文 **289** ／ 含标题 **300** |
| 不含标点（汉字+字母+数字） | **268** |
| 标题 | 不计入正文（另列） |

压缩顺序（本次 330 → 交稿 289，全靠这四刀，**不掉信息量**）：

1. **删跨项重复表述** —— 同一件事在两项指标里各写一遍（本次"统一UI设计规范"同时出现在指标一和指标二）→ 只留一处。
2. **删动词的软垫词** —— "项目问题情况汇报"→"问题汇报"、"全部完成"→"完成"、"完成了"→"完成"。
3. **砍活动/机构的限定词** —— "第四届西安老博会"→"西安老博会"、"二期平台建设与交付"→"二期交付"。
4. **同级合并** —— "对接蚂蚁集团、杭民星等生态伙伴"比逐一列举短，信息不减。

**不要靠删条目来压字数** —— 条目就是内容，删了这块指标就没内容了；先砍修饰词。

报数写法（给用户看）：`正文 289 字（含标题 300 字，都卡在"300字以内"；不含标点 268 字）`。
