# 智慧民政双周工作汇报生成

## 铁律：固定模板，只替换内容（用户2026-08-06明确纠正）

用户原话：参照最新一期《智慧民政第X个双周工作汇报-日期.pdf》的**内容和格式**编写，这是**固定模板和定式，内容不用新增**，主要将新双周的日期和内容替换。

- ❌ 不要重新设计章节结构、不要自创条目、不要新造"重点事项/问题"数量
- ✅ 动笔前先完整读取最新一期PDF（fitz: `page.get_text()` 或 markitdown），逐段对照模板骨架，再填充新双周内容
- ✅ 重点条目数、问题条数、每段说法习惯都要贴合模板（第五双周版：重点8条、问题3条；第四双周版：重点5条、问题2条——以最新一期为准）
- 第一版教训：按通用"工作汇报"套路写了8条重点+4条问题，被用户打回重写

## 数据来源（真实数据，禁止编造）

1. **《陕西智慧民政项目双周任务和问题清单-<日期>.xlsx》**（核心）
   - Sheet「任务完成统计透视」：任务总数/已完成/进行中/未开始/已延期/完成率/延期率——**直接引用这些数**
   - Sheet「双周任务清单」：每条任务的完成状态、"现存问题"列、"推进措施"列（常含具体日期，如"7月30日开始上传，每天6万，存量100万"）
   - ⚠️ 该xlsx常带损坏样式，openpyxl data_only 会报 `TypeError: expected Fill` → **用 read_file 直接提取文本**（内部机制可靠），不要死磕 openpyxl
2. **上期双周汇报PDF**：算环比（本期任务数 vs 上期、本期完成数-上期完成数=本双周新增完成）
3. **月度报告PDF**：运营数据（账号数、登录次数、系统上线/试运行/开发中状态）；用户指定 **PDF一律用 markitdown 读取**（缺依赖时 `uv pip install --python <venv> 'markitdown[pdf]'`；网络慢时 fitz 兜底，效果相同）
4. 推算数据要注明来源逻辑并校验合理性（如优待证存量100万÷每天6万≈15天）

## 模板结构（以最新一期为准，第五双周骨架）

- 标题：陕西省"智慧民政"一体化平台 第X个双周工作进展及问题汇报（起止日期）
- 引言：根据《陕西省"智慧民政"一体化平台2026年建设推进工作方案》安排，为扎实推进平台建设、落地功能迭代、解决实操堵点，现将X月X日至X月X日平台建设推进情况、存在问题及下一步工作计划汇报如下。
- 一、本双周整体工作推进情况：任务总量（环比+新增数）→ 本双周重点方向 → 当期+遗留延期合计推进数 → 累计完成（进度%）+延期数（延期率）→ 十大系统需求确认现状 → **四类延期原因**（①统一UI标准前期未确认影响工作台开发 ②多处室原型确认及需求沟通滞后 ③外部接口与数据对接依赖（银行联调/电子印章/社会组织对接）④档案归档标准长期未统一）→ 下双周攻坚方向
- 二、重点工作落实情况：(一)(二)...条，每条"**加粗小标题**"+一段（见事见数、带具体日期）
- 三、当前存在的主要问题及建议：(一)(二)...条，每条"问题描述"+"建议："，问题要量化、建议要可操作
- 结尾：以上情况，请厅领导审阅。
- 完整模板原文见 references/template-4th-biweekly.md

## 产出

- 目录：`/opt/data/OutPut Box/智慧民政双周工作汇报-YYYYMMDD/`
- markdown 源稿 + python-docx 转 Word（公文格式：标题方正小标宋简体22pt居中、正文仿宋_GB2312 14pt首行缩进28pt行距1.5、一级小标题黑体16pt、二级小标题楷体_GB2312 14pt加粗）
- 命名：智慧民政双周工作汇报（起止日期）.docx

## 写作要求（用户偏好）

- 像体制内有经验的老笔杆子：说理说事摆数据，不装不飘；数据前置
- 不用AI套话：值得注意的是/需要指出的是/彰显/赋能/深耕/抓手/不仅仅...更是/展望未来/必将/显著/大幅
- 具体日期写实（7月30日完成、7月27日部署），不写模糊时间
- 延期原因"四类共性"归纳是模板固定写法，保留

## 陷阱

- 下双周日期以用户指定为准（第五双周用户要7月27日-8月6日，模板原写8月9日）
- 当期任务数（如30项、其中提前完成6项）继承自上一期PDF的预测，直接沿用并说明
- 附件任务清单表格跟随最新一期格式（PDF版有、docx版无，看最新一期是否带）
- 用户习惯直接要成品Word，一步到位，不用先确认提纲（汇报类固定模板不走plan-writer四轮制）
