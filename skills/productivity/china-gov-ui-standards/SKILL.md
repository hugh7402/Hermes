# 中国政务系统界面与规范依据

> 2026-10-07 整理。**触发场景**：用户说"这是政府系统""要更符合政府风格的 UI""政务系统""政府门户""党政"时。
> 核心态度：**政务视觉有硬规范和既有惯例，不是自由创作** —— 别用"出版物质感 / 文艺风"代替它。
> 界面实现技术（HTML 单文件、jsdom 验证、静态渲染器陷阱）见 `ui-prototype` skill；本 skill 只管**政务这个领域该长什么样、依据是什么**。

## 一、先分清对象：政府网站 ≠ 内部业务系统

《政府网站发展指引》(国办发〔2017〕47号) 管的是**政府网站**（对外门户）。内部业务系统（省级部门的管理后台）不直接受其约束，
**但甲方与验收普遍按同一套视觉预期看**，所以照它的精神做最稳，且能直接引用原文作为设计依据。

## 二、国办发〔2017〕47号 的硬性页面设计规定（原文要点）

- 「政府网站应确定一种主色调，合理搭配辅色调，**总色调不宜超过3种**」
- 网站名称以本地区/本部门**机构名称**命名，并在**头部标识区域显著展示网站全称**
- **底部功能区至少要列明**：党政机关网站标识、政府网站标识码、ICP备案编号、公安机关备案标识、网站主办单位及联系方式、站点地图
- 要提供**适老化 / 无障碍**（真实门户常见入口：无障碍浏览、长者版、繁體/简体）
- 严禁刊登商业广告或链接商业广告页面
- 服务器不得境外；前台发布页面与后台管理系统应分别部署

> 地方标准 DB14/T 3002-2024《政务服务办事指南图解设计指引》另给出「主色:辅色:点缀色 = 6:3:1」「正文不得使用艺术字体」等，
> 但该标准状态显示**已作废** —— 只作参考，**不要当合规依据引用**。引地方标准前先核状态。

## 三、实测配色（2026-10-07 抓真实门户 CSS）

| 来源 | 主色（高频） | 辅助 | 点缀 | 中性 |
|---|---|---|---|---|
| 中国政府网 www.gov.cn | **#015293**（×20，全站最高频彩色） | #2e5586 / 亮蓝 #2691e2 | **#d9000d 中国红**（×11） | #fff / #f7f7f7 / #ccc |
| 陕西省政府 | **#20528f / #11559b**（×42 / ×20） | 亮蓝 #4e8fde / 浅底 #f7f8fb | — | #333 / #666 / #999 / #e5e5e5 |

**通用规律**：主色 = 深蓝（低明度、中饱和）；红**只用于警示/重要/热门**，绝不做装饰；浅蓝底（`#e8f1f9` 一类）承担表头与选中态。

⚠️ **配色值必须抓，不能凭印象写**（用户会核对出处）。抓法（国内站点直连，**不走代理**）：

```bash
curl -sL --noproxy '*' -m 25 -A 'Mozilla/5.0' https://www.gov.cn/ | grep -o '<link[^>]*\.css[^>]*>'
# 再抓主样式表，正则提色 + 按频次排序：
#   HEX = re.compile(r'#([0-9a-fA-F]{6})\b');  collections.Counter(HEX.findall(css)).most_common()
```

**只看内联 HTML 的色会漏掉主色 —— 主色在 CSS 里。** 底部功能区列明项也可从门户 HTML 直接核实（政府门户普遍带这些字样）。

## 四、通行布局骨架（政务后台）

```
深蓝顶栏：徽标 + 平台名 + 机构名（左） | 无障碍浏览·长者版·繁體·使用帮助·用户名·退出（右）
白色主导航：数据资源 / 共享管理 / 统计分析 / 运行监测 / 系统管理（选中项主色下划线）
正文两栏：左侧分组菜单（选中 = 浅蓝底 + 3px 主色竖条 + 主色字） + 内容区
内容区：面包屑「当前位置：X > Y」→ 页标题（底部 2px 主色横线）→ 检索条 → 表格（浅蓝表头）→ 分页 → 提示条
底部功能区：按指引列明项
```

- **字体用黑体栈**（PingFang SC / Microsoft YaHei / Source Han Sans）。**不要宋体** —— 宋体是出版物/公文正文感，政务界面用黑体。
- 圆角 2-4px（近乎直角，庄重）；状态用**小尺寸标签**（浅底深字），不要圆角药丸。

## 五、"政府风格"是一个语境，不是一种设计 → 用**使用者场景**分化方向

用户说"要更政府风格"时，不要只换皮、也不要猜一种。三种真实场景对应三种形态：

| 场景 | 使用者 | 对标 | 形态特征 |
|---|---|---|---|
| 日常业务办理 | 经办人 | 政府门户 + 通行政务后台 | 深蓝顶栏 + 左菜单 + 高密度表格，开门见数据 |
| 对外服务入口 | 办事人 | 各省"一网通办" | 蓝色渐变 banner + 服务分类卡片 + 精简列表 + "查看全部" |
| 运行态势监测 | 领导 | 政务指挥中心 / 大屏 | 深色底 + KPI 卡 + 条形/环形图 + 监测表 |

**先出三个方向让用户选，选定后才铺全套** —— 风格词收窄的是解释空间，不转移选择权；用户变更风格要求时要**重出方向**，不要在旧方向上演进。

## 六、与 huashu 反 AI 味清单冲突怎么处理

huashu 禁「所有背景都渐变」「圆角卡片」，但政务惯例**就是**用渐变 banner 和服务卡片。
huashu 自己写的唯一合法破例理由是「**品牌本身用**」—— 政务视觉规范就是这里的"品牌"。

**处理方式：破例但克制，并在交付说明里写清为什么。** 例：全页只保留 banner 一处渐变，它标记"服务入口"这一视觉层级。
仍严格禁止的：紫渐变、emoji 图标、圆角卡片 + 左彩色 border 那一套、Inter/Roboto/Arial 作 display。

## 七、一处必须交给甲方定的合规取舍（别自己拍）

严格按「总色调不宜超过3种」算，主色蓝之外再加**状态语义色**（绿=已发布 / 橙=有条件共享 / 红=不予共享）就是超的。
但实际政务系统普遍保留语义色，无障碍也要求"不靠颜色单传信息"。

**遇到这个就把取舍摆出来让用户定，不要默默选一边。**

## 八、渲染落地注意（政务形态特有）

政务 chrome（顶栏 + 主导航 + 左菜单 + 表格 + 底部功能区）比纯内容页高 **150-250px**，具体实现要点：

- 必须做一轮**「密度收口」**（收紧各段 padding）才能落进 1440×940；收不动时做**隔离实验**定量定位是哪一块放不下。
- 政务按钮要真实盒子（背景 + 边框 + 内边距）→ 静态渲染器会把 `<button>` 撑满，改用 `<span role="button" tabindex="0">`。
- **底部功能区用流转文本行**，不要一堆 `inline-block` span —— 7 个 span 会折成 3 行、把整体顶出一页。政府网站通行的就是"一行密集排"。
- 备案号/标识码用 `XXXXXXXXXX` 占位即可，**不要编造某省真实备案号**（会被误当成真实信息）。
