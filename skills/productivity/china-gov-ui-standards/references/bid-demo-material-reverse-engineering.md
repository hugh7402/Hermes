# 投标 / 评审演示原型：从参考材料反推输入（配方）

> 2026-10-10 整理。场景：做招标采购需求某几条（如 215/216）的**演示原型**，
> 手上陆续到位采购需求解析表、对手演示脚本 docx、样例填写清单 xlsx、对手系统截图。

## 一、材料矩阵

| 材料 | 反推出 | 坑 |
|---|---|---|
| 采购需求 / 技术要求（已解析成「序号 → 原文」表） | 条款原文、**实质性标记**、演示步骤边界 | 用户转述不可信，按序号取原文；合并单元格会让表头句在每行重复、残留 `<br>` |
| 对手/自家演示脚本 docx | **精确到按钮名的操作链**、状态词、系统与模块名 | 常比采购需求更细；措辞可能与采购需求不同（"访问方式" vs **「对接方式」**）|
| 样例填写清单 xlsx | 完整字段树 + 必填性 + 值域 + **联动校验规则** + 样例数据 | 样例可能图省事填"暂无系统"/"其他"，与演示联动要求冲突 |
| 对手系统截图 | ① 界面可用性弱项 ② **业务/数据破绽** | 必须先建立"截图 ↔ 步骤"映射才能定位 |
| 初步设计 / 需求说明书全文 | 功能点；对既有系统的批评（可当设计依据）| 全文检索定性字段，别通读 |

## 二、对手截图要找两类东西

### 第 1 类：界面可用性弱项 → 写成「对手的问题 → 我们的改进」两列表

这是对用户最有说服力的交付内容。实测抓到的高频弱项：

- 新增/编辑长表单**分组不可折叠**，无进度条/锚点导航/错误汇总 → 必填项多时易迷失
- 条件字段**同时出现**（"是否允许回流" 与 "不允许回流原因"），看不出触发条件
- 自动生成/只读字段只是变灰，**没标"系统自动生成"**
- 提交按钮在**底部**，长表单要滚到底才能提交
- 筛选条件 **9 个无分组全挤一行**
- 状态**靠颜色单传信息**（色弱用户不可辨，也不合无障碍要求）
- 操作列按钮**不统一**（配置/查看/变更/停用混排）
- 左侧菜单 **约 20 项**、层级深、无搜索或最近访问
- 结果列表用**卡片**而非表格 → 无常驻表头、长文本截断、**没有汇总统计**

对应改进写法：可折叠分组 + 左侧锚点条 + 分组完成状态 + 顶部错误汇总（点错误跳字段）；
条件字段联动显隐 + 小字说明；只读字段加锁图标 + "系统自动生成"；**吸底操作条**；
筛选默认只露 3 个主条件、其余"展开"并按属性组归类；状态用**颜色 + 文字 + 图标**三重冗余；
主操作固定位 + 次操作收进"更多"；演示版**只呈现演示路径所需菜单**；改**表格 + 固定表头 + 悬浮全文**；
顶部**汇总条常驻**。

### 第 2 类：业务/数据破绽 → 可正面压过去

**实例**：对手"数据清洗结果明细"页 4 条记录的「待整改问题数据总量」**全是 0**。
而要求明确要演示问题清单，含**过滤/转换/保留原值/去重**四类，还要能**确认被保留原值的异常数据明细样本**。
→ 对手治理全跑完了却没造出问题数据，现场一句"问题数据呢"就下不来台。

**我们的做法**：五项数字**自洽**（归集总量 − 去重 = 清洗总量 = 优质 + 问题）；
四类问题**各有明细行可点开**；保留原值的样本能对照**原始值 vs 权威值 vs 处置结果**；
大屏把"问题数据 N 条"做成醒目待整改项而不是 0。

**问法**：用 `vision_analyze` 问**具体可证伪**的问题——
"这一页有哪些统计数字？名称与数值分别是什么？表格有哪些列？有没有显示问题类型？"
**不要问"好看吗"。**

## 三、技术配方

### ① docx 内嵌截图 ↔ 上文档落 精确映射

`markitdown` 会把图片变成占位符、**丢失步骤对应关系**。用 python-docx 按段落顺序取 `a:blip` 的 `r:embed`，
查 `part.rels` 拿媒体文件名：

```python
from docx.oxml.ns import qn
rels = {rid: r.target_ref for rid, r in d.part.rels.items()}
order, cur = [], []
for p in d.paragraphs:
    if p.text.strip():
        cur.append(p.text.strip())
    for b in p._p.findall('.//' + qn('a:blip')):
        order.append({'n': len(order) + 1,
                      'media': pathlib.Path(rels[b.get(qn('r:embed'))]).name,
                      'after_text': cur[-1] if cur else ''})
        cur = []          # 每张图只认它上方最近的那段文字
```

现成脚本：`scripts/docx_image_step_map.py`。图片本体从 docx（就是个 zip）的 `word/media/` 直接抽。

⚠️ 同一张媒体可能在正文里被引用多次（映射表里会出现同名不同序号）——**序号才是文档顺序**。

### ② 样例填写清单 xlsx → 完整字段树

- 表头常占**连续多行**（属性组名行 + 字段名行 + 必填说明行），要按行读出「组 → 字段」层级。
- **标称列数可能是格式化残留**（实测某清单标称 16382 列）→ 扫前几行找最后一个非空列作真实边界，
  否则遍历极慢。判定方法：`max(j for r in 前8行 for j,v in enumerate(r,1) if v 非空)`。
- **必填与联动规则就写在字段名后缀里**，用正则抽出来即可当原型的校验逻辑：
  "（必填项）"、"（必填项，当主键填写'是'，该字段必须填写'否'）"、
  "（仅当共享属性为不予共享时，无需填报此字段）"。
- 多条目录**堆在同一个 sheet**：以「目录级字段（如 数据目录名称）非空」作为新目录边界。
- 把结果落成 JSON（目录 → 数据项数组），原型直接读，不要每次重新解析 xlsx。

### ③ 样例数据要对着演示要求验一遍

本次抓到的两个坑：

1. 6 条样例目录的「数据来源系统」**全填"暂无系统"**，但演示脚本明确要求
   "**先选一个系统，系统所属分类字段才会带出来**" → 样例不能直接照用，得指定真实系统。
2. 某条样例目录只有 **2 个数据项**，而演示要求"模块表里**至少建 3 个字段**，为后续配置治理规则做准备"
   → 不能拿它做治理演示（规则要挂在字段上）。

**通用做法**：逐条对照演示脚本的硬性要求检查样例是否够用，不一致的**写进清单让用户定**，别默默凑合。

## 四、输入需求清单 v1 → v2

**v1 的做法（差点返工）**：46 项平铺，全是"请你提供"。
**用户真实期望**（原话："然后再给我一份输入需求清单，看还有哪些是需要我继续准备的"）：
材料陆续给到后，清单要**越缩越短**，且能自拟的先自拟。

v2 的形状 —— 34 项、四档状态色、加一个「统计」sheet 给四档计数：

| 档 | 条数 | 含义 |
|---|---|---|
| ✅ 已解决 | 12 | 标注由哪份材料的哪一处填上 |
| 🟡 我已自拟，待你确认 | 11 | 给出具体建议值 + 「☐ 同意 ☐ 换成：____」|
| 🔴 仍需你提供 | 6 | 只留真正没有依据的 |
| ⚪ 可后补 | 5 | 不影响开工 |

**判据：能从已有材料推出自洽建议值的，就不要放进 🔴。** 典型可自拟项：
演示用哪条样例目录、数据提供单位、数据所属领域/层级、校验规则具体内容、
关联字段与验证字段、权威数据源名称、数据规模与问题分布、演示角色划分。

**必须留给用户的**（本次 6 项）：演示数据集实物、演示时长、评分表里"演示"条目原文、
演示环境与分辨率、是否允许用原型（评分表若写明"须现场真实系统操作"，原型只能当彩排辅助）、值域表内容。

**最大那一个要写明"没有它就没法开工"**：参考材料给的是**格式与字段**，不是**数据**。
