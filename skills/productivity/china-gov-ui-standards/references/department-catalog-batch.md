## 生成器骨架

一个脚本、一份 `CATS` 列表，循环产出多份文件。**列从 `form_spec.json` 渲染，不要手写。**

```python
CATS = [
    {
        'file': '政务数据目录编目模板_居民电子健康档案信息.xlsx',
        'v': {  # 逐要素填值，key = form_spec 里的 label（37 个）
            '数据目录名称': '四川省居民电子健康档案信息',
            '数据提供单位': '四川省卫生健康委员会',
            '数据来源系统': '四川省卫生健康信息平台',
            '数据来源系统所属分类': '省直',
            # …数据摘要/领域/层级/存储方式/更新频率/共享属性/开放属性/事项 6 项/是否发布
        },
        'items': [  # 15 个数据项：与「数据项」工作表 12 列一一对应
            ('健康档案唯一标识', 'jkdaid', 'varchar', '32', '是', '是',
             '有条件共享', '依申请共享', '不予开放', '—', '居民电子健康档案唯一标识'),
            # (中文名, 英文名, 类型, 长度, 主键, 必填, 共享属性, 共享条件, 开放属性, 开放条件, 描述)
        ],
    },
    # …其余 4 个部门
]

groups = [g for g in json.load(open('data/form_spec.json')) if not g.get('isTable')]
for cat in CATS:
    ws.cell(1, 1, '政务数据目录编目模板')                      # 标题行
    ws.cell(2, 1, '填写说明：① 一行填写一条数据目录；…')        # 说明行
    # 第 4 行 = 属性组合并表头；第 5 行 = 要素名（带 * / ◐ 前缀）；第 6 行 = 数据
    # 第 2 个工作表「数据项」：12 列，首列 = 数据目录名称（挂接键）
```

要点：

- 表头前缀按 `required` 生成：`req → '*'`、`cond → '◐'`、其余无前缀。
- 列宽 `max(11, min(24, len(label) * 2.1))`，第 5 行行高 34，`freeze_panes='C6'` / 数据项表 `'A2'`。
- 属性组合并表头用 `merge_cells(start_row=4, start_column=start, end_row=4, end_column=col-1)`。
- 每条目录固定 **15 个数据项**（与原型内置目录的数据项数一致，演示时可对照）。
- 文件命名沿用 `政务数据目录编目模板_<目录名>.xlsx`。

## 逐份「真导入」验证配方（别只看文件生成成功）

生成成功 ≠ 能导入。用真 Chrome 逐份过一遍：

```python
for f, name, org, sysn, nitem in metas:
    pg.evaluate('window.APP.go("s1")'); pg.wait_for_timeout(220)
    before = pg.evaluate('window.APP.S.catalogs.length')
    pg.set_input_files('#file-upload', str(f)); pg.wait_for_timeout(2200)
```

## 三个会假报错的坑（都踩过）

1. **表头必填标记前缀**：校验脚本按精确标签匹配会全空 → 先 `re.sub(r'^[\u25d0*\u2605\s]+', '', hdr)`。
   症状是「10 项断言全红但文件明明是对的」。
2. **千分位**：页面/表格里是 `1,000`，断言别写 `'1000'`。
3. **值域项数写死**：`len(values) == 6` 这类断言会在扩值域时变红 → 写成「≥ N 且必需项全在」。
