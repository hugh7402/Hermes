# 分阶段工作计划表的编制（指标表 → 任务表）

一类常见任务：用户给一个含「指标成效」页的工作簿（阶段目标值 + 期限），再给一张工作分解示例表，要求把计划填进几个空白 sheet。

典型输入：
- `指标成攈` sheet：运营主线 / 运营任务 / 验收指标 / **2026年底** / **2027-02初验** / **2027-05终验** 各阶段目标值 + 验证方法
- `×××工作（示例）` sheet：已有的工作分解，定颗粒度
- `×××工作` sheet：空表，只有表头，待填
- 另一份清单（如 71 条标准），要求逐条覆盖

---

## 一、先摸清三件事，再动笔

1. **示例表的颗粒度**：多少条任务、分了几个工作分类、哪些责任岗位、单任务多少人天、日期跨度多少天。
   把它 dump 成一张紧凑清单（序号/分类/工作项/细项/岗位/起止/天数/交付物）看一眼，照它的粗细写。
2. **指标表的时间节点**：每个阶段叫什么、截止是哪天。后续所有排期从它未。
3. **目标值的可拆性**：指标页里哪些是「建成要件」（本期就要有），哪些是「能力」（后期才要）。
   拆错会把验收口径抬高。

## 二、🚨 阶段划分：只承诺当期指标要的东西

排期前先算一遍：
- 窗口有多少自然日 / 工作日；
- 待做条数 × 单条人月 = 总人月；÷ 窗口月数 = **需要多少人并行**。

算出来不现实（比如 85 人月要压进 47 天 → 要 56 人满负荷）就是信号：**不是硬排，而是回看指标页——当期其实只需交付一部分。**

铁律：
- **每期只排该期指标明写的交付物**，剩下的推到下一阶段，不要全压进第一个窗口。
- **早期阶段的文案不得声称后期能力**。本期只做到建库/预留时，就写「为后续……预留支撑」「预留分析基础」，不要写「支撑××场景」——后者是初验/终验的验收点，写进去等于提前许诺。
- 阶段划分直接照搬指标页的名称与日期，不自创阶段名。

## 三、🚨 多阶段排期的偏移量必须换算到同一基准

这是本类任务最容易出的错，而且**不报错、静默错**。

若每个阶段的任务用「相对本阶段起点」的天数偏移（好写、好改），写入时却统一拿第一个阶段作基准，
**后期阶段会整体叠到前期上面**——表格看着有 95 行、日期也有排序，实际三阶段全挤在头几周。

```python
p2off = (P2_START - P1_START).days
p3off = (P3_START - P1_START).days

rows = (PHASE1
        + [[c, i, d, role, off + p2off, dur, dv] for c, i, d, role, off, dur, dv in PHASE2]
        + [[c, i, d, role, off + p3off, dur, dv] for c, i, d, role, off, dur, dv in PHASE3])
```

更好的写法：给排期函数一个 `shift` 参数，在生成时就加好，别事后再补。

## 四、🚨 校验分组边界要与阶段定义严丝合缝

校验时把行按日期分桶统计（「阶段一 N 条 / 阶段二 M 条」）会把 bug 暴露出来——但**分桶边界自己也会错**。

相邻阶段是 `P1_END = 12-30`、`P2_START = 12-31` 时，分桶必须用 `[P1_START, P1_END]` 与 `[P2_START, P2_END]`。
若写成 `[P1_START, 12-30]` 与 `[2027-01-01, …]`，**12-31 这一天落进缝里**，就会出现「合计 94 / 全表 95 → 有任务落在阶段外」的假警报，诱使你去改本来正确的产物。

## 五、格式向示例 sheet 对齐（不是重新设计）

先把示例页的样式读出来，再仿写：

```python
ws.cell(1,1).font.name, ws.cell(1,1).font.size, ws.cell(1,1).font.bold
ws.cell(1,1).fill.fgColor.rgb, ws.cell(1,1).alignment.horizontal
ws.cell(2,6).number_format          # 日期通常是 'yyyy/mm/dd'
{k: v.width for k, v in ws.column_dimensions.items()}
ws.merged_cells.ranges              # ← 关键：分类列往往是纵向合并的
```

两条最常被忽略的：
- **分类列是纵向合并的**，只写每组首行，不留空行重复写。用 `ws.merge_cells` 按组起止行合并。
  这会导致后续读取时 `MergedCell.value` 为 `None`——统计分类条数时要按合并锦点去重，否则只能数到「每类 1 条」。
- **日期写 `datetime` + `number_format='yyyy/mm/dd'`**，不要写字符串，否则排序与筛选都废。

## 六、交付前的硬校验（写成脚本，不靠眼看）

每次生成后必跑：

1. **日期不越界**：每行 `P_START ≤ start` 且 `end ≤ P_END`
2. **时长自洽**：`(end - start).days + 1 == 时长列`
3. **序号连续**：`1..N` 无跳号
4. **覆盖清单**：拿源清单（如 71 条标准）逐个名称比对表中工作项，报缺失数与多余数
   （前置/收尾类任务必然属于「清单外」，要预先排除再判）
5. **指标关键词覆盖**：把指标页该阶段的硬要素（如六个环节名、可用率 99%）做成关键词表，
   `grep` 全表文本，逐项打 ✅/❌
6. **原始页未被改动**：示例页、指标页的 `max_row/max_column` 与生成前一致

## 七、坑

- **读旧版 `.xls` 用 `xlrd`**，不需要 LibreOffice。`xlrd 2.x` 不支持 `.xlsx`，但读 BIFF `.xls` 正常：
  `xlrd.open_workbook(p).sheet_by_index(0)`，`cell_value(r, c)`。本机没 soffice 时这是唯一可行路径。
- **列名要按实际取**：清单表里「名称」列常常是空的，真正的内容在下一列「文档名称」；逐列打印前 3 行确认后再写取列逻辑。
- **人月与工期是两件事**：清单里每条固定 1.2 人月（≈26 人日），不等于计划表里该排 26 天。
  合同口径的人月包含后期征询/评审/试用；排期只排当期编制动作，差额在交付说明里讲清。
- **期限是周五/周末时看工作日**：窗口用自然日算，但描述工作量时用工作日算，两个数都给用户。
