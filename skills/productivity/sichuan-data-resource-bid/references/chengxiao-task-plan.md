# 从成效指标反推「达成任务计划」

适用：用户手里已有一份运营任务计划（过程动作清单），并要求「根据运营成效指标对计划进行补充」。
也适用于反向场景：只有目标值、要配一套能落地的任务。

## 一、先诊断：原计划到底缺什么

把工作项逐个扫一遗，只看一件事：**有没有任何一项是围绕指标结果的**。

实测典型形态——一份「治理常态化工作」计划有 9 个工作项 / 55 个细项：

| 工作分类 | 工作项 | 本质 |
|---|---|---|
| 融合治理日常工作 | 巡检融合任务 / 处理失败任务 / 配新增来源表 / 执行融合 / 响应新增数据服务工单 | 过程动作 |
| 数据质检日常工作 | 配质检规则 / 执行质检 / 质检结果分析 / 问题整改 | 过程动作 |

**结论：缺的是「结果层」**。指标考覆盖率/完整率/可用率，而计划里没有人负责测当前值、找缺口、把值推上去。
这就是要补的东西，**不是重写计划**。

## 二、补法：一条指标一条线，每条线五步闭环

```
口径固化 → 基线测算 → 缺口归因 → 补齐推进 → 节点复核
              ↑__________________ 监测预警贯穿 ______________↓
```

每步都是能写成「工作项 → 细项」的具体动作：

| 步 | 做什么 | 没做会怎样 |
|---|---|---|
| 口径固化 | 定义分子/分母/数据来源/取数时点，与甲方确认 | 每个人算出的覆盖率不一样，验收时扯不清 |
| 基线测算 | 按口径算出当前值，形成基线快照 | 不知道起点，目标值只是口号 |
| 缺口归因 | 逐部门 / 逐字段拆开，归到具体责任方 | 补齐推进时不知道找谁 |
| 补齐推进 | 源头补供 / 修融合逻辑 / 清洗格式 / 回溯补录 | 指标永远停在基线 |
| 节点复核 | 每个节点出一次复核报告 | 验收时拿不出达成证据 |

**归因是最容易写空的一步**。要拆成可判定的分类，例：
- 覆盖率缺口：未建立对接 / 已对接未同步 / 已同步但缺唯一标识
- 字段缺失：源头未供 / 供了为空 / 融合过程丢失 / 格式不合规

分类定下来才知道动作是「找部门要数据」还是「改自己的融合逻辑」——这两件事的责任方完全不同。

## 三、表结构：沿用原表，不新造

照搬用户原表的列，才能直接粘到同一个表里：

```
序号 | 工作分类 | 工作项 | 工作细项（≤3天） | 责任岗位 | 计划开始时间 | 计划结束时间
     | 时长（天） | 完成情况 | 完成占比 | 延误时长（天） | 交付物/记录 | 备注 | 风险/问题状态 | 预警色
```

两条硬约束：

1. **责任岗位只取原表已有的取值**。原表只有「治理工程师 / 数据质检工程师」，就只用这两个；凭空加岗位等于新设编制，用户会质疑。分工口径：治理工程师管接入、融合、补齐；质检工程师管规则定义、测算、监控、核验。
2. **细项必须能在 ≤3 天内做完**（列头就这么写的）。带 21 天 / 62 天 / 141 天的长任务要写成「持续性工作」并注明贯穿到哪个节点，别硬塞成「一件事」。

**备注列拿来当指标标签**，格式 `<指标简称>-<环节>`，如 `覆盖-基线`、`完整-归因`、`供数-监控`。
好处：可筛选、可追溯，且按标签给行上色后，一眼看出哪条线薄。

## 四、必须附的两张表

### 指标与任务对照（给评审看）

| 列 | 内容 |
|---|---|
| 成效指标 | 逐字抄指标名 |
| 三阶段目标值 | 85% → 90% → 95% |
| 原计划是否覆盖 | ✅ 覆盖 / ⚠️ 部分 / ❌ 未覆盖 |
| 本次补充任务 | 对应工作项列表 |
| 说明 | **为什么原计划不够、补的这几步解决了什么** |

「说明」列是这张表的价值所在。写清「原计划有『执行质检任务』，属发现问题的动作，但没有以完整率为目标的基线测算、缺口归因和补齐推进」，
评审才能接受「补」而不是质疑「原来的为什么不行」。

### 补充说明（给用户看）

至少四问：① 为什么要补；② 补了什么（工作项/细项数）；③ 和原计划什么关系；④ 哪几件要他确认。

**「和原计划什么关系」必须点明**：不是替代，是补结果层——新任务的执行仍落在原流程上
（例：「存量回溯补录」走的就是原来的「配置新增来源表融合任务」；「核心字段纳入质检」走的就是原「执行质检任务」）。
原计划是手段，新任务是目的与度量。

## 五、时间排布：先基线，再推进

- 剩余天数紧时（实测只剩 57 天到第一个节点），把**口径固化 + 基线测算 + 缺口归因全部压在开头两周**。理由：不知道起点就无从定路径。
- 然后才是提升推进，最后对齐各节点做复核报告。
- 时间实在排不下就**如实说「偏紧，请调整，别硬压」**，不要为了表格好看写一个跑不完的计划。

## 六、诚实边界：哪些要留待确认

补计划时一定会遇到「口径本身待定」的地方（覆盖率的分母到底是户籍人口还是常住人口、用哪一年的数、完整率每个字段的判定规则）。
**写进去并标明待确认**，不要自己拍一个数写死。在补充说明里集中列出「要你确认的地方」，一条一句。

## 七、反方向：没有现成指标时要自己设计

若用户说「要建某库，帮我写一些成效指标」（无存量指标表可补），按下面来：

1. **先找国家/省考核口径挂靠**，不自创体系。有官方口径的指标，目标值直接引用原文。
2. **分主线**，每主线 3–6 条，总条数 30–40 条够用（实测 8 条主线 / 35 条）。
3. **三档处理目标值**：
   - 有硬依据 → 直用 + 依据列写出处
   - 需推算 → 标「建议值」+ 说明需甲方确认，单元格上色
   - 无依据无口径 → `【待补】`，**不编**
4. **依据列必须写可用出处**：条例名称+条款、细目名称+规模、监测指标名称。地方标准先查是否废止，废止的在依据列标注「须按现行规定执行」。
5. 附一张「说明」sheet，逐条解释：为什么有黄底（建议值）、为什么有红字（待补）、哪些目标值是国考硬指标不是自定的。
