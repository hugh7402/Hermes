## 🚨 用户纠正三：字数/时长（迭代 6 轮）

同一份稿子的字数轨迹：

```
1350 (5.9分) → 1229 (5.3) → 1469 (6.4) → 1315 (5.7) → 1189 (5.2)
→ 1243 (5.4) → 1479 (6.4) → 1356 (5.9) → 1203 (5.2) → 1279 (5.6) → 1210 (5.3)
```

**根因**：每次都"写完再统计"，凭感觉估字数永远偏低；每次新增一手素材（配置表细节、设备构成、照片数据）都会反弹。

**正确做法**：先按 1150 字预算写，脚本统计，超了按段落比例砍。目标区间 1100-1200 字。

**有效的砍法**（保留信息密度、砍修饰语）：
- 删重复的框架词（"方向非常清晰"、"技术成色不错"这类评价性尾巴）
- 长列举换成顿号串（"智能适老装备（外骨骼机器人、防跌倒监测）" → "智能适老装备"）
- 删掉可以省的解释性从句（"这些数字第一次以动态方式集中亮相"）
- **不要砍数据和用户原话措辞**
