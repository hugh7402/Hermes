# 矢量路径 PDF → 表格结构逐行还原（完整流程）

来源实战：2026-10-07《某省数字政府项目（某省一体化数据资源管理系统）建设采购需求》PDF，69 页，`%PDF-1.7` 无文字层，每页 891-1012 个矢量绘图对象。
目标：把 3.2 技术要求表（450 行、含大量合并单元格）还原成可逐条比对的结构化表。

## 0. 为什么必须走这条路

- `markitdown` 对矢量转曲 PDF 返回 **0 字符**（不是报错，是静默返回空）——极易误判成脚本坏了。
- 该 PDF 每页 `get_text()=0`、`get_images()=0`、`get_drawings()=746~1012`，且文件内 `/Font`、`/Image`、`/XObject` 计数全为 0。
- 结论：文字以**填充路径**绘制，无字形信息 → 任何文本提取工具都拿不到，只能 OCR 渲染图。

## 1. 分层 OCR 策略（这里踩了两个坑）

### 1.1 整页转录（拿正文，够用）
`qwen-vl-ocr-latest` @ dpi=200，prompt 用 `请提取图片中所有文字，保持原文段落结构。只输出文字，不要加解释。`
- 69 页 / 72s / 297,331 tok ≈ **¥0.089**（并发 6）
- 质量验证：抽 3 页用 400dpi 重跑比对，输出几乎逐字一致（760→763 / 766→766 / 691→695 字）→ 证明 200dpi 无漏读
- 幻觉检测：1171 行里 1162 行唯一，重复 5 处全是合法表头 → 无编造

### 1.2 表格结构还原（拿行结构）—— 必须换模型
| 方案 | 结果 |
|---|---|
| `qwen-vl-ocr-latest` + Markdown 表格 prompt | 还原 406/449 序号，**漏 43 个**；描述被拆到两列 |
| **`qwen3-vl-plus` + 同样的 prompt** | **450/450 序号，0 缺号 0 重号**；描述为完整句子 |
| `qwen-vl-max-latest` | HTTP 403 access_denied（账号无权限） |

**核心差异**：合并单元格（分类列纵向合并、描述列横向合并）需要**语义理解**，转录型 OCR 模型做不到。

### 1.3 两条确认无效的路线（省下重试时间）
- **TSV / 语义重组 prompt**：明确要求「按合并单元格语义输出 TSV」→ 模型只回 22 字符（摆烂）。
- **裁左侧窄条读序号列**：裁 x∈[0,13%] 单独 OCR → 每页都输出 `▲1 2 3 … 86` 连续序列（凭空编造）。**窄条 + 序列推断 = 必编。**

## 2. 可用的 prompt（qwen3-vl-plus）

```
这是一页中文采购需求文档的表格页，表格有合并单元格（分类列纵向合并、要求描述列横向合并）。

请把这个表格**逐行**还原成 Markdown 表格，共 4 列：
| ▲标记 | 序号 | 分类 | 要求描述 |

规则：
1. ▲标记列：该行序号前有 ▲ 就写 ▲，否则留空。
2. 序号列：照抄该行序号。
3. 分类列：该行所属分类若来自纵向合并单元格，请在这行**完整写出**分类名称（不要留空、不要写片段）。
4. 要求描述列：若该行描述由**横向合并的多个单元格**组成，请**拼接成一段完整文字**，一个字都不能少；不要把描述拆到别的列。
5. 没有序号的行（上一条描述的续行）请把序号写 `-`。
6. 不要总结、不要改写、不要补全你没看到的内容；看不清写【?】。

只输出 Markdown 表格，不要解释。
```
参数：`dpi=300`、`temperature=0`、`max_tokens=8000`、并发 5。49 页 / 119s / 162,267 tok。

## 3. 解析器必须处理的 5 件事

1. **▲ 在独立首列**，不与序号同格 → 判定时同时看 `cells[si-1]` 和 `cells[si]`。
2. **描述跨列** → 拼接 `cells[si+1:]`（去掉空与 `/`），**不能只取最长格**（会丢半句）。实测样例：错误结果 `市（州）前置数据库，用于临时存储` / 正确结果 `建设市（州）前置数据库，用于临时存储市（州）推送的相关数据资源`。
3. **分类纵向合并** → 留空的分类需**前向填充**。
4. **多来源合并禁止按页去重**（会丢掉同一页另一个版本的整行）→ 收集**所有来源的所有行**，再按序号分组。
5. **打分选优**：`(以句号结尾, 是否优质模型来源, 描述长度, 是否有标记)` 元组降序取最大。
6. **续行**（序号写 `-`）→ 追加到上一行描述。
7. **「分类：描述」粘连** → 若首个 `：` 前 ≤14 字、无标点、且描述够长，则拆成分类。实测修复 24 行。

## 4. 校验（不通过不能交付）

| 校验项 | 阈值 | 实测 |
|---|---|---|
| **序号连续性** | `1..N` 连续、无缺号无重号 | **0 缺号 / 0 重号**（起点 406 → 450） |
| 描述非空率 | 100% | 450/450 |
| 描述长度中位 | — | 52 字（最长 471） |
| 可疑描述 | 越少越好 | 7 条（仅缺句号或短句，非内容缺失） |
| 抽样回查 | 描述前 8 字能在原页 OCR 中找到 | 404/450（46 条为 OCR 用词变体，非缺失） |

**序号连续性是行结构完整的充要证据** —— 任何缺号必须逐页定位补跑，不能带着缺口交付。

## 5. 关键标记（▲）的三源复核

1. 来源一：整页转录文本里 grep `▲`；
2. 来源二：表格结构解析出的 `marker` 字段；
3. 来源三（独立）：把表格页左侧 42% 宽、纵向**三等分**裁切（dpi=400），逐块问「序号=X ｜ 三角符号=有/没有」，tally 投票。

结论要求：**双源一致 = 高置信**；单源 = 列入人工复核；两源冲突 = 必须裁图点对点确认。
本次实测：20 条双源一致、0 条冲突、1 条（▲215）由第三源发现 → **最终 21 条**。
⚠️ 教训：早先用「展平文本 grep」得出的 11 条是**错的**，因为合并单元格里的标记会随单元格一起被拆散。**标记类清单必须双源以上交叉，不能只 grep 一次。**

## 6. 成本与并发参考

- `qwen-vl-ocr-latest`：输入 0.3 元/M、输出 0.5 元/M（华北2北京）。整页 200dpi ≈ 3.8k tok/页；300dpi ≈ 8.4k tok/页。
- `qwen3-vl-plus`：300dpi 表格页 ≈ 3.4k tok/页（图片 token 更省，但单价更高，以账单为准）。
- 并发：**5**（表格结构）/ **6**（整页转录）稳定无 429；单页 3-13s。
- 本次全流程（含 2 次作废尝试）≈ **142 万 tokens**。
