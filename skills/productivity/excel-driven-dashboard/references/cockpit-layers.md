# 驾驶舱七层：判定口径与下钻数据模型

甘特图之外的那六层怎么算、怎么判、怎么下钻。照此实现，用户第一轮就不会回「太简单」。

---

## 1. 三个进度量（页面上永远同时可见）

| 量 | 来源 | 算法 |
|---|---|---|
| **计划进度%** | 纯计算，不让人填 | `(今天 - 计划开始) / (计划完成 - 计划开始) × 100`，clamp 0–100 |
| **实际进度%** | PMO 每周填 | 0–100 整数；**空 = 未填报，不是 0** |
| **偏差** | 计算 | `实际 - 计划`，负数=滞后 |

- 计划完成后仍为 0 时，计划进度直接给 100（工期为 0 的单点任务同理）。
- **未填报的任务不参与总体进度平均**，但要单独报数（「已填报 37 项（共 39 项）」）。
  把未填报当 0 会让整体进度凭空塌下去，当 100 更糟。

## 2. 健康度判定（用户认这一套，别自创）

| 偏差 | 判定 | 色 |
|---|---|---|
| 状态=已完成 | 正常 | 绿 |
| ≥ 0 | 正常 / 按计划进行 | 绿 `#2E7D32` |
| −1 ~ −15 | 预警 / 轻度滞后 | 橙 `#EF6C00` |
| < −15 | 延期 / 明显滞后 | 红 `#C62828` |
| 实际进度为空 | 未填报（单独一档，不参与判定） | 灰 `#8A96A3` |

判定文案要带数，不要只说“滞后”：
`实际进度 33%，按计划应完成 39%，滞后 6 个百分点，处于预警区间。`

**里程碑过期必须并入总判定**——否则会出现「M1 已过期 15 天」与「按计划进行」同屏自相矛盾。
节点日期 < 今天即视为过期，在判定卡追加红字提示，并把总判定至少抬到预警。

## 3. 关键结论（判定卡里的自动分析）

领导不看表，只看结论。判定卡下方自动生成 2–3 条，全部由数据排出来：

1. 把工作分类、责任组各自按偏差升序排，各取最差一名：
   `▸ 最需关注的工作分类：专属云建设（计划 61% / 实际 38%，偏差 −23，延期 2 项）`
   `▸ 最需关注的责任组：标准组（计划 100% / 实际 80%，偏差 −20）`
2. 延期 / 预警条数汇总，指向问题清单：`▸ 当前延期 7 项、预警 15 项`

只排“有填报数据”的分组；全未填报时不出结论，改写「待填报」提示。

## 4. 偏差对比条（②）

一对多的双维度：**左=按工作分类，右=按责任组**，同一个渲染函数吃两个字典。

- 轨道底色要极浅（`#FAFCFE` + 细边），**计划条用蓝灰实心**（`#B7CFE4`），实际条用蓝（`#2196F3`），
  两段之间的缺口用斜纹（`repeating-linear-gradient`）。轨道本身若做成灰底，用户会把轨道当计划条。
- 右侧数值行固定写「计划 X% ｜ 实际 Y%」，偏差只在数字上着色，不加图标。

## 5. 下钻数据模型（④）

三级，逐层懒展开（`openCat` / `openSys` 两个字典存展开态，点一下重渲染这层即可）：

```
工作分类  lv1 ── 任务数 / 计划 / 实际 / 偏差 / 延期数 / 责任人清单 / 状态徽标
  └ 系统  lv2 ── 同列，系统名取「所属系统」按 / 拆分的第一个
      └ 任务 lv3 ── 计划 / 实际 / 偏差 / 健康度 / 责任人 / 工期
```

- 系统级归组只能用**主系统**（第一个），否则一条任务在多个系统下重复计数、合计数对不上。
- 每一层都要能算出偏差（用同一条 `agg(list)` 聚合函数），否则 PMO 到系统层就断了。
- lv2 点击必须 `stopPropagation`，否则会连带触发 lv1 收起。

### 抽屉（下钻终点）必含

| 区块 | 字段 |
|---|---|
| 任务状态 | 工作分类、所属系统、责任组（+人数）、**责任人**、执行成员、计划工期、计划进度、实际进度、偏差、健康度、问题风险 |
| 关联运营成效指标 | 主线 / 任务名、2026底 / 初验 / 终验 三档目标值、当前完成情况（截断 ~70 字，全量放 title） |
| 关联平台建设项 | `#序号 系统 / 子系统`、建设内容、验收标准尾段 |

「关联建设项」列可能是 `49,62` 或区间 `4-28`，解析要同时支持单号、逗号列表、区间三种写法。

## 6. 问题清单（⑤）：自动挑、带动作

按优先级拼：延期 TOP8（按偏差最差排）→ 预警 TOP6 → **无系统承载**的任务（`所属系统` 含「缺口」或为空）
→ 未填报汇总一行。每条给一句建议动作，不要留空：
「约谈责任人，确认是否需增派资源或调计划」「本周内跟进，避免转为延期」「该任务对应平台建设内容缺失，需补建设项」。

## 7. as-of 数据日期 + 示例数据（让空底盘也能验收）

真实底盘交付时进度%必然全空，全 0 的图什么也证明不了。两个开关，都不违反「不编数字」：

- **数据日期**：顶栏 `<input type=date>`，改它只改 `TODAY` 再重渲染。计划进度、剩余天数、里程碑风险全部跟着走。
  默认今天；双击日期字样回到今天。给用户看的截图建议挑一个项目正中的时点（如开工后 2–3 个月），否则计划进度全是 0。
- **示例数据**：按钮切换 `S.sim`，用固定种子生成偏差分布（~18% 略超前 / ~44% 正常 / ~23% 预警 / ~15% 延期），
  页脚常显「⚠ 示例数据视图」，切回真实数据时立即清空。

种子必须固定，同一份数据每次模拟结果一致，否则截图和讲解对不上。

## 8. 验收断言（写进交付前自检）

```js
S.loaded === true
S.tasks.length / S.ms.length / S.ops.length / S.pf.length / S.weeks.length   // 与底盘行数逐项相等
[...document.querySelectorAll('#drill tr.lv1')].reduce((s,r)=>s+parseInt(r.children[2].innerText),0) === S.tasks.length
document.getElementById('keyFind').innerText          // 关键结论非空（切 as-of + 示例数据后）
document.getElementById('asof') !== null              // 日期控件还在（没被 textContent 干掉）
```

再点一遍 lv1 → lv2 → lv3 → 抽屉，确认抽屉里「关联运营指标」「关联平台建设项」两段都有内容。
