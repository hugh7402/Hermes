# Excel 驱动的作战图 / 进度看板

## When to Use / 何时用

用户手上有多份项目材料（时间计划/甘特 Excel、指标 Excel、人员或架构图），要一张**能体现整体情况与进度、
细到任务、责任到人、到具体时间、且以后能自己改**的视图。

关键判断：**用户要的不是一张画好的图，是一个可维护的图。** 他要的是「改 Excel → 刷新 → 图变」。

不适用：
- 解析别人的离线包 / 大屏 → `offline-web-bundle-inspection`
- 只是把成品包成双击运行 → `demo-launch-package`
- 带假数据的产品原型 → `ui-prototype`；政务配色规范 → `china-gov-ui-standards`

## 核心原则：先定「数据底盘」，图只是它的一个视图

**永远不要先写页面。** 页面一旦硬编码了任务和指标，这份交付就死了——用户下周要改一个日期就得回来找你。

交付物是两件套：

```
data.xlsx           ← 唯一的编辑面（用户改这里）
index.html          ← 读底盘渲染（谁都不用改）
```

🚨 **两个文件名都用 ASCII，不要叫「作战图数据底盘.xlsx」「驾驶舱.html」**——macOS 解压中文名是 NFD、
浏览器请求是 NFC，字节对不上就 404（文件明明在，报错却像启动失败）。机制与兜底链见 `demo-launch-package`。

六张表的列名、填法约束、哪些列是必改列，见 `references/data-backbone-schema.md`。
多份来源材料**各自落成底盘里的一张表**，不要混进同一张：

| 用户给的 | 落到底盘的 |
|---|---|
| 时间计划 / 甘特 Excel（合并单元格画的条） | 任务台账：一条任务一行，含计划开始/完成、责任人、状态、进度 |
| 甘特条起止（合并区） | 解析成 `计划开始`/`计划完成` 两个日期列，**不要保留合并画法** |
| 验收成效指标 Excel（按节点给目标值） | 指标表：一个指标一行，三个节点目标值各占一列 |
| 人员组织架构图 / 人员表 | 组织架构表：组、角色、姓名、人员构成说明 |
| 节点承诺 / 验收条件 | 里程碑表：节点代码、目标日期、交付内容、验收标准 |

## 交付层级：甘特图只是第七块，单独交甘特会被打回

用户说「作战图」时要的是**能判进度、能追责任的驾驶舱**，不是一张排期条。只交甘特 + 数据底盘会被判
「太过于简单」——这是他原话，务必一次做够。

| 层 | 给谁 | 回答什么问题 | 必须有 |
|---|---|---|---|
| ① 总体健康度 | 领导 | 进度多少？延迟还是按计划？ | 大环=总体实际进度 + 判定结论 + 自动生成的「关键结论」 |
| ② 偏差分析 | 领导 / PMO | 哪一类、哪个组拖后腿？ | 按工作分类 + 按责任组两组对比条（计划 / 实际 / 缺口） |
| ③ 里程碑风险 | 领导 | 哪个节点要出问题？ | 每节点：剩余天数、滞后百分点、已过期天数 |
| ④ 系统级下钻 | PMO | 延迟是哪个系统、哪条任务、谁负责？ | 分类→系统→任务三级展开 + 右侧详情抽屉 |
| ⑤ 问题清单 | PMO | 我今天该抓谁？ | 延期 / 预警 / 无系统承载自动挑出，每条带建议动作 |
| ⑥ 指标看板 | PMO | 验收指标谁在拖？ | 指标按主线聚合 + 关联任务进度 + 填报情况 |
| ⑦ 作战甘特图 | 全体 | 时间轴全景 | 见下文甘特渲染规则 |

**下钻终点必须是抽屉，一次列全**：责任组与人数、责任人、执行成员、计划工期、偏差、健康度、问题风险、
关联运营指标（三个节点目标值 + 当前完成情况）、关联平台建设项（建设内容 + 验收标准）。
点不到「具体人 + 具体指标」的下钻等于没做——这是用户衡量「能不能当 PMO 抓手」的唯一标准。

判定口径、偏差公式、关键结论算法、抽屉数据模型见 `references/cockpit-layers.md`。

## 步骤

### 1. 把甘特 Excel 解析成任务台账

原表的甘特条是**合并单元格**（`C4:C9` 这类），任务名在 C 列、序号在 A 列，分类列常常是「只在第一行写、
下面留空靠视觉合并」——解析时**必须向上填充分类**，否则任务会丢分类。

```python
bars = {}
for m in ws.merged_cells.ranges:              # 普通 load，不要 read_only
    if m.min_row >= 4 and m.min_col >= 4 and m.max_col <= LAST_COL:
        s, e = weeks.get(m.min_col), weeks.get(m.max_col)
        if s and e: bars.setdefault(m.min_row, []).append((s, e))
# 一行可能有多段（如「原型确认」+「开发测试」），起止取 min/max
# 没有合并条的任务（只在某一列写了一格文字，如“启动会”）：取该行有文字的列所在周
```

表头是日期序列号（Excel serial）：`date(1899,12,30) + timedelta(days=int(v))`。
周轴**对齐到周一**再生成，否则每周列错开一天。

### 2. 生成底盘（openpyxl，一次成型）

每张表都按「表头样式 + 列宽 + 冻结首行 + autofilter + 换行列」统一处理，用户一眼看得出来哪些是给人填的。
底盘里**再放一张「使用说明」表**：写清哪几列必改、状态只能是哪几个词、进度填 0-100 整数、
日期格式、加行时分类要跟着填。用户不会回来看你的聊天记录，说明要跟着文件走。

### 3. 页面：单文件 HTML + 内联 SheetJS

```bash
curl -sL -o xlsx.full.min.js https://cdn.jsdelivr.net/npm/xlsx@0.18.5/dist/xlsx.full.min.js
stat -c%s xlsx.full.min.js      # 应 ~880KB；几百字节说明下到的是错误页
```

`xlsx.full.min.js` 与 HTML **放在同一目录**、用 `<script src>` 引入（不要 base64 塞进 HTML，会撑到几 MB 且难维护）。

读表：`XLSX.utils.sheet_to_json(sh, {defval:'', raw:false})` —— 用**表头名取列**（`r['责任人']`），
不要用列序号，用户插一列就全错位。

### 4. 加载策略（决定用户第一眼能不能看到图）

| 打开方式 | fetch 同目录 xlsx |
|---|---|
| 启动包 / 任何 http 服务 | ✅ 可用 |
| 直接双击 HTML（`file://`） | ❌ 被 CORS 拦掉 |

所以必须三层兜底，缺一层用户就会看到空图：

1. `loadAuto()`：`fetch('data.xlsx', {cache:'no-store'})`
2. 失败 → 顶部黄色提示条，明确说「用浏览器直接打开时属于正常现象，点右上角『载入数据』选择那份 Excel」
   —— **不要让它静默失败**，更不要报成“文件损坏”
3. 常驻「载入数据」按钮（`<input type=file>`）+ 整页拖拽落区

拿到 ArrayBuffer 后统一走同一个 `apply(XLSX.read(buf,{type:'array'}))`，两种入口共用一套渲染。

### 5. 甘特渲染规则

- 周轴：自最早任务对齐到周一，逐 7 天；右侧每列宽 ~28px，横向滚动容器 + `thead` sticky。
- **月份行按「连续同月」合并 `colspan`**，只在第一个月与跨年的 1 月标年份（`2026年10月`、`2027年1月`）。
  每周都写一次月份会挤成竖排乱码。
- 里程碑用**红竖线**标记：给该周 `<td>` 加 `::before{width:2px;background:#C62828}` + `title="M1 2026-12-31 系统初验"`。
  只把整列染成浅粉，用户会问“这列为什么是红的”，而看不出是哪个节点。
- 任务条：底色按状态（已完成/进行中/未开始/已超期/已暂停），上面叠一层 `width:进度%` 的浅色填充 = 实际进度。
  **图例必须写“浅灰底=计划工期，深色填充=实际进度”**，否则用户会把整条计划期照成的灰条当成“已完成的进度”。
- 本周列加浅黄底，用户一眼定位现在在哪。

### 6. 不编数字：空着就是空着

- 进度%、状态、复盘结论这些**只有用户知道的数据，一律留空**，图上显示 0%、状态“未开始”，
  并在交付话术里明确说“现在图上是空的是因为没有进度数据，这个只能各组填，我不编”。
- 代码里唯一的自动判定只允许是**事实性推导**：完成日期已过且状态未完成 → 显示「已超期」。
- 更不要因为“图太丑没人看”就自己拍一个 60%、80% 进去。
- 但“全 0 的图没法看”是真实交付问题，解法不是编数，而是两个开关：
  **① 数据日期（as-of）**——计划进度由日期推，把时点切到未来某天就能预演「到那天本该到哪一步」，
  这是纯事实推导，不算编数，也是 PMO 每周复盘的正确用法；
  **② 示例数据按钮**——默认关，开启后生成一套模拟进度，页脚必须常显「⚠ 示例数据视图」，并在话术里点明「正式汇报前一定关掉」。
  截图给用户时必须说明「这是示例数据视图」，不能让他以为真实进度已经出来了。

### 7. 交付形态

目录 + zip，`serve.py` 只监听 `127.0.0.1`、端口 8080 起自动顺延、`end_headers()` 强制 `no-store`；
mac 版给 `启动.command`（`chmod +x`）+ `启动.sh` + `使用说明.md`。
打包与地址栏的硬规矩看 `demo-launch-package`。

### 8. 验证（不能只做语法检查）

1. 起服务 → 真 Chrome 打开，断言 `STATE.loaded === true` 与各表行数（任务/里程碑/指标/平台建设）、周轴周数。
2. 断言月份行序列：`[...document.querySelectorAll('thead tr.m th')].map(t => t.textContent + '(' + t.colSpan + ')')`
   —— 跨年、跳月、叠字都在这一步暴露。
3. 断言甘特行数 == 任务台账行数（分类行不计），里程碑单元格数 > 0 且 `title` 有值。
4. 版式看 `printToPDF` 转 PNG（重页面截图会超时），挑体积大的那页看，具体坑见 `offline-web-bundle-inspection`。
5. 真的双击 `启动.command` 跑一遍 `serve.py`，用 `curl -s -o /dev/null -w '%{http_code} %{size_download}'` 三个文件全 200。

### 9. 交付话术：把「我做了判断的地方」单列出来

原表往往没有责任组列、没有细化到人、没有里程碑日期——这些是你**推断**的，不是他给的。
交付时必须分三段写：

1. **有据可依的**：哪几项数据来自哪份材料。
2. **我做了判断的（请他逐行核）**：任务→责任组的映射、责任人填的是组长而非执行人、
   从甘特条反推出来的里程碑日期。每条都写明依据，并给出“挂错的告诉我”。
3. **明确待补的**：进度/状态/占位符姓名/未填的复用人数。

这三段写清楚，用户回的是“哪里改一下”；不写清楚，回的就是“这不对那也不对”。

## 坑

- **合并单元格是这类表最大的陷阱**：读出来是空、写进去报 `MergedCell ... read-only`，
  要先建 anchor 映射再读/写，否则缺口数量会被放大成好几倍。细节见 `xlsx` 的 Pitfalls。
- **分类列靠视觉合并**：只在首行写、下面留空，解析时必须向上填充。
- **不要用列序号取数据**，用表头名；用户加一列就全错位。
- **`file://` 下 fetch 必失败**，这是浏览器安全策略，不是 bug——三层兜底 + 明确提示，别当成错误去查。
  提示条里直接给一个**大按钮**调 `document.getElementById('file').click()`，比让用户自己找右上角按钮成效率高一些。
- **重页面（10MB+ 单页）截图会 60s 超时**，改 `printToPDF` + PyMuPDF 转图。
- **月份行每周写一次月份**会把 28px 列挤成竖排，必须按连续同月 `colspan` 合并。
- **灰条被当成“已完成”**：图例必须区分“计划工期底色”与“实际进度填充”。
- **`container.textContent = ...` 会连带干掉容器里的表单控件**：刷新时若整体改写了含 `<input type=date>` 的顶栏，
  之后 `getElementById` 拿到 null、交互全废。容器里只要有控件，就只改独立的子 `<span>`，不要改父节点文本。
- **不要照着 vision 报的“数量对不上”去改代码**：分页 PDF 会把表格切断，视觉模型据此断言「39 项只剩 36 项」「某分类缺失」，
  实际是续页没截进来。凡是要动代码修“缺失/不一致”，先用 JS 把数加一遍
  （`[...document.querySelectorAll('tr.lv1')].reduce((s,r)=>s+parseInt(...),0)`）再决定。
- **`write_file` 拒写已有文件时不要硬改报错**：新建脚本用新文件名（`build_v2.py`），要覆盖既有交付文件就先 `rm` 再写，
  不要在原文上反复试。
- 涉密材料全程本地解析、只监听回环、不发网盘；交付说明里写明“只在本机跑，不要放公网”。
