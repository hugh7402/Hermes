# 中文公文 .docx 交付（cn_docx 路径）

**适用**：把已有的 markdown / 会议纪要 / 报告转成交付用的中文公文 docx，要求标题层级清楚、字体合规、手机上好读。

字体属性本身为什么要写 `w:eastAsia`，见 SKILL.md 的 CJK 陷阱条目；本文只讲工作流和交付约定。

## 字体分工（用户未指定时按此默认）

| 位置 | 字体 | 字号 |
| --- | --- | --- |
| 大标题 | 黑体 | 22pt |
| 一级 / 二级小标题 | 黑体 | 16 / 15pt |
| 正文 | 仿宋_GB2312 | 16pt（三号） |
| 引述 / 录音原话 / 待确认说明 | 楷体_GB2312 | 14pt |

页面：A4，公文页边距 top 37 / bottom 35 / left 28 / right 26 mm，页脚加页码。

## markdown → spec 的映射

写个小转换脚本，不要手抄 spec：

| markdown | spec block |
| --- | --- |
| `# 标题` | 顶层 `title` |
| `## 一级节` | `h1`（黑体） |
| `### 二级节` | `h2`（黑体，小一号） |
| `> 引述` | `p` + `font: 楷体_GB2312` |
| `\| 表格 \|` | `table` |
| `- 列表项` | `p`，文本前保留「· 」并缩进 |
| `**粗体**` / `[[双链]]` / 行内 code | 去掉标记，只留文字 |

表格判定：`|` 开头**且下一行匹配** `^\|[\s\-:|]+\|$` 才是表头，否则只是正文里的竖线。

## 表格字体会不一致

`cn_docx.py` 的表格默认 `cell_font` 是 **仿宋**（不是 `仿宋_GB2312`）。要和正文统一，必须在 table block 里显式传 `cell_font: {name: '仿宋_GB2312', size: 10}`，否则同一份文件里会出现两种仿宋。

## 交付前反向读校验（必做）

不信生成代码，直接读回 docx：

1. **关键词 / 关键数字反查** — 把必须保住的那批词和数字列成清单，逐条 `in text`，报「命中 n/N」。这能拓出排版时静默丢字/掉数字。
2. **字体实测** — 遍历 run 读 `w:eastAsia` 并计数，确认三类字体都在，不能只看 spec。
3. 段落数、表格数、总字数对一遍。
4. `docx_validate.py` 返回 `{"ok": true}`。

## 排版坑

- spec 的 `blocks` 是一个平铺列表，**没有嵌套**：层级只靠 `h1`/`h2` 和缩进体现，不要指望自动编号。
- 转换脚本必须跳过原文 frontmatter（`---` 之间的 YAML），否则 tags/summary 会变成正文第一段。
- 引述块的连续 `>` 行要**先合并成一段**再输出，逐行输出会碎成多段。
- spec 的 JSON 等中间件生成在临时目录，**交付目录只放最终 docx**，不要两种版本或多个中间文件混在一起。
