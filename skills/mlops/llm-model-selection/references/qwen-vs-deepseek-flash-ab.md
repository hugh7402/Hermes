# Qwen3.8-Flash vs DeepSeek-V4.1-Flash-1017 — 实测对比（2026-11-04）

场景：用户（联通政务咨询规划岗）日常任务 = 政策/方案写作、指标结构化对照、长文档理解。
两家都能用同一把百炼 key（`dashscope` provider，`api_key: ${BAILIAN_API_KEY}`）。

## 结论

**分用途选，不是一个模子通吃：**

| 用途 | 选谁 | 理由 |
|---|---|---|
| Hermes 交互主力（跑 agent loop） | DeepSeek（`deepseek-v4-flash`，官方，已路由 V4.1） | 指令结构理解强、非推理别名不会静默出空 |
| 备用 | 百炼 `qwen3.8-flash` | 跨厂商，主方全线故障时不会一起倒；但**复杂嵌套指令会误读结构**，只兜底 |
| **长文写作（方案/报告）** | **百炼 `deepseek-v4.1-flash-1017`** | 同 prompt 写 2000 字：25.5s/¥0.0278，比官方同代快 26%、便宜 41%（**字数差异不可靠，见下方「复核」**）。见下方四模型实测 |

一开始只看两个 flash 的短任务 A/B，得出“主力继续用 DeepSeek”是对的；但那不能直接套到长文写作上——长文是另一个工况，必须单独测。不是价格原因（见下），而是**复杂指令结构理解**：

- T1（三阶段×每段三段式的政务成效写作）：Qwen 把“三个阶段（时间轴）”误解成“运营起点/成效/指标（内容维度）”，整篇作废；DeepSeek 三阶段划分正确、每段首句提纲挈领、指标逐项留【待补】。
- T3（信息不足时的抗编造周报）：两者都不编数字，但 Qwen 自行添加了“当前风险/其他潜在阻碍”等无来源条目，DeepSeek 只写给定信息并在末尾统一声明缺项。
- T2（指标↔建设项承载对照）：平手，都给完整表格且对无对应项写“无法确定”未硬凑。

## 关键教训：思考 token 是成本大头

两个都是推理模型。第一轮没关思考时：

- Qwen 在 T1 上输出 11,383 token，其中 **11,172 是 reasoning**，正文只剩 211，耗时 **201.9 秒**。
- DeepSeek 在 T1 上 3,000 输出**全部**是 reasoning，正文为空（撞 `max_tokens`）。

关思考（`enable_thinking: false`）后同一批任务：Qwen 4.6s / 204 token，DeepSeek 6.5s / 323 token，两边 reasoning 归零，总成本 Qwen ¥0.0013、DeepSeek ¥0.0041（峰时价）。

**结论：cron 批处理类任务（入库、OCR、巡检、备份）必须关思考；否则 20~50 倍的无效开销全按输出价付费。**

## 四模型长文实测（2000 字政务方案章节，同 prompt）

工况：plan-writer 的真实任务——按「总述→分节→分阶段收口」写 2000 字标准地址平台技术路线，硬约束是**不得编造任何数字**。`max_tokens` 给到 16000。

| 模型 | 汉字（各 1 次，**不可作质量依据**） | 耗时 | 成本 | 小节 | 编造 | 套话 |
|---|---|---|---|---|---|---|
| **百炼 `deepseek-v4.1-flash-1017`** | 2301 | **25.5s** | **¥0.0278** | 7 | 无 | 无 |
| 官方 `deepseek-v4-flash` | 1675 | 34.7s | ¥0.0472 | 7 | 无 | 无 |
| 官方 `deepseek-v4-pro` | 1860 | 136.9s | ¥0.0823 | 6 | 无 | 无 |
| `qwen3.8-flash` | 2358 | 164.5s | ¥0.0284 | 10 | 无 | 无 |
| `qwen3.8-max` | 2135 | 266.3s | ¥0.3765 | 8 | 无 | 无 |

关键读法：

1. **质量维度四家打平**——都没编数字、都没有“综上所述”这类套话、都写了分阶段落地收口、七级要素和编码标准都对。差异全在速度和成本。
2. **贵不等于好**：`qwen3.8-max` 贵 13.5 倍、慢 10 倍，字数比 flash 还少、小节数一样、质量同样无优势。高价模型的溢价在长文写作上**买不到东西**，别想当然认为旗舰更会写。
3. **必须按真实输出长度测**：短任务只看得到“谁想得久”，长任务才看得到“谁写得出来”。
4. 自动判“编造数字”的正则要排除标准号：`DB51/T 2441-2018` 里的 `5` 会被误报，别把它当编造。

## 🚨 复核：单次采样的字数差异是噪声（2026-11-04 追加）

上表每格只跑了 **1 次**。据此得出的“官方版思考占 81% / 正文只出 1675 字 / 差 27%”**不成立**。补测各 3 次（380 字短任务，同一 prompt）：

| 模型 | 汉字中位（全距） | 思考占比中位 | 耗时中位 | 输出 token 中位 |
|---|---|---|---|---|
| 官方 `deepseek-flash` | 377（368~383） | 90% | 17.5s | **3081** |
| 百炼 `deepseek-v4.1-flash-1017` | 404（367~411） | 88% | 15.8s | 2517 |
| 百炼 `deepseek-v4.1-flash`（不带日期） | 383（367~416） | 85% | 14.4s | **1849** |

**结论改写：**

- **字数全距完全重叠（368~416）**，单次 2301 vs 1675 是撞上了两端极值。**不能据此判断模型产能差异。**
- **思考占比三家都在 79~91%**，“官方版思考更冗长”是伪差异。
- **唯一稳定的差异是输出 token 效率**：1849 / 2517 / 3081，差 67%。官方为写出同样约 380 汉字要多烧六成思考 token。这是平台的 serving 差异，不是模型能力差异。
- 规则：**模型对比至少跑 3 次取中位数，看全距重叠再下结论。** 单次 A/B 的结论不可写进 skill。

## 三个名字的关系（易混）

| 名字 | 平台 | 实质 |
|---|---|---|
| `deepseek-flash` | 官方 | V4.1 Flash 最新版，官方 `/v1/models` 只有它和 `deepseek-v4-pro` |
| `deepseek-v4-flash` | 官方 | **旧名兼容别名**，不在模型清单里，路由到 `deepseek-flash` |
| `deepseek-v4.1-flash-1017` | 百炼 | 冻结在 2026-10-17 的快照 |
| `deepseek-v4.1-flash` | 百炼 | 最新版，不带日期，输出 token 最省但行为会随上游迭代变 |

## 实测方法（可复用）

```python
# 请求体关键字段
body = {
    "model": model,
    "messages": [{"role": "user", "content": prompt}],
    "max_tokens": 4000,
    "enable_thinking": False,   # 关键：否则 reasoning 吃光预算
    "temperature": 0.3,
}
# 成本 = prompt_tokens/1e6*输入价 + completion_tokens/1e6*输出价
# 注意 completion_tokens 含 reasoning_tokens，按输出价计费
```

坑：`max_tokens` 要留够。推理模型会先烧思考，`max_tokens` 给小了（如 3000）会得到**空正文**，看起来像模型没有能力，其实是参数问题——判读结果前先看 `completion_tokens_details.reasoning_tokens` 占了多少。

## 成本量级提醒

按该用户 30 天真实用量（输入 79 万 / 输出 9.4 万 token），月成本 Qwen ¥0.89、DeepSeek 闲 ¥1.17 / 峰 ¥2.34；即便全部按输入价重算也不到 ¥15/月。**这个量级下不要按价格选模型，要按效果和场景选。**
