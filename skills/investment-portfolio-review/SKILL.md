# 持仓复盘与行情定位

回答“我这笔怎么样、现在该不该动”，而不是给一份行情综述。

## When to Use

- 用户报了一笔买入（品种、克数/股数、成本价），想知道浮盈亏
- 用户发来券商/银行 App 截图要他看持仓
- 用户问“现在能不能加仓/该不该卖”
- 用户要找黄金/股票的分析 skill

不适用：开户、下单、转账等操作类需求。**不碰用户账号密码，也不代下单。**

---

## 一、第一步永远是问清品种（不问就答必错）

**同一块金子，品种不同，定价机制完全不同。** 这步没确认就下结论，结论会全错。

| 品种 | 你看到的价 | 退出方式 | 买卖摩擦 |
|---|---|---|---|
| **账户金**（银行黄金账户 / 积存金 / 纸黄金） | 实时报价，**卖出价就是你的净值** | 按卖出价即时成交 | 点差，无回收折价 |
| **实物金条** | 银行挂牌价（含加工费溢价） | 按**回收价**回购 | 挂牌价与回收价差很大，买入即产生 |
| **黄金 ETF** | 二级市场价 | 盘中卖出 | 佣金，无实物折价 |
| **金饰** | 品牌零售价（含工费） | 回收按旧金价 | 磨损费＋工费几乎全损 |

🚨 **最容易犯的错：把实物金条的“回收折价”套到账户金上。** 账户金按实时卖出价即时兑付，不存在回收打折；反过来，拿账户金的逻辑去看实物金条会严重高估可兑现值。开盘前先问一句“你是在银行 App 里买的，还是拿的实物？”

## 二、招行黄金账户（已实测）

| 项 | 值 |
|---|---|
| 定价 | 挂钩上海黄金交易所 Au99.99，**双边总点差 5 元/克（买卖各 2.5）** |
| 持仓金额 | **按卖出价计**，不等于买入价 |
| 出金 | 卖出资金 **T+1** 可提（国有大行多为当日可取） |
| 交易时段 | 交易日 9:10 — 次日 02:00（覆盖欧美盘） |
| 风控 | 行情剧烈波动时会**动态上调点差**，下单前先看当天实际点差 |

## 三、报价口径陷阱

**银行 App 上那个大字“买入价”不是你的净值。** 买入价是银行卖给你的价，你要卖只能按卖出价成交，中间吃掉的正好是点差。

- 算收益、算仓位、报结论，**一律用卖出价**
- 盯盘时若习惯性看买入价，会系统性高估 5 元/克（50 克就是 250 元）

## 四、持仓复盘流程

1. **确认品种**（见 §1）
2. **取当日报价**：上海黄金交易所 Au99.99 延时行情；国际现货 XAU/USD；实物另取银行投资金条挂牌价与水贝回收价
3. **反推验算截图**（有截图就必做，能立刻判定口径有没有错）：
   - `持仓金额 ÷ 持仓克数` → 应正好等于 App 上的**卖出价**；对不上就是看错了口径
   - `持仓金额 − 成本价×克数` → 应等于 App 上的持仓收益
   - `买入价 − 卖出价` → 就是当天实际点差
4. **收益率** = 浮盈 ÷ 本金；同时把点差摩擦算成钱（克数 × 点差），告诉用户这是沉没成本
5. **位置判断**：卖出价在**当日区间**里的分位（(现价−最低)/(最高−最低)），以及距日内高/低点差多少。高于 70% 分位就是当天高位，**不是加仓位置**
6. **仓位测算**：当前市值 ÷ 总资产，对照用户既定分层目标给出“还差多少元、多少克”
7. **结论要可执行**：说清“现在不是加仓位置 / 可以分批接 / 已到止盈区”，不要停在“注意风险”

## 五、用户既定口径（沿用，不要重新问）

- 总资产规模人民币 120 万元
- 稳健分层：国债/大额存单为底仓 ＋ **黄金 10%–15%（12–18 万）** ＋ 美元定存
- 加仓节奏：**分批**，一轮下跌接一点；单日反弹日不追（尤其当日已涨 2%＋时）

## 六、铁律

1. **不编价格。** 所有报价必须来自当次检索或用户截图；取不到就直接说取不到，用旧价推算要明确标注是哪天的价
2. **截图数据优先于用户口述。** 用户口头说的成本价常是取整值（“765”），截图里是 765.73，差 0.1% 会让反推验算对不上
3. **不把挂牌价当可兑现价。** 只有当品种是实物金条时才谈回收折价
4. **不做诊断式断言。** 给位置、给摩擦成本、给仓位缺口；不打包票预测方向
5. 金额用表格对齐，避免只给一个“赚了 621”而不给成本、收益率、点差三项

## 七、用户问“有没有 XX 分析 skill”时

先搜 ClawHub / Skywork Skill Hub / skillsmp，但**把各自的限制说清再给结论**：生态锁（OpenClaw 的 `openclaw skills install` 本机跑不了）、平台锁（Skywork 内 skill 拿不下来）、正文空壳（只写了功能列表、买卖信号与数据源章节是空的）。不要因为“名字对”就推荐装。

常见结论：针对单一资产的第三方 skill 价值有限——核心就三件事（取准时点的价、算清真实可兑现盈亏、给仓位缺口），本地写脚本比装别人的更准，因为口径能按用户品种定制。

## 八、做成每日定时简报

用户说「做个监控」或「每天给我一份简报」时，不要接第三方 skill，直接本地起一个零 token 的 cron：

| 件事 | 怎么做 |
|---|---|
| 拿价 | 东方财富 `push2` 为主源、新浪 `hq.sinajs.cn` 为备源，双源都取不到就明说取不到 |
| 换算 | 中间价≈Au99.99现价，**卖出价 = 中间价 − 2.5**，一切结论用卖出价 |
| 输出 | 行情 → 你的账户（卖出价/市值/浮盈/点差摩擦）→ 位置与仓位 → 一句可执行结论 |
| 投递 | `no_agent=true` + `script`，stdout 原样发，不需模型、零 token |

四个必踩的坑：

1. **cron 最小环境没有 `TZ`**，脚本开头必须 `os.environ['TZ']='Asia/Shanghai'` 再 `time.tzset()`，否则取价时间显示成 UTC。
2. **`hq.sinajs.cn` 不带 `Referer` 返回空**，`User-Agent` 和 `Referer: https://finance.sina.com.cn` 两个头都要。
3. **cron 的 `script` 只认 `/opt/data/scripts/` 下的文件名**，传绝对路径会被拒；配置文件和历史数据可以放别处，用脚本内绝对路径指。
4. **同日重跑会写重复行**，写历史前先读全表、剔掉今天那行、再整体重写。

建完立刻 `cronjob_manage(action='run')` 打一次端到端（脚本→定时器→投递），并在 `env -i PATH=/usr/bin:/bin HOME=/opt/data` 下复跑，两条都过才算能上。

完整实现（数据源字段、脚本/配置布局、cron 参数、自检命令）见 `references/daily-briefing.md`。
