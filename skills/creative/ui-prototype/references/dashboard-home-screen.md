# 大屏「总屏 / 首页」设计与验证

适用：用户已有一套 N 屏汇报大屏（每屏一个板块：数据汇聚、数据治理、数据赋能…），要再补一张**总屏/首页**，作为领导汇报的起点。

与 `image-hotspot-dashboard.md` 的分工：那篇是「页面已经是做好的截图、只叠热区」；本篇是「**新画一张**总屏，风格要与既有各屏一致」。

## 需求口径：四条几乎总是同时出现

1. **少放数据、不接后台** —— 数字会变，写死就错，所以尽量不写量化指标。
2. **要有综述感** —— 是 N 个板块的总览和讲解起点，不是又一张明细屏。
3. **风格与既有各屏一致** —— 配色、导航形态、面板质感都要对齐。
4. **别把 UI 工作量做大** —— 不要图表引擎、不要 Canvas。

## 第 1 步：先从既有截图量出视觉规范，不要凭印象配色

把每一张既有屏交给 `vision_analyze`，**只问视觉不问业务**：

> 只描述视觉设计规范，不要业务内容：1) 背景最暗/最亮处色值；2) 导航栏文字颜色、当前项高亮表现；3) 主标题颜色与字体观感（发光/描边）；4) 面板边框颜色、有无发光、圆角、内部底色；5) 主强调色与次强调色各用在何处；6) 有无装饰纹样。

同时用 PIL 量出各屏真实像素尺寸与比例：**同批图比例常常并不统一**（实测一批 6 张里混了 1.77 / 1.93 / 2.04 三种），总屏取**出现次数最多的那个比例**，并在交付说明里点出不一致的那几张会露黑边。

深色政务大屏的典型取值（可直接作为起点，按实测微调）：

```css
background: radial-gradient(ellipse 74% 62% at 50% 42%,
  #0B335D 0%, #082A4C 26%, #04162B 58%, #020A16 82%, #010713 100%);
/* 青蓝主强调 #2FD6FF / #4FE2FF；金橙次强调 #FFAC2F 只给「当前阶段」和序号；
   面板 linear-gradient(160deg, rgba(9,46,85,.92), rgba(4,26,52,.96))；
   边框 1px rgba(47,214,255,.26)；斜切角用 clip-path: polygon(…14~28px…) */
```

暗角用 `::after` 的 radial-gradient 压边，层次色带用 `::before` 的上下淡青，别用网格线。

## 第 2 步：结构模板（N 个板块 → 三段式）

把 N 个板块压成「总览 → 主流程 → 保障层」三段，**编号必须等于阅读顺序**（01→02→…→0N），否则一眼就乱：

```
┌ 标题 + N 项导航（左右分排，与既有屏同形）────────────┐
│ 01 项目总览：一条阶段轴，当前阶段用金橙点高亮          │
│ 02 → 03 → 04：主流程三卡，卡间加箭头表流转             │
│ 05 | 06：两大保障层，两列并排托底                      │
└──────────────────────────────────────────────┘
```

映射规则：有先后关系的板块（汇聚→治理→赋能）放中段用箭头串起来；**贯穿性/约束性的板块（安全、制度）放底部当保障层**，两列并排，语义正好是「托底」。

⚠️ 一开始容易把「贯穿性」板块插在总览和主流程之间（因为语义上它包住一切），结果编号变成 01→05→02→03→04→06，评审第一眼就指出「顺序与阅读习惯冲突」。**视觉位置服从编号顺序**。

## 第 3 步：零数据的填法——每卡四行定性 + 一行导览语

不写数字不等于卡片只能放一句话。每张主卡按这四层填，内容全是定性表述、后台怎么变都对得上：

```
【序号 + 板块名】        ← 04 数据赋能
【四行业务说明】         ← 围绕自然人与法人 / 提供画像分析与综合查询 /
                            支撑部门业务与领导决策 / 把治理好的数据真正用起来
【看：……】              ← 看：数据反哺业务成效        ← 告诉领导这块屏关注什么
【关键能力标签】         ← 自然人 法人 画像分析 综合查询
```

「看：……」这一行是把总屏做成**导览屏**而不是目录页的关键——领导知道每块屏该看什么，才愿意往下点。

## 第 4 步：版面必须「定高 + 均匀分布」，否则一定塌成大片空白

🚨 **最高频的返工点。** 容器高度远大于内容时，`justify-content: space-between` 会把剩余空间全摊进块间距：

- 症状：内容只有 ~520px，容器 1041px → 块间距被撑成 **各 259px**，看着像「上下分三段、中间大片空场」。
- 二次症状：改用 `flex:1` 让主流程区吸收高度后，卡内三段（标题/正文/标签）又被 `space-between` 摊成 **各 190px**，变成「卡里也空」。
- 正解：**每个区块给固定高度**（`min-height` / `height`），再由父级 `space-between` 分配**已知且均等**的块间距；卡内同理定高。验收目标是两个数字都落在几十像素：

```
块间距 79 / 79 px      卡内三段间距 28 / 28 / 28 px      ← 实测可交付状态
```

补内容也是正解之一：把正文从 3 行扩到 4 行（仍然是定性文字），比继续压高度更自然。

**必须量，不许看着调。** 每次都改一个版本再目测，要迭代五六轮；量一次就知道该收多少：

```js
const kids=[...document.querySelector('main').children].map(e=>e.getBoundingClientRect());
const gaps=[]; for(let i=1;i<kids.length;i++) gaps.push(Math.round(kids[i].top-kids[i-1].bottom));
// 卡内同理：遍历 .node 的直接子元素，算相邻 gap
```

## 第 5 步：中文断行必须显式控制

浏览器对 CJK **在任意汉字之间都会断行**，正常字号下必然出现「把治理好的数 / 据反哺决策」这种把词劈开的断法，专业度直接掉一档。

没有办法用 CSS 可靠地按词组断行（`word-break`/`line-break` 对 CJK 无效）。**唯一可控的做法是把文案切成短句、在语义边界写 `<br>`**：

```html
<div class="node-desc"><span>围绕自然人与法人<br>提供画像分析与综合查询<br>把治理好的数据反哺决策</span></div>
```

前提是按卡片实际内容宽度估算每行字数（卡宽 − 左右 padding，除以字号），每行留出余量，否则 `<br>` 之外还会二次折行。

## 第 6 步：验收三件套

1. **几何量化**（真 Chrome）：块间距/卡内间距是否均等、卡片是否等宽同高、**多栅布局下各栅首行元素的 `top` 是否齐平**、编号顺序、`overflow` 是否为空、`page_errors` 是否为空。

   多栅最容易漏的是**首行基线**：某一栅的卡片用 `justify-content:center` 时标题会被推到中间，
   实测中栅标题 `top=294` 而左右两栅 259/262，差 35px，vision 会直接点「三栅横向阅读线不齐」。
   修法：把该栅改成 `justify-content:space-between`（或 `flex-start` 配固定 `padding-top`）并微调，
   把三栅首行 `top` 收进 **~15px 内**（实测收到 259/249/262 即可）。断言写法：

   ```js
   {'left':  document.querySelector('.ph-head').getBoundingClientRect().top,
    'mid':   document.querySelector('.ncard .n-head').getBoundingClientRect().top,
    'right': document.querySelector('.scard .s-head').getBoundingClientRect().top}
   // 三者极差 < 15px 才算齐平
   ```
2. **`vision_analyze` 看截图**，问法要具体：「有无重叠/错位/裁切/中文拆词？上下是否饱满、有无大片空白？层级是否清晰？」——它会点出自己量不出来的观感问题，但**它的判断要换算成数值再改**。
3. **`slopscan` 必须 0 fail**，再核外链数量为 0。

```bash
node /opt/hermes/optional-skills/creative/auteur/scripts/slopscan.mjs <产物.html>
grep -cE 'https?://|src="//|@import' <产物.html>     # 期望 0
```

## 第 7 步：交付与跳转钩子

- 单文件自包含、零外链零 CDN，画布用**固定 px + `transform: scale()` 等比缩放**适配任意屏，不裁切不变形：

```js
var s=Math.min(innerWidth/W, innerHeight/H);
stage.style.transform='translate(-50%,-50%) scale('+s+')';
```

- **导航与入口块都要可点**，但分屏 HTML 还没接进来时不要留死链：点击先弹 toast，并留一个整合钩子，等分屏接入时只改一处：

```js
function goScreen(id){ toast('进入「'+LABEL[id]+'」'); if(window.__onNavigate) window.__onNavigate(id); }
window.__proto={go:goScreen, toastText:()=>toastEl.textContent, current:()=>'overview-home'};
```

- 总屏上**不要给任何导航项加高亮**——此刻并不属于任何一个板块，硬加会误导；靠中段入口块的悬浮态表达「这里可点」即可。
- 交付说明里主动点出：哪些行/块没有数字（因为不接后台）、原各屏比例不一致的那几张、以及跳转钩子的接入位置。

## 第 8 步：被要求「再出两版、风格要有区分」时

用户看完第一版常追加「再出两版，风格和这版要有区分」。**变体只动三样东西，深蓝底子一律不动**——
动了底色就不再像同一套大屏体系，评委会觉得是另一个产品：

| 变体维度 | 可选项 |
|---|---|
| 版式语言 | 纵向清单（总览条→主流程横排→保障条）｜三栏分区（左进程／中主线／右保障）｜中心辐射（核心居中、板块环绕） |
| 容器造型 | 斜切角 `clip-path` ｜ 直角卡片 ｜ 圆角 + 同心圆环 |
| 主强调色 | 青蓝为主＋金橙点缀 ｜ **金橙为主**（青蓝退回辅助） ｜ 青蓝＋加同心虚线环 |

背景层次也可以换手法：径向渐变光晕 ↔ 平铺 64px 细网格（`linear-gradient` 双层 1px 线，透明度 0.04~0.05），
两者观感差距很大但不破坏配色。导航形态同理（斜切块／直角小按钮／胶囊）——这三处一起换，区分度就够了。

交付时给一张三版对照表（主强调色／版式／装饰／导航／气质），并**给出你的倾向和适用场景判断**：
清单式阅读顺序最直白、最适合逐屏汇报；三栏式信息分区最像驾驶舱；辐射式最抓眼但需要靠编号才能理清先后，
对不熟悉系统的人偏绕。别只丢文件让用户自己挑。

### 中心辐射版的三个专属坑

1. **核心必须纵跨整块才真正居中。** 把核心放在两行格子里的某一行（`grid-row:2`）会变成「底部中央核心」，
   辐射感全失。正解：`grid-column:2; grid-row:1 / span 2`，并断言 `core` 的 `cx/cy` 与辐射区容器的 `cx/cy` 相等
   （实测两者都是同一个点才算过关）。
2. **环绕节点用 3 列 × 2 行的格位摆放**，左右各两卡、核心占中列跨两行，天然对称，不需要手写绝对坐标。
   编号顺序按「左列自上而下、右列自上而下、底部托底条」读，配合序号徽标即可，别为了凑顺时针把编号打乱。
3. **阶段轴的当前节点不要同时改字号 + 圆点尺寸 + 强光晕**。10px→14px 加亮环会被读成「有两个当前节点」。
   只用颜色与光晕区分，尺寸保持全轴一致。

### 某一栏内容撑不住高度时的两种补法

均衡度检查会显示某列「卡内 slack 一百多到两百多 px」。按顺序试：

1. **把标签行从单行 flex 改成 2×2 `grid`**（`grid-template-columns:1fr 1fr`，标签加 `text-align:center` 与纵向 padding）
   —— 同一批标签占两行，slack 立降（实测 179 → 114）。
2. **补一块不带序号的「小结」卡**（如「保障格局」一句话收口），让该列变成三块等高，与中栏节奏对齐。
   不带序号是为了不打乱 01→0N 的编号序列。

## 验收时的一个假信号

`vision_analyze` 是**观感裁判，不是量尺**。实测它断言「04 数据赋能的卡片明显高于 02/03」，
而 `getBoundingClientRect()` 量出来是三张各 312px 完全相等。
所以：**凡是「高度／宽度／间距／位置不一致」这类数值结论，一律先量再改**；
vision 的意见只用来决定「哪里观感不好」，改法由数字定。反过来，它很擅长抓中文拆词、编号顺序反常、
大片空白这类肉眼可见但脚本难写断言的问题，这两类信号分工要分清。
