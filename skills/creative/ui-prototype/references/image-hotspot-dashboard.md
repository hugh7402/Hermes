# 图片热区型大屏（图片只读 + 叠加导航）

一类独立的原型形态：**页面已经是做好的大屏截图**，任务不是再画 UI，而是给这些固定图片套一层可点击导航，让领导先看交互效果再定方案。

与主 skill 其他路线的区别：不走 WeasyPrint、不生成 UI、不碰图面。核心风险不在样式，而在**坐标**和**页面身份**。

---

## 一、三条铁律

1. **图片只读**。原图像素级不动——不裁、不缩放、不调色、不覆字、不加蒙版。base64 原样内嵌，页面上呈现的就是用户给的原图。
   验证方式见第五节，必须脚本断言 `filter:none / opacity:1 / transform:none / naturalWidth==原宽`。
2. **交互全部是叠加层**。可点击区域、悬停提示、面包屑、返回，都浮在图片之上，**不侵入图面**，且能一键全部关掉（`H`）只剩纯图。
3. **一套图 ↔ 一张地图**。新图进来只补地图对应行，不改代码结构——所以生成器必须把「屏定义」和「热区」做成数据表。
4. 🚨 **收到图只登记，不自动构建产物**（用户明确要求过）。每来一批图只做三件事：图存进 `img/` 并按语义命名 + `md5sum` 与源文件逐字节核对、像素级量出热区坐标、更新生成器里的屏定义表。**不要跑构建、不要生成 HTML、不要截图**——等用户说「出图 / 要 HTML」再一次性构建 + 验证。
   理由：这类工作是「边收图边改结构」的长过程，每来一张就重出一版只会堆一堆中间产物，用户还得逐个确认哪版最新。已生成的旧产物留着别删，说明「未更新」即可。

## 二、🚨 页面身份 = 图片文件名

**不要靠「哪个导航项高亮」推断这张图是哪一页。**

大屏截图里的高亮态经常与页面语义不一致（默认态高亮、沿用模板、设计稿未同步），据此推断会把图挂错页面，而且**用户是按文件名认图的，他会直接指出错误**。

做法：
- 拿到图后**先问自己「用户会怎么称呼这张图」**，按文件名/用户口述给每张图定页面；
- 图片文件也**按语义重命名**（`p0_shouye.jpg`、`p2_shujufuneng.jpg`），别留 `img_aaff077.jpg` 这种无意义名；
- 高亮态只能当参考，不能当判据。图上高亮项与文件名冲突时，**以文件名为准**。
- **向用户汇报时同样用文件名指代页面，不要写「图1 / 图2 / 图3」**。同批大屏版式相近，用序号指代会说错归属（把首页当成数据汇聚页报给用户，当场被纠正）。交付说明一律写成表格：`图片文件名 → 归属页面 → 该页可点热区`。

## 三、网站地图：照用户说的写，不要发明层级

用户描述的层级就是全部层级。**不要自行加专题页、下钻页、弹窗层、二级标签层。**

判断方法：把用户原话里的名词数一遍（「1 个首页 + 4 个二级页」= 5 屏），地图就写 5 屏。多写出来的每一屏都要用户花时间否掉，而且会让他认为你没听懂。

地图里必须有的四样：
1. 结构树（就写实际层级）
2. 页面清单表：编号 / 页面 / **图片文件** / 路由
3. 导航与跳转表：点哪里 → 跳到哪，适用哪些屏
4. 交互约定 + 图片规范（尺寸/比例/命名）

路由用拼音首字母短名（`/sjhj`、`/sjzl`），汇报时可现场报地址直达某屏。

## 四、热区定位：像素级探测，不要用 vision 目测

**从 vision 读出来的坐标不可信**（自报误差 ±10px，且会整行编造位置）。用像素统计定界。

分两步：先按**行**找文字带，再在带内按**列**聚类成块。

```python
from PIL import Image
import numpy as np
im = Image.open(p).convert('RGB')
a = np.asarray(im).astype(int)
lum = 0.299*a[:,:,0] + 0.587*a[:,:,1] + 0.114*a[:,:,2]

# ① 行带：找出文字所在的水平区间
rows = [y for y in range(0, 230) if (lum[y] > 170).sum() > 15]
bands = []
s = prev = rows[0]
for y in rows[1:]:
    if y - prev > 4: bands.append((s, prev)); s = y
    prev = y
bands.append((s, prev))          # 标题带 / 导航带 各是一段

# ② 带内按列聚类成文字块
def blocks(y0, y1, thr, gap, minw):
    band = lum[y0:y1+1]
    on = (band > thr).sum(axis=0) > 0
    out, s, last = [], None, None
    for i, v in enumerate(on):
        if v:
            s = i if s is None else s
            last = i
        elif s is not None and i - last > gap:
            if last - s >= minw: out.append((s, last))
            s = None
    if s is not None and last - s >= minw: out.append((s, last))
    return out
```

要点：
- **`gap` 是最关键参数**：中文标签之间的间距比字内间距大得多。`gap` 给小了会把一个词切成几块，给大了会把相邻导航项并成一块。按实测，导航项间 `gap≈32`、标题 `gap≈26` 好用。
- **阈值要按图调**：亮字 `thr=170`；背景被压暗的弹窗图降到 `100`；**整条表头都被压暗的页要降到 `55–70`**（实测有的页标题亮度只有 66–79，而正常页 200+）。这类页的标题热区照样能点，但**视觉上几乎看不见**——交付时要主动告诉用户「这页回首页的位置不明显」，别让他演示时找不到。
- 🚨 **浅底页要把判据整个反过来**。先看 `np.median(lum)`：中位数 > 150 就是浅底页（实测 GIS/网页类截图背景中位 251），此时 `lum > 170` 会命中整屏，行带扫描出来就是「一块，1920 宽」。浅底页改写 **`lum < 190`** 去找压在浅底上的深色按钮/文字块，行带与列聚类同样取反。深浅底混用一套阈值，结果必定是「全屏一个块」或「什么都没找到」。
- **标题位置跨图往往一致，先测一张定常量、再抽查其余**：同批截图若同一模板产出，品牌标题框几乎逐像素相同（实测五张 2276×1280 的图，标题都在 `x 948–1545 / y 25–60`）。定一个 `TITLE_PX` 常量给所有屏复用，省掉逐图测量；但**新批次必须抽查**，换过模板的图会漂。
- **块的平均色能判高亮，但判据不是固定色相**。多数大屏把选中态做成金色（R>G>B 且 R−B>70），但并列的「视图切换胶囊按钮」不是——选中态只是同一色系**更亮**（实测选中 `RGB(143,212,241)`、未选中 `RGB(201,209,224)`，都偏冷）。通用判据是**该块均色亮度/饱和度明显高于同排其他块**，选色阈值只能当先验，不能当规则。
- **文字块宽度不等于按钮外框**。块宽明显小于标签字数应有的宽度时（2 字块只有 36px、5 字块 91px 是正常的，3 字块 52px 就偏窄），用**相邻块中心距反推按钮节距**（实测五个导航项中心距稳定在 ~175px），再按 `中心 ± 节距/2` 划热区，比「文字宽 + 固定 padding」稳。
- **纵向同理，必须取按钮外框而不是文字行**。文字在按钮里垂直居中，照文字带画的框会整体偏上：实测一页把导航按钮 y 定成 `76–112`，实际外框是 `84–132`——粉框骑在按钮上沿，下半截点不到，而 Playwright 点元素中心照样跳转成功，**断言全绿也发现不了**（只有第四节的可视对齐复核能抓到）。做法：在已定好的 x 区间内，用「该行暗于背景的像素数 > 5」扫出**连续行段**，取整段；不要取文字最亮的那几行。
- 探测完**用一张放大裁图 + vision 复核文字内容**（只复核「写的什么字」，不复核坐标）。两块证据分开取：像素给坐标，vision 给语义。
- 🚨 **vision 还会凭空造出元素**，不只是坐标偏。它会报告「这里有个『详细列表』标签」「右上角有个 × 关闭按钮」，而图上根本没有；也会把「数据编目」读成「数据追目」。所以**「这个按钮存不存在」只能由像素证据回答**：别因为 vision 说有就去给不存在的元素配热区（配了就是隐形误点，演示时点空）。
  但**反向推不成立：一次亮字扫描扫不到，不等于没有**。实测一行浅蓝小字标签亮度只有 55–80（同页标题 200+），按 `thr>110` 扫那片区域是全空的，据此两次回复用户「页面上没有这段文字」，直到把裁图**提亮 2.4–3.0 倍 + 对比 1.8–2.2 倍**才看见（内容是同一行两个标签、竖线分隔）。
  **判「不存在」前必须补一轮**：多阈值（150 / 110 / 70 / 55）扫描 + 提亮加对比的裁图目视。浅色、低饱和的小标签是大屏里最常见的「看不见但真在」的元素，也是这类活儿最容易向用户误报的一次。
- **堆叠卡片用「节距一致性」反证**：同栏三张卡片的标题带实测落在 `y 368 / 612 / 856`，节距精确 244px——等距本身就是「我找对了标题带」的证据；节距忽大忽小说明混进了指标行或装饰条。判据看行均值亮度剖面：**标题条 ≈70–80，下方指标行 ≈90–115**，一「中亮带 + 三亮行」为一组，周期即卡片节距。
- **粗定位时给 vision 加坐标网格**：裁图放大 2 倍后，在左缘和上缘画红色刻度线、用黄字标出原图坐标（每 40–100px 一格）。这样 vision 报「大约 y 420–460」是可信的粗区间，再拿亮度剖面精修到像素。不加网格时它报的百分比会整体偏一两百像素。

最后把像素框留出点击余量（导航左右各 +45px、上下到按钮框边界），再换算成百分比：

```python
def pct(x0, y0, x1, y1, w, h):        # w/h 必须是【该图自己的】尺寸
    return (round(x0/w*100,3), round(y0/h*100,3),
            round((x1-x0)/w*100,3), round((y1-y0)/h*100,3))
```

百分比坐标的好处：换分辨率、换投屏尺寸都不用重标。

⚠️ **`w/h` 不能全局取一个常量**：同一批图的尺寸可能不一致（实测六张里五张 2276×1280、一张 2466×1280）。拿错基准算出的百分比，在图上就是整体偏移或错位，而且不会报错。每屏自己的 `w/h` 跟热区一起登记进屏定义表。

## 五、🚨 屏级热区隔离（不做必出隐形误点）

热区默认是全局浮层。若不加隔离，**A 屏的热区会在 B 屏继续生效**——B 屏那块区域是空白背景，用户点一下却跳走了，且没有任何视觉反馈，最难查。

典型场景：弹窗页/无导航页上，前一屏的导航热区仍然可点。

写法：热区带 `data-scr`，`go()` 里只激活当前屏那批。

```css
.hot{pointer-events:none;opacity:0}
.hot.act{pointer-events:auto;opacity:1}
```
```js
[].forEach.call(document.querySelectorAll('.hot'), function(a){
  var mine = a.getAttribute('data-scr') === id;
  a.classList.toggle('act', mine);
  a.classList.toggle('cur', mine && a.getAttribute('data-target') === id);
});
```

另外三条小规则：
- **当前页对应的导航项不显示悬停提示**（`.hot.cur .tip{display:none}`），否则提示文字与按钮上的字重复，看着像 bug。
- **互为切换的两个按钮必须双向接线**：同一模块下「A 视图 / B 视图」这类并列胶囊按钮（如「户籍人口分析」/「人口流动分析」）会在两屏上各出现一次，**两边都要配热区**。只做单向时，演示中从 B 想切回 A 会卡住，只能 ESC 回首页再点进来——领导现场来回切是常态。
- **平级按钮全部接线，只跳过「自己」那一个**：用户说「这几个按钮是一级的」时，同一排的 `数据赋能 / 自然人 / 法人 / 空间地理库 / 电子证照` 互为兄弟，凡是有目标图的都要接，**唯独当前页自己那个不接**（点了原地不动，用户会以为坏了）。没图的兄弟先留空，并在汇报里点名「这几个还没图」。
- **目标页还没到手就先别接入口**：屏定义表里指向不存在的屏会生成死链。分两次做——图到了先建屏，再补上一屏的入口。
- 悬停高亮包在 `@media (hover:hover) and (pointer:fine)` 里，并提供 `H` 一键全关——有的领导不喜欢图上多出东西。

### 返回（× / 「返回」）用导航栈，别写死目标页

用户说「所有页面右上角有 × 的都设成返回」时，× 的语义是**回到进来时那一页**，不是某个固定屏：从数据汇聚进汇聚更新 → 回数据汇聚；从数据编目进汇聚更新 → 应回数据编目。写死 `data-target="sjhj"` 后者就错了。

`go()` 若用 `history.replaceState` 写 hash，浏览器历史里就没有记录，`history.back()` 也回不去。自己维护一个栈：

```js
var stack=[];
function go(id, isBack){
  if(!isBack && cur && cur!==id && stack[stack.length-1]!==cur) stack.push(cur);
  /* …切屏… */
}
function back(fb){
  var prev=stack.pop();
  if(prev && NAMES[prev] && prev!==cur) go(prev,true);
  else go((fb && NAMES[fb]) ? fb : 'home', true);   // 兜底：直开弹层页时没有历史
}
```

热区写成 `data-back="1" data-fallback="<父屏>"`，点击走 `back()`；`data-fallback` 保证「用 hash 直接打开弹层页」也不会卡住。验证必须覆盖两条：**有来路的回退**（A→弹层→×→A）与**无来路的兜底**（新开页面直落弹层→×→父屏）。

### 顺序翻页链用叠加箭头

一组「按图片顺序往下翻」的页（GIS 图集这类）图上没有翻页钮，**可以叠一层箭头**（用户会明确授权「此处可以添加向下和返回箭头」）。

- 箭头写在**该屏 section 内部**：屏级隔离（`visibility:hidden`）自动让它在别的屏失效，不用额外接线。
- **首屏不放 ▲、末屏不放 ▼**，别让用户翻出边界。
- 箭头 **idle 半透明（`opacity:.55`）、hover 才实显**。实测不透明圆钮会压住 GIS 右侧的图例/统计数字；半透明既挡不住阅读又找得到。
- 补 `@media (hover:none){.arw{opacity:.85}}`，兜住触屏和投屏（没有 hover 时永远半透明就找不到了）。
- 链长 N 的验证要**点 N 次**才回到链首：`for i in range(N)` 少写一次会报「逐级返回失败」，那是假 bug（本次就这么误判过）。

## 六、交付：单文件 HTML，默认不问启动包

这类产物**默认就是单文件自包含 HTML**：图片 base64 内嵌、CSS/JS 全内联、零外链，Windows 与 macOS 双击都能开。用户明确要过「不要启动包形式，两个系统都能展示」。

- **不要主动提议启动包 / 本地服务**，除非图多到单文件过大（实测 3 张 2276×1280 JPEG ≈ 970 KB，完全可接受；按每张约 200KB base64 估算）。
- 同一张图被多个占位屏复用时，**用 CSS 类共享一份 base64**，不要 `<img>` 复制多份（否则文件按屏数翻倍）。
- 🚨 **占位兜底样式要按「是否真缺图」条件生成**。实测所有屏都有图时，兜底逻辑仍默认取第一张真图塞进 `.ph` 类，那份 base64 于是被写了两遍，白占 230KB。写法：`fb = next((v for v in imgs.values() if v), None) if missing else None`。构建后**断言唯一 base64 块数 == 屏数**（把每块 base64 取 `md5` 去重比对），出现重复就是这里漏了。
- 🚨 **画幅要逐屏跟随该图自己的宽高比，不要全局锁 16:9。** 同批图尺寸未必一致（实测五张 2276×1280 + 一张 2466×1280）；锁死 16:9 会让宽图左右出黑边，更糟的是热区百分比按错误基准换算、整屏错位。做法：每屏登记 `w/h`，`go()` 里同步设 `frame.style.aspectRatio`，`fit()` 用 `RATIOS[cur]` 按视口重算宽高。
  只有「所有图尺寸完全一致」才可以直接锁一个比例。`object-fit:contain` 只当兜底，不能替代按各图自身尺寸换算热区。
- 缺图的页给**占位屏**：复用现有图压暗 + 居中标签「页面图片待补」。占位屏的热区照样能点，导航不中断。

## 七、验证断言清单（真 Chrome，全部真点击）

`skill` 的 `scripts/verify_proto_chrome.py` 可作骨架。这类原型必须断言：

- 无 JS 报错；热区总数与设计一致
- **每屏生效热区数正确**（首页只有 N 个导航，弹窗页只有标题+关闭）
- **非当前屏的热区 `pointer-events === 'none'`**（隔离生效）
- 逐个真点击：首页每个导航 → 目标屏；二级屏点标题 → 首页；弹窗页点 × → 返回
- 键盘：ESC 回首页、← → 翻页、`H` 切提示
- 地址栏 `#hash` 直达
- **三张图逐屏核对图片未被改动**：
  ```js
  const i = document.querySelector('#scr-X img.shot'), s = getComputedStyle(i);
  return {nat: i.naturalWidth+'x'+i.naturalHeight, filter: s.filter,
          opacity: s.opacity, transform: s.transform};
  // 期望 filter:none, opacity:1, transform:none, nat 等于原图尺寸
  ```
- **画幅跟随当前屏**：在宽图屏与 16:9 屏之间来回切，断言 `frame` 的 `width/height` 分别接近该图自身比例（实测 1.778 ↔ 1.927），切回首页要恢复。
- 🚨 **「点得通」不等于「热区压对了」**。Playwright 点的是元素中心，热区整体偏移几十像素照样跳转成功、断言全绿。必须另做一次**可视对齐复核**：把当前屏的 `.hot.act` 临时改成可见
  ```js
  document.querySelectorAll('.hot.act').forEach(h=>{
    h.style.border='3px solid #ff0055'; h.style.background='rgba(255,0,85,.22)';
    h.style.opacity='1'; h.style.pointerEvents='auto';
  ```

## 八、常见坑

- **图上有导航、别的图上没有** —— 不同截图的顶栏可能根本不是一套（一个是四项一级导航、一个是主题库子导航、一个是无导航的弹窗页）。**不要假设跨图热区通用**，每屏单独探测、单独配热区表。
- **同一批、同一风格的图里导航项数也会不同** —— 实测同为 GIS 页，入口页只有「自然人 / 法人 / 空间地理库」三项（外框 `x 689–1276`），其余页是五项。**「跟上一页一样的坐标」是错的假设**，每个新页的导航列都要重测；沿用上一页坐标的结果是热区错位到相邻按钮上，而且会串页。
- **拿不到导航的屏只能给已有入口** —— 图上没有的按钮不能凭空画（等于改图）。这类屏只能靠「点标题回首页」+ 上一屏的导航进入，落地时要向用户说明「这页上能点到哪、哪些是装饰」。
- **不要把后期阶段能力写进当期的任务/说明** —— 若大屏要挂在分期指标上，早期页面只承诺当期交付物，后期能力写「为后续……预留支撑」。
- **`sed -i` 改验证脚本的键名** —— 自己写的断言若报 `KeyError`，先看 JS 返回对象的键名与 Python 取的键是否一致，别急着怀疑产物。
- **heredoc 里取 shell 变量**：写 `python3 - <<'PY'`（引号版）时变量不展开，Python 里裸写 `pills(ZR, ...)` 会直接 `NameError`。二选一：`export ZR=...` + `os.environ['ZR']`，或不加引号的 `<<PY` 但在 **Python 字符串里**写 `"$ZR"`。别把 shell 变量名当 Python 变量用。
- **弹层 × 的坐标不能跨弹层复用**：同一个底层页面上弹出的几个弹层高度不同，× 的 y 也不同（实测同页三个弹层分别是 `y 184–218 / 265–301 / 233–269`）。每个弹层单独量，套用上一个必点空。
- 🚨 **一批图同时到达时用 mtime 还原发送顺序**。微信一次发 7 张会用同一分钟落盘，文件名是哈希、不含先后。用 `find <dir> -newermt '-25 minutes' \( -iname '*.jpg' -o -iname '*.png' \) -printf '%T@ %s %p\n' | sort -n` 取毫秒时间戳排序，再按序重命名 `p14_g1..g7`。**排完要连着每张一句话内容一起报给用户**，并明说「顺序不对告诉我编号就调」——顺序错了画面上看不出来，但演示时会跳戏。
- 🚨 **同一批图可能连风格都不是一套，要主动预警**。实测一个工程里混了深蓝大屏（2276×1280，16:9）和浅底 GIS 网页截图（1920×880，2.16:1）；画幅逻辑能撑住不变形，但切过去会上下出黑边、画面明显「矮一截」，视觉割裂很强。**交付说明必须点出这一条**，并给两个选项：让出图方按统一尺寸重导，或把这批页单独拆一个文件。别默认用户知道。
- **验证脚本自身两个必踩坑（长得像产品 bug，先怀疑测试）**：
  ① **状态残留** —— 上一个用例把页面停在某屏后直接点首页热区，Playwright 报 `TimeoutError: … <section id="scr-XXX" class="screen on"> intercepts pointer events`。每个阶段开头先 `go(pg,'home')`。
  ② **循环次数差一** —— 见上「链长 N 要点 N 次」。修正后要连同路径序列一起断言（`back == [p6,p5,…,p1,入口]`），只断终点会漏掉中间错序。
