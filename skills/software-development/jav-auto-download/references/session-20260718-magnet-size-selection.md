# 2026-07-18 会话：磁链大小选择教训 + -U 禁止规则

## 问题

用户连续下载了 FNS-216 (1.8GB)、DSOD-018 (1.5GB)、SNOS-324 (1.5GB) 三个番号，全都太小（<2GB），清晰度差。用户要求全部重下高清版。

## 根因

从 javdb 选磁链时，没有看页面上标注的文件大小。javdb 每个磁链后面直接写着文件大小（如 `1.50GB` vs `4.83GB`），但我选了最小的版本。

## 正确的磁链选择方法

用 curl+grep 提取页面上的磁链和属性：

```bash
curl -s --proxy http://127.0.0.1:10808 \
  -H "User-Agent: Mozilla/5.0" \
  "https://javdb.com/v/VIDEO_CODE" | grep -oP '(magnet:[^"&]+[^"]*|[0-9]+\.[0-9]+ *GB|中字|字幕|无码|破解|HD|高清)' | head -60
```

输出示例（DSOD-018）：
```
字幕
无码
magnet:?xt=urn:btih:8d851558...&dn=[javdb.com]DSOD-018
8.71GB                  ← 标注的大小
高清
...
magnet:?xt=urn:btih:8a70cc2d...&dn=[javdb.com]DSOD-018
1.46GB                  ← 第一次选的太小版
```

关联方法：grep 输出按行顺序排列，磁链 URL 和大小交替出现。通过看 `dn=` 参数里的文件名区分哪个磁链对应哪个大小。

## 用户新增规则（2026-07-18）

1. **禁止 `-U`（无码破解版）**：文件名含 `-U` 的磁链一律不选。注意 `-UC` 是允许的（`U`=无码，`C`=字幕，`-UC`=无码中字版）
2. **<2GB 不下载**：视频必须大于等于 2GB
3. **选前看大小**：从 javdb 页面直接读标注，不猜
