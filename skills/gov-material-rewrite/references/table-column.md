# 表格单列批量规范化

适用：用户发来 xlsx，某一列（如「错误描述」）技术黑话太重，要改写成给领导看的规范表述。

## 第 0 步：目标列已有样例行时，先复现样例再批量

用户常亲手在目标列写几行样例，让你照着往下续。这时**样例的风格压倒本 skill 的默认句式**，不要套用后面的 10 类表述词。

1. 读出样例的 `{原列 → 目标列}` 对照，反推模板。典型：`mq_xm 母亲姓名：56 条数据为空` → `母亲姓名字段存在56条数据为空`，模板是 `{中文字段名}字段存在{N}条数据{问题}`——保留原始数据量、去掉英文名、去掉冒号结构。
2. **先写断言逐条复现样例，全部一致再量产**：`assert rewrite(d) == e`。有一条不一致就回去改规则，不要带着偏差往下跑。
3. 样例行不动，从最后一条样例的下一行开始写。
4. 「目标列有内容」不等于「整列都是样例」，先确认几行、哪几行（`[r for r in rows if cell(r, COL)]`），别无脑整列覆盖。

样例驱动时问题类型的措辞跟着样例走：样例写「存在数据为空」就用「存在数据为空」，不要自作主张换成「信息缺失」。

数据量在几百行、去重后一百多串时，规则引擎 + 十几条 override 就够，不必上模型——模型批改这种表反而更贵更难复核。

## 第 1 步：先量化，再决定用什么手段

**不要一上来就调模型逐条改。** 先算三个比例：

```python
import collections
rows = [...]                      # 非空数据行
g = [str(r[COL]).strip() for r in rows if r[COL]]
print('去重写法数', len(set(g)) / len(g))     # 越接近 0 越模板化
print('高频前 30 覆盖', sum(c for _, c in collections.Counter(g).most_common(30)) / len(g))
```

判读：

- 高频前 30 覆盖 > 50% → **模板批量生成**，走规则引擎，几秒跑完、结果稳定可复核。
- 长尾占比 < 30% → 长尾单独处理。
- 中文定位信息（表中文名/字段中文名/括号内中文）覆盖率 > 80% → 规则引擎能给出高质量表述。

## 第 2 步：规则引擎三要素

**① 拆出「业务对象 + 问题类型」。** 多数描述是 `{字段标识}{问题短语}` 的拼接，先剥标识再匹配问题类型。

问题类型收敛到 10 类，同类同措辞：

| 关键词 | 规范表述 |
|---|---|
| 为空/空值/空字符串/未填报/无数据 | 信息缺失 |
| 包含特殊字符/特殊符号 | 含有非法字符 |
| 校验位 | 校验位有误 |
| 不规范/不合规/格式混乱/正则/编码规则 | 格式不规范 |
| 不在规定时间内/不是有效值/超出范围 | 取值超出有效范围 |
| 不能全为0/全为同一/重复/解密后 | 取值不符合规定 |
| 长度小于/大于/等于/不足 | 内容长度不符合要求 |
| 不匹配/不一致/不唯一 | 关联信息不一致 |
| 大于/小于/早于/晚于 | 数值逻辑关系有误 |
| 无码表/未找到码值/数据字典/不符合枚举值 | 缺少对应标准代码表 |

**② 业务对象必须有名词性校验。** 这是质量分水岭，不做就全是病句。

```python
BAD_OBJ = re.compile(r'(是否|能否|可否|请问|请|建议|需要|应该|必须|可以|无法|不正常|正常|'
                     r'补齐|增补|确认|核实|处理|置空|删除|提供|反馈|治理|修改|转换|转码|'
                     r'该|此|其|或|和|及|全部|大量|部分|以下|如下|其中|'
                     r'率|个|条|的|中|信息|数据|字段|问题|情况|原因|说明|方式|方法|结果|'
                     r'存在|包含|不|未|不能|没有|无)')
```

对象长度限 2–16 字。**不要把「内容」放进黑名单**——「诉求内容」「许可内容」「经营范围」是完整名词，剥掉会产出「诉求数据不符合规范要求」这种残句。

**③ 对象来源按可靠性排序**：字段中文名列 → 原文括号内中文 → 原文中文名词片段（先剥噪声词再切，否则「姓名字段内容」被整体判废）→ 拼音缩写固定释义表（只收能 100% 确定的，如 `c_lxdh`=联系电话；不确定的宁可退回「该字段」）→ 表中文名。

**④ 技术标识退到括号里**：`联系电话格式不规范（c_lxdh）`。不要删——它是定位依据。同时清掉对象里的纯码号括号，如 `统一社会信用代码(ca91)` → `统一社会信用代码`。

SQL 片段识别：`SQL_TOKENS = {select,count,where,from,and,or,sum,max,min,case,when,then,else,end,null,not,is,as,length,group,order,by,distinct}`。**不要用「字母数 ≤3 就判 SQL」这条规则**，它会把 `org_code`（`or` 前缀）、`qlr`、`xm` 这类真实字段名一起误杀。

**⑤ 括号里写哪个标识：先滤噪声，再「字段优先于表」。** 用户追加「技术字段或表名称也写上」时，括号内容同样是质量的一部分，**过松和过严都会错**。

要滤掉的（都是单元格里的取值/码号，不是字段名）：

```python
NOISE = {'test','none','ceshi','abc','null','oracle','sql','clob','true','false','varchar','number','date'}
if low in SQL_TOKENS or low in NOISE:                               continue   # 测试值、SQL 片段
if re.search(r'\.(CLOB|VARCHAR|NUMBER|DATE)$', x, re.I):             continue   # oracle.sql.CLOB@36fc9796
if re.fullmatch(r'[A-Z]{2}\d{2}', x):                                continue   # CA26 这类标准码号
if re.fullmatch(r'[0-9a-f]{6,}', low) and x not in FIELD_CN:         continue   # fc9796 十六进制残留
```

**但不要滤波过头** —— 下面三类是真实字段名，误杀后输出就只剩「该字段」：

- 两字母字段名（`tw` 体温、`zs` 住址、`sjh` 手机号）。长度闸写成 `len(x) < 2` 才跳过；两字母的若在 `FIELD_CN` 里就保留。
- 全大写字段名（`YHZGX` 银行账号）。**不要写「全大写即行业码」**，只让 `^[A-Z]{2}\d{2}$` 这种带数字的码号命中。
- 带点号的表路径（`swsjkw.swsjkw_cffm`）。同行还有字段名时优先字段名，只剩表路径时才用它。

取几个：单字段写一个；对比类（A 小于 B、A 与 B 不一致）两个都写 `（opto/opfrom）`；上限两个，多了读者抓不住。

**行内根本没有技术标识时（如「整表规则：…重复数据检测」），不要硬编一个字段名。** 留空并在交付说明里点名是哪几行、请用户补表名——编出来的标识比没有更糟，技术同事会照着去查一个不存在的字段。

**用户中途追加「要把技术名写上」时，上一版按「样例行不动」保留下来的那几行要不要同步改，必须显式决定并说明。** 做法：改（否则整列格式不统一），但只在末尾追加 `（标识）`、原措辞一字不动，交付说明里写清改了哪几行，并附一句「要恢复原样说一声」。样例措辞是用户逐字认过的东西，静默改动比不改更糟。

## 第 3 步：分层自检，如实汇报

```python
fallback = [x for x in res if x['new'].startswith('该字段')]          # 连对象都提不出
vague    = [x for x in res if '数据不符合规范要求' in x['new']]        # 只能给空话
bad      = [x for x in res if re.search(r'(是否|能否|请问|补齐|置空|确认|反馈|治理)', x['new'])]
dup      = [x for x in res if re.search(r'(.{2,6})\1', x['new'])]      # 对象+问题词双重拼接
trail_en = [x for x in res if re.search(r'[A-Za-z]{3,}', x['new'])]    # 英文标识没清掉
mobj     = [x for x in res if 're.Match' in x['new']]                  # re.search 忘取 group
```

`dup` 这条专抓双重拼接型病句（`姓名字段包含特殊字符字段含有特殊字符`），靠眼看 300 行里挑不出来，必须用正则跑。`mobj` 抓的是把 Match 对象直接拼进字符串——输出里会出现 `<re.Match object; span=(39, 45), ...>` 直接写进单元格。

三项指标必须分开报。**「病句 0 条」和「兜底占比」是两件事**：病句为 0 只能说明句式合格，不代表表述有信息量。

典型分布（可作预期基线）：规则引擎能到自动处理 77%、需人工 23%（其中一半连业务对象都提不出）。

## 第 4 步：交付方式

- **新增一列，不覆盖原列。** 用户明确要求过在原列后插入新列（表头写「XX（规范表述）」），原列及右侧列整体右移，格式列宽尽量保留，行数与其他列不动。
- 先给 **20 条左右样例**（含强项与弱项各若干），认可风格后再批量落表。
- 长尾（疑问句、多问题混述、带 SQL 的）建议**筛成子表交业务方**——原文含糊的东西模型再改也是猜，谁提的问题谁改最准。

## 陷阱

- **位置索引取错字段导致全部指标作废**：`res = [(r,) + extract(...) for r in rows]` 之后 `x[3]` 取到的是技术标识而非新表述，于是「兜底 0 条 / 病句 0 条」全是假的。改用 dict（`{'row': r, 'new': ..., 'issue': ..., 'ident': ...}`）或命名元组，并在打印任何指标前先打印一行样例核对索引。
- **先批量后确认**：4800 行的表改完一大片才发现风格不对，返工成本极高。
- **只报「病句 0」不报兜底占比**：会让用户以为全量可用，实际近四分之一是空话。
- **问题词表里塞太长的问题短语，会把字段名一起剥掉**：把 `身份证不合规` 整条放进噪声词表，`zjh身份证不合规` 剥完就剩空串，直接掉进「该字段」兜底。噪声词表只收**纯问题词**（不合规/为空/校验位/特殊字符/长度小于/不能全为0），绝不收 `{字段名词}{问题词}` 这种组合。
- **字段词典命中但原文名只是词典名的前缀时，要用词典全称**：`opto 经营(驻在)期限至` 只能抓到「经营」，规则应是「原文名是词典全称的前缀 → 用词典全称」，否则输出 `经营字段数值逻辑关系不符合要求`。
- **人工兜底（override）的键必须忽略空白匹配**：Excel 单元格内的换行会在读出来时变成空白，原样拼出的键永远匹配不上。查表用 `re.sub(r'\s+', '', d)` 归一化后再比。
- **openpyxl 的 `max_row` 可能虚高**：声明一百万行、真实数据只有几百行是常见情况。遍历前先扫出真实最后一行（`max(r for r in ... if any(cell(r,c).value))`），否则白跑百万次空循环。
- **字段中文名要靠表内互证，不要凭字段名猜**：同一字段在别的行若带中文（`name姓名字段为空` → `name` 即姓名），据此建映射是可靠证据；表内找不到中文、只能按字段含义补的那些（`deformlevel`→残情等级），交付时要单独说明并请用户拿内部字段字典核对替换——用户会追问「这是你总结的吗」。
- **按分号拆多问题时，拆分出来的纯数值/纯符号碎片必须丢掉**：`字段存在全部为同一数字的数据，例如：；1111，22，该情况是否正常` 按 `；` 切会把示例值切出一段尾巴。拆完先过滤一遍——不含中文也不含标识的碎片直接扔：
  ```python
  parts = [p for p in re.split(r'[；;]', d) if p.strip()]
  parts = [p for p in parts if re.search(r'[\u4e00-\u9fa5]{2,}|[A-Za-z_]{3,}', p)]
  ```
  否则尾部碎片会继承同一个对象名，产出「资质资格证书2字段1111，22」这种垃圾。
- **多问题分段时，业务对象要能继承上一段**：`出生孕周：214018条数据为空；69461条数据出生孕周不在20周和45周范围` 的第二段既无标识也可能抽不准对象。在分段循环里把上一段定下的对象带下去作为 fallback，并在抽对象前先判「本段是否包含 fallback 对象名，包含就直接沿用」。
- **对象名会被整串词重复一次，要折叠**：`吊销日期日期` 这类原文自带重复，拼出来后是「吊销日期日期不合理数据字段…」。收尾统一折一遍：
  ```python
  text = re.sub(r'([\u4e00-\u9fa5]{2,4})\1+', r'\1', text)
  ```
