# 解说词 / 讲解稿的精简改写

适用：大屏解说词、述标脚本、汇报讲解稿。用户给出原稿并嫌「内容太多」「太技术」，要求按固定屏幕顺序精简重写。

## 第 0 步：读清原稿的真实结构

先数清三件事再动笔：总字数、章节数（H1 级）、画面切换提示数（`（切换至…）`/`（点击…）`）。

**屏幕数按画面切分，不按章节切分。** 一个 H1 章节里可能含 8 个画面（如「数据治理大屏」含总览+归集库详情+清洗库详情+治理仓+三个基础库+主题库）。按章节给字数预算必然算错。

若用户说「每张屏 2 分钟」，先确认「屏」指的是画面还是章节——两者字数差 3 倍以上。把两种口径的后果都摆出来让用户选，不要自己假设。

## 第 1 步：定字数口径并报给用户

```
主要屏上限 450 字（约 2.0 分钟）
次要屏上限 350 字
折算基准 220 字/分钟（用户口径：5 分钟发言≈1150 字）
```

先报口径再写，一次问完：xx 是否带单位、能否使用定位性提法、主次屏如何划分。

## 第 2 步：逐屏改写，保持段落一一对应

原稿一段 → 新稿一段。合并只允许发生在同屏、同话题的相邻段落。章节标题、`（切换至…）`舞台提示原样保留。

拔高格局只做四件事，且都不改变叙述顺序：

1. 在原有首句之后补一句立意（不是另起一段）。
2. 把功能描述翻成「这项改革的实质是什么」。
3. 用「过去怎么办、现在怎么办」的对照撑层次。
4. 收尾落到治理能力、营商环境、企业群众的实际获得感。

## 第 3 步：三项脚本自检

```python
# 1) 字数必须脚本计量
n = len(text.replace(' ', ''))
assert n <= (450 if kind == '主要屏' else 350)

# 2) 原稿真实数字集合不得有差集（排除 xx 占位）
import re
def nums(t):
    t2 = re.sub(r'[xX]{1,4}', ' ', t)
    return set(m.group() for m in re.finditer(r'\d+(?:\.\d+)?%?', t2))
lost = nums(orig) - nums(new)
assert not lost, lost

# 3) 禁用提法
BAN = ['全国率先', '全国第一', '西部第一', '领先全国', '走在全国前列', '首个']
assert not [w for w in BAN if w in new]
```

数字校验会报出几类**误报**，判读时别被吓到：

- `xx TB` 中间有空格，正则里的单位类要允许空格前缀。
- `x至x年` 是区间写法，不是缺单位。
- 原稿里 `T0P10` 这类错别字会贡献一个孤立 `0`，先 `replace('T0P10','TOP10')` 再取集合。
- `唯一性` 是数据质量「六性」的规则名，不是定位性提法。

## 第 4 步：交付

- 正文 docx：公文格式，标题方正小标宋/黑体，正文仿宋_GB2312，页脚 `— 页码 —`。用 `docx` skill 的 `cn_docx.py`，它会把 `w:ascii/w:hAnsi/w:eastAsia/w:cs` 一起写，中文字体才真生效。
- 对照表 docx：每屏一行，列为「屏号与屏名 / 原字数 / 新字数 / 增减 / 主要改动」。
- 单独一节「请你确认」：被删掉的内容逐条列出（哪怕只是 61 字的通用收尾），以及总时长是否仍需削减。

## 时段与总时长的诚实汇报

每屏都压到 2 分钟以内之后，总时长仍然可能是 25–30 分钟。**这时不要承诺「已经够短了」**，要明确说：再压字已无意义，只能砍屏，并给出建议砍哪几屏（通常是数据不完整、只能讲全省数据的那种弱屏）。
