## 落选方向保留意见

- **B** 的空间定位交互本身有效，但实测暴露了大量渲染兼容问题（见下），且其"关系图"主张对"查找某个具体目录"这一主任务帮助有限。B 的代码保留在 `B_图谱.html`，若将来要做「数据资源关联分析」视图可复用。
- **C** 的命令式检索交互对高频用户效率最高，但**假设使用者已经知道要什么**，不满足"首次进入需要浏览了解有什么"的场景。

## 这个方向的主张（后续所有屏都必须守住）

1. **把数据资源当"档案台账"编**，读起来像省级年鉴/统计公报的内页，不是 SaaS 后台。
2. **秩序由 1px 细线与字重承担** —— 零圆角、零阴影、零渐变、零图标、零 emoji。
3. **全册只有一种彩色：朱红**，且只用于需要被看见的例外（待审核、不予共享、驳回、需另行审批）。
4. **逐行读的信息节奏** —— 一屏一表，信息密度高，不靠卡片堆叠。
5. 字体：display 用**宋体系**（中文排版正统），正文用黑体栈；禁用 Inter/Roboto/Arial 作 display。

## 反 AI slop 自查（huashu §6.2）

## 已发现并修复的渲染陷阱（技能已固化）

3 个方向的自查中共发现 10 类**静默**失效：按钮 `width:auto` 被撑满、`<input>` 完全不渲染、SVG 文字 CSS `font-size` 失效、`@page` 不指定则按 A4 重排、grid 显式列放置丢子项、`inset`/`min()`/`display:contents` 不被支持、`box-shadow` 用带 alpha 的 oklch 直接抛异常、flex 的 `margin-left:auto` 不可靠、`flex:1 + overflow-y:auto` 不收敛。

完整清单 + 唯一有效解 + 6 条量化验证法：`ui-prototype` skill 的 `references/weasyprint-static-render-traps.md`。

## 验收基线（每改一次都要重跑）

1. jsdom 无头功能测试全绿
2. 文字重叠 = 0（bbox 相交面积量化）
3. 关键短语全部存在（grep）
4. 页数 = 1
5. `pdf page.rect` = 目标 CSS px × 0.75
6. 视觉终检（vision，用具体问题问）
