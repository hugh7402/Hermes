如果你使用过 CoCo（Snowflake 的智能体 AI 助手，原名 Cortex Code），那么你可能已经创建过一两个 SKILL.md 文件。这类文件就像一份可复用的操作指南，能够教会智能体如何完成特定且可重复的任务，例如核对 Snowflake 成本报告，或生成每周高管业务指标摘要。然而，一直以来，维护这些技能并将其分享给更广泛的团队都相当繁琐。如今，这一情况终于有了改变。

Snowflake 最近通过推出技能与插件共享功能，填补了这一空白。这项目前处于预览阶段的功能，可以将本地技能转化为账户范围内可共享、可治理、支持版本管理的对象，其底层依托一种名为 Cortex Extension（Cortex 扩展）的原生 SQL 对象。用户可以通过链接分享技能，浏览其他人共享的技能目录；如果拥有管理员权限，还可以对优质技能进行认证，使其显示可信认证标识。

本文将介绍技能的完整生命周期：如何编写、共享、发现和认证技能，并展示每一步背后实际执行的 SQL 代码。这样，你不仅可以了解整个过程的运作机制，还可以根据需要自行编写脚本实现这些操作。

什么是技能（Skill）和插件（Plugin）

技能是一份采用 Markdown 格式编写的操作指南，即 SKILL.md 文件。文件开头包含简短的元数据说明，例如名称、描述以及触发 CoCo 加载该技能的条件，正文则逐步指导智能体完成特定工作流程。创建技能不需要编写代码，但技能可以引用需要 CoCo 执行的脚本。

CoCo 内置了大量技能，涵盖数据治理审计、动态表故障排查、成本分析，以及 Cortex Agent 配置等场景。这些技能由 Snowflake 编写和维护，随产品进行版本管理，并自动提供给所有用户。

本文真正关注的是用户自行创建的技能。这些技能只有在用户编写后才会存在。与内置技能不同，它们需要一种有效的分发机制。

那么，什么样的任务适合封装为用户自定义技能？可以参考以下几个判断标准：

你已经重复执行过两次以上。 例如，诊断计算资源消耗突然增长的原因、排查停滞的动态表数据处理管道，或核对月度资源消耗报告。只要某项任务具有足够的重复性，甚至已经让你在脑海中形成了一套固定处理流程，就值得考虑将其封装为技能；

执行过程需要判断，而不只是运行一条查询。 如果任务完全可以通过固定的 SQL 查询完成，那么保存的工作表或视图就足以胜任。技能真正发挥价值的场景，是工作流程中存在条件分支，例如“如果出现 X，就继续检查 Y；如果 Y 没有问题，再检查 Z”。这类流程通常需要你向新员工解释具体的判断逻辑；

它能够沉淀团队内部的隐性知识。 例如，团队采用的命名规范、哪个仪表板才是权威数据来源，或记录在便签上的业务规则。这些知识目前可能只存在于某个人的脑海中，或者散落在一段日后难以查找的 Slack 对话里。

插件是新版“技能与插件目录”（Skills & Plugins Catalog）支持的另一种对象类型。

.cortex-plugin/plugin.json

清单文件。它可以将多个技能与其他 CoCo 扩展能力（包括钩子（Hooks）、MCP 服务器和自定义智能体）打包成一个支持版本管理、可安装的独立单元。

如果你的目标不只是教会智能体执行某一项工作流程，而是希望封装一套更完整的能力，就可以考虑创建插件。例如，将多个相关技能与生命周期自动化能力（如 Hooks），或通过 MCP 服务器提供的外部工具和数据连接整合在一起。

在开始具体操作之前，我们需要先区分三个容易混淆的概念：

本地技能（Local Skill）： 本质上只是一个包含 SKILL.md 文件的文件夹。它可以存放在任意指定位置，例如项目目录、用户主目录或 Snowflake 工作区；

Cortex 扩展（Cortex Extension）： 共享技能时在 Snowflake 中创建的对象。每个共享技能或插件对应一个扩展对象，支持版本管理、基于角色的访问控制（RBAC）权限授予，以及可发现性设置；

认证（Certification）： 由管理员针对扩展对象的特定版本授予的可信认证标识，表示“这是经过认可的版本”。认证与共享并不是一回事。共享可以由用户自行完成，而认证属于治理流程。

下文介绍的所有操作，都可以归入这三个层次之一。
