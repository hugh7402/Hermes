术语和定义
数据接入 data collection
数据接入是将分散的数据从一点或多点集中起来以在计算机中使用的过程。
【条文说明】在数据治理领域，数据接入可等同于“数据入湖”，指的是将数据集中并导入到数据湖的过程，这是数据治理和数据管理策略的重要组成部分。
[参考来源：《数据管理术语标准》]
结构化数据 structured data
一种数据表示形式，按此种形式，由数据元素汇集而成的每个记录的结构都是一致的并且可以使用关系模型予以有效描述。例：存储于关系型数据库中的各类库表数据。
[参考来源：《数据管理术语标准》]
非结构化数据 unstructured data
不具有预定义模型或未以预定义方式组织的数据。例：文本、图像、语音、视频、传感信号。
[参考来源：《数据管理术语标准》] 
数据湖 data lake
将来自不同数据源、不同数据类型的数据，以原始格式进行存储的系统，无需事先对数据进行结构化处理
[参考来源：《数据管理术语标准》] 
物理入湖 physical ingestion
将原始数据复制到数据湖中。
[参考来源：《数据管理术语标准》] 
虚拟入湖 virtual ingestion
原始数据不在数据湖中进行物理存储，通过建立对应虚拟表的集成方式实现入湖。
[参考来源：《数据管理术语标准》] 
离线同步 offline synchronization
按照预设的时间间隔，从数据源批量获取数据并同步至目标系统的方式。数据同步延迟通常在分钟级至小时级，甚至更长。
[参考来源：《数据管理术语标准》] 
准实时同步 near real-time synchronization
在数据生成后较短时间内完成传输和同步的方式。数据同步延迟通常在秒级至分钟级之间。
[参考来源：《数据管理术语标准》] 
实时同步 real-time synchronization
通过监听、订阅等方式持续感知数据源的变更，低延迟的将变更数据同步至目标系统的方式。数据同步延迟通常控制在毫秒级至秒级以内。
[参考来源：《数据管理术语标准》] 
数据虚拟化 data virtualization
一种数据管理技术，允许用户在不移动或复制数据的情况下，从多个来源访问和整合数据。
[参考来源：《数据管理术语标准》]

数据来源
数据来源包括业务系统在内的各类结构化数据和非结构化数据。其中结构化数据包括数据库表、CSV、TXT等类型，非结构化数据包括GIS、BIM、图片、文档、音频、视频等。
数据接入
数据接入负责完成数据入湖操作，包括连接数据源、执行数据抽取、转换与传输任务等。根据数据应用特征的不同，数据入湖可分为以下两种方式：
物理入湖：适用于多源异构的结构化数据和非结构化数据集成到数据湖进行物理存储，以支撑后续数据分析与加工的场景。根据数据源类型及其访问特性，可分为库表数据、文件数据、API数据和消息数据4类，每类数据的具体技术处理方式如下：
库表数据：可通过定时抽取实现离线同步，或通过高频轮询抽取实现准实时同步，或基于数据库变更捕获机制（如CDC）实现实时同步。
文件数据：可通过周期性扫描与拷贝实现离线同步，或通过高频轮询检测实现准实时同步，或结合文件系统变更监听与事件推送机制实现实时同步。
API数据：可通过定时轮询方式实现离线同步，或通过高频轮询请求实现准实时同步。
消息数据：可通过定时批量消费方式实现离线同步，或通过高频轮询消费实现准实时同步，或基于持续订阅与消费机制实现实时同步。
虚拟入湖：适用于多源异构的结构化数据不进行物理存储，非结构化数据解析为结构化数据后接入数据湖，以支持实时查询与分析的场景。
数据存储
入湖数据按照不同数据类型统一存储至数据湖。
数据接入技术要求
数据源类型要求
数据管理平台应支持对常见的、主流的数据源进行数据接入，包含但不限于以下类型:
关系型数据库：如MySQL、PostgreSQL、Oracle、SQL Server、DB2、MariaDB、人大金仓、达梦等；
大数据数据库：如Hive、MPP（ClickHouse、Greenplum、Apache Doris等）；
文件/对象存储：如Hadoop HDFS、FTP/SFTP、阿里云 OSS、MinIO 等；
消息队列：如Kafka、pulsar等；
接口服务：如Webservice,RestfulApi等；
时序数据库：如InfluxDB等。
物理入湖技术要求
库表数据入湖
功能要求
离线同步功能要求
数据管理平台应具备对主流关系型数据库、大数据数据库和时序数据库中的结构化数据进行离线同步的能力，并应满足但不限于以下功能：
支持对数据库中常用的数据类型进行数据同步，包括但不限于数值型、字符型、日期/时间型等；
支持“全量”和“增量”两种数据同步模式；
支持对数据库表进行字段映射、类型格式转换等操作；
支持在数据同步过程中，利用可视化配置或脚本配置等方式设置数据筛选规则，能够对字段值、时间范围等信息配置逻辑表达式，同时支持设置自定义变量配置筛选条件；
提供图形化管理界面，支持数据源配置、指定数据表配置、表字段选择配置、字段类型转换配置、目标存储位置配置等操作；
支持数据同步任务的立即执行和定期调度运行。
准实时同步功能要求
数据管理平台应具备对主流关系型数据库和时序数据库的结构化数据进行准实时同步的能力，并应满足但不限于以下功能：
支持对数据库中常用的数据类型进行数据同步，包括但不限于数值型、字符型、日期/时间型等；
支持基于轮询机制抽取源端数据，最小粒度应达到秒级；
支持对数据库表进行字段映射、类型格式转换等操作；
提供图形化管理界面，支持数据源配置、指定数据表配置、表字段选择配置、字段类型转换配置、目标存储位置配置、轮询周期配置等操作；
支持增量范围的精确判断和断点续传能力。
实时同步功能要求
数据管理平台应具备对主流关系型数据库的结构化数据进行实时同步的能力，并应满足但不限于以下功能：
支持的数据库应包括但不限于MySQL、PostgreSQL等数据库类型；
支持对数据库中常用的数据类型进行数据同步，包括但不限于数值型、字符型、日期/时间型等；
支持毫秒级时延的增量同步能力，同时支持在全量同步的基础上，无缝自动切换到增量同步模式；
支持对数据库数据的内容和类型转换操作，包括但不限于字段类型格式转换、时区转换等操作；
支持对同步对象的过滤，包括但不限于模式过滤、表过滤、字段过滤、数据行过滤等；
提供图形化管理界面，支持对数据表配置、表字段选择配置、字段类型转换配置、目标端输出配置、运行监控等操作；
提供“精确一次”处理语义。
应用要求
离线同步应用要求
库表数据离线同步应用要求如下：
数据源须提供数据库的访问链接，包括IP、端口、数据库类型及版本号、数据库名称、用户名、密码等，具体模版参考附件A；
数据源提供的访问账号应具备必要的读取权限，至少包括原始数据表的元数据和数据内容的读取权限；
选择增量同步模式时，源数据库表应包含可用于识别数据变更的增量字段（如时间戳、递增主键或其他变更标识字段）。
准实时同步应用要求
库表数据准实时同步应用要求如下：
源数据库应是关系型数据库或时序数据库；
源数据库应包含可用于识别数据变更的增量字段（如时间戳、递增主键或其他变更标识字段）；
数据源提供的访问账号应具备必要的读取权限，至少包括原始数据表元数据和数据内容的读取权限；
源端数据库应能够承受高频查询对业务系统性能的影响。
实时同步应用要求
库表数据实时同步应用要求如下：
源数据库应是关系型数据库；
源数据库表应包含主键或唯一索引；
源端数据库应开启附加日志和强制归档模式；
源端数据库的在线日志文件、归档日志文件应存放在文件系统上；
源数据库访问用户应具备读取日志文件、元数据及表结构信息的权限。
文件数据入湖
功能要求
离线同步功能要求
数据管理平台应具备对文件/对象存储系统中的结构化数据文件和非结构化数据文件进行离线同步的能力，并应满足但不限于以下功能：
支持基于正则表达式对源路径中的文件进行过滤；
支持对文件名变量进行提取、替换与传参；
支持对传输文件进行压缩处理，提供可配置的压缩策略；
支持配置目标文件的存储路径与动态重命名规则；
对结构化文件（如csv,txt等），应支持配置数据结构信息（如schema、字段类型、分隔符等），将文件内容转换为数据表同步至数据湖；
提供图形化管理界面，支持文件源配置、文件目标存储配置、文件压缩规则配置、文件名过滤配置等；
支持数据同步任务的立即执行和定期调度运行。
准实时同步功能要求
数据管理平台应具备对文件/对象存储系统中的结构化数据文件和非结构化数据文件进行准实时同步的能力，并应满足但不限于以下功能：
支持基于轮询机制对指定文件源目录或存储路径进行扫描，发现新增或更新的数据文件进行数据同步，最小粒度可达到分钟级；
支持配置目标文件的存储路径；
提供图形化管理界面，支持文件源配置、文件目标存储配置、轮询周期配置等操作。
实时同步功能要求
数据管理平台应提供对文件/对象存储系统中的结构化数据文件和非结构化数据文件进行实时同步的能力，并应满足但不限于以下功能：
支持利用可视化配置或脚本配置等方式，定义文件数据实时同步任务请求参数、文件目标存储路径等信息；
支持将文件数据实时同步至目标存储路径。
应用要求
针对文件数据的离线、准实时及实时同步，统一适用以下应用要求：
业务系统应统一管理文件的基本特征元数据信息，至少包括文件名称、大小、创建时间、修改时间、来源标识、格式类型及存储路径等；
GIS、BIM、音频、视频等非结构化数据应遵循国家、行业、企业的相关标准规范要求进行存储；
业务系统生成文件数据时应同时生成对应的完整性校验码，文件数据校验算法应支持标准的SHA-1进行校验，结果转化为16进制ASCII字符表示。
对于多文件组成的数据包，应提供清单文件，明确各子文件的内容、顺序与依赖关系；
数据文件访问应支持通过常用的数据存储协议或接口进行文件读取，包括但不限于 FTP、SFTP、HDFS及对象存储服务；
结构化数据文件转换为数据表同步至数据湖时，源端系统提供的文件应保持一致的数据结构信息；
实时同步场景下，源端系统应开启文件变更监听配置，在文件变更发生时，能够通过数据管理平台提供的文件同步服务同步至目标系统。
API数据入湖
功能要求
离线同步功能要求
数据管理平台应具备从源端系统开放的API中获取结构化数据和非结构化数据进行离线同步的能力，并应满足但不限于以下功能：
支持接入多种API接口的能力，包括RESTful、WebService 等不同类型的API；
应具备数据流编排能力，支持通过图形化配置化方式组装处理流程，支持常用数据处理算子（如字段映射、字段拆分/合并、格式转换、正则提取、异常处理等），可对 API 返回的多种格式（ JSON、XML、CSV、文本等）数据进行解析处理；
支持多种认证机制，包括但不限于 Basic Auth、Token、OAuth 2.0 等；
支持对 API 中路径参数、Query 参数、Header 参数、Body 参数等多种参数类型进行动态赋值；
支持数据同步任务的立即执行和定期调度运行。
准实时同步功能要求
数据管理平台应具备从源端系统开放的API中获取结构化数据进行准实时同步的能力，并应满足但不限于以下功能：
支持接入多种API接口的能力，包括RESTful、WebService等不同类型的API。
支持响应格式为JSON或TEXT的API；
支持基于轮询机制请求API，最小粒度应达到秒级；
支持通过图形化界面配置数据结构信息（如schema、字段类型等）、分页信息及请求参数信息等。并支持自动循环遍历多页API，将所有响应数据转换为数据表同步至数据湖；
提供图形化界面，支持API请求配置、schema配置、轮询间隔周期配置等操作。
实时同步功能要求
数据管理平台应支持从源端系统开放的API中获取结构化数据和非结构化数据进行实时同步、并具备以下功能：
支持利用可视化配置或脚本配置等方式，自定义Webhook数据接收接口；
支持通过外部系统触发Webhook接口，接收数据同步至数据湖。
应用要求
针对API数据的离线、准实时及实时同步，统一适用以下应用要求：
数据源提供的API接口应符合集团或行业关于数据格式及传输协议等方面的统一标准规范。
数据源需要实施有效的身份验证和加密传输措施，敏感数据的传输应使用HTTPS等加密协议，防止未授权访问和数据泄露，确保数据在传输过程中的安全性；
数据源提供的API应支持访问频控与错误返回机制；
高频轮询的API接口应具备高可用能力，其服务可用性应不低于99.99%；
数据源提供的API需支持分页、时间范围过滤、关键字段筛选等查询功能；对于分页或批量返回的数据，需明确返回总数、当前页码、记录范围等信息；
数据源提供的API应支持数据访问日志记录、异常事件预警和调用链路追溯能力。
消息数据入湖
功能要求
离线同步功能要求
数据管理平台应具备对消息队列中的结构化数据和非结构化数据进行离线同步的能力，并应满足但不限于以下功能：
支持指定消息数据源1个或多个topic进行消费；
支持指定消息数据源消费组ID；
支持指定多种消费模式，包括但不限于group-offsets、earliest-offset、latest-offset、timestamp以及specific-offsets；当为timestamp模式时，支持指定时间范围消费；
对结构化消息数据，应支持配置数据结构信息（如schema、format等），将数据内容转换为数据表同步至数据湖；
应支持自动记录和管理每次同步消费后的最新偏移量或时间点，并作为下次消费起点，实现增量数据同步能力；
支持断点续传；
提供图形化界面，支持topic配置、消费组配置、消费模式配置、schema配置等操作。
支持数据同步任务的立即执行和定期调度运行。
准实时同步功能要求
数据管理平台应具备对消息队列中的结构化数据和非结构化数据进行准实时同步的能力，并应满足但不限于以下功能：
支持指定消息数据源1个或多个topic进行消费；
支持指定消息数据源消费组ID；
支持指定多种消费模式，包括但不限于group-offsets、earliest-offset、latest-offset、timestamp以及specific-offsets；
对结构化消息数据，应支持配置数据结构信息（如schema、format等），将数据内容转换为数据表同步至数据湖；
支持基于轮询机制抽取源端数据，最小粒度应达到秒级。并支持自动记录和管理每次同步消费后的最新偏移量或时间点，作为下次消费起点；
支持“精确一次”传输语义；
提供图形化界面，支持topic配置、消费组配置、消费模式配置、schema配置、轮询间隔周期配置等操作。
实时同步功能要求
数据管理平台应具备对消息队列中的结构化数据及非结构化数据进行实时同步的能力，并应满足但不限于以下功能：
支持指定消息数据源1个或多个topic进行消费；
支持指定消息数据源消费组ID；
支持指定多种消费模式，包括但不限于group-offsets、earliest-offset、latest-offset、timestamp以及specific-offsets；
对结构化消息数据，应支持配置数据结构信息（如schema、format等），将数据内容转换为数据表同步至数据湖；
支持基于流处理引擎（如Flink、Spark Streaming）的实时数据处理模式；
支持“精确一次”传输语义；
提供图形化界面，支持topic配置、消费组配置、消费模式配置、schema配置、实时等操作，提供实时监控面板，展示消费延迟、吞吐量、错误率等关键指标。
应用要求
针对消息数据的离线、准实时及实时同步，统一适用以下应用要求：
数据源应具备实时生成与发送消息数据流的能力，其数据生成速率与频率应与数据管理平台的处理能力和分析时延要求相匹配；
数据源应支持通用、标准化的数据格式与通信协议（如HTTP、WebSocket等）；
消息传输过程中应采用安全通信机制，如基于 TLS/SSL 的加密连接、认证机制（如Token、OAuth）等。
虚拟入湖技术要求
原则上所有数据应进行物理入湖，如有特殊场景无法采用物理入湖方式，需向数信中心完成单独审批后方可采用虚拟入湖方式。特殊场景主要包括以下几类：
实时性要求极高且不具备实时同步条件；
因合规或安全策略限制不得持久化的数据；
其它经评估确有必要采用虚拟入湖的场景。
虚拟入湖针对结构化数据，通过数据虚拟化技术实现。
数据虚拟化
功能要求
数据管理平台应具备对各类数据源的结构化数据进行虚拟化接入的能力，并应满足但不限于以下功能：
支持对各类数据源的结构化数据定义虚拟表，提供字段映射、重命名、类型转换及表达式计算等功能；
支持跨源融合查询，通过虚拟表执行多表、多库、多协议的数据整合；
支持虚拟视图的嵌套定义与复用，便于构建多层逻辑模型；
支持查询性能优化，包括谓词下推、投影下推、并行度配置及结果缓存，并可设置缓存刷新策略；
提供虚拟表定义变更、访问与执行日志的监控与审计功能，支持血缘跟踪与性能诊断。
应用要求
数据虚拟化应用要求如下：
虚拟化接入的数据源需提供可读取的连接信息（地址、端口、协议、凭证）及元数据访问权限；
虚拟表定义应遵循统一命名规范，字段名称、类型、来源等元信息需完整标注。
数据接入异常处理机制
数据管理平台应具备数据接入异常处理能力，能够及时发现、响应、处理各类数据接入异常问题。
数据容错能力
数据管理平台应具备数据容错能力，能够自动识别和处理异常数据条目，具体包括但不限于以下功能：
对个别数据记录因格式错误、字段缺失、唯一性冲突等问题导致的接入失败，支持自动跳过等容错处理措施，避免因单条数据异常导致整批数据接入失败；
支持对异常数据的数量设置阈值，若异常条数超过预设阈值，则触发阻断作业；
自动重试机制
数据管理平台应支持在接入失败（如网络中断、接口超时、服务不可用等）时自动发起重试操作，具备包括但不限于以下功能：
支持对重试次数及重试间隔的灵活配置，重试过程应记录完整日志（包括失败原因、重试时间、结果等）；
重试失败的数据应被记录和标记，等待人工或系统触发的后续处理。
异常告警通知
数据管理平台应具备通过邮件、短信、企业微信等渠道通知异常告警的能力。
数据接入存储要求
接入数据应统一存储于数据贴源层ODS。
区域划分要求
为保证接入数据的规范化管理，应依据数据特性将其归类存放于以下三个区域：
实时数据区：存储实时生成的流式数据，包括传感器采集、日志埋点等低延迟、高频写入的数据，满足快速实时处理与分析需求。
结构化数据区：存放原始结构化表格数据，保持数据完整性和一致性，主要为后续清洗和加工提供基础数据支撑。
非结构化数据区：涵盖 GIS、BIM、文档、图像、音频、视频等非结构化文件，并辅以索引实现高效检索。
存储格式要求
为提升接入数据的处理效率，应根据不同数据类型选择合适的存储格式：
实时数据区适当采用 Avro 等行式二进制格式进行优化存储，并支持schema演化；
结构化数据区稀疏表适当采用Parquet或ORC等列式格式进行优化存储，并支持schema演化；
非结构化数据区应以原生二进制文件存储；
所有区域数据存储格式应支持数据版本管理。
分区分桶要求
为提高接入数据的查询效率，应结合数据特征制定合理的分区与分桶策略：
优先基于时间字段（如 year、month、day）进行分区，必要时结合业务维度字段进行二级分区；
对于高基数字段或频繁 join 字段，应采用固定桶数进行分桶存储。
数据压缩要求
为节约存储空间，提升数据传输效率，应根据数据类型与业务场景合理配置压缩策略：
对于需要压缩的接入数据，优先采用标准无损压缩算法（如 GZIP、ZIP、BZIP2等），并可按业务需求动态配置压缩级别；
接入的数据若已为压缩编码格式（如 JPEG、MP4、H.264 等），应直接以原始文件形式存储，避免重复压缩处理。
数据备份要求
为保障数据可靠性和灾难恢复能力，数据管理平台应具备多级数据备份机制对接入数据进行备份管理，支持通过自动化工具进行不同策略的备份，如定期备份、实时备份等。
数据接入质量要求
在数据接入阶段，应重点关注数据完整性、时效性的质量要求，并结合业务使用需求，在规范性、准确性、有效性、唯一性、一致性方面进行数据质量稽核。完整性、时效性的数据质量稽核要求如下：
完整性
字段完整：接入的数据字段完整，没有遗漏。
字段值完整：数据字段值完整，没有缺少字段值。
数据记录的完整：数据记录是完整的，没有缺少行。
及时性
数据入库及时：数据在预设的时间内，传输到数据管理平台。
数据更新及时：数据的更新频率,与预设的接入频率保持一致。
数据接入安全要求
数据接入的安全保护应符合GB/T 22239、GB/T 35274和GB/T 43697等国家标准及企业相关标准，实施分级分类的数据管理机制。针对数据接入过程中可能存在的安全风险，应结合实际应用场景，采取相应的安全技术和防护措施，确保接入数据的完整性与机密性。对于涉及个人信息、敏感数据及重要数据的内容，应加强安全管控，重点防范数据泄露、篡改及非法访问等风险。
