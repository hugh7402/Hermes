术语和定义、缩略语
下列术语和定义适用于本文件。
数据共享 data sharing
不同部门、系统或单位之间，在满足安全和合规前提下实现数据可用、可访问和可交换的过程。
[参考来源：《数据管理术语标准》]
数据服务 data service
数据服务是一种信息技术服务，它允许用户通过标准化的接口访问、检索、管理和操作数据。数据服务通常提供一种方式，使得数据能够以一种一致和可编程的格式被获取和使用。
[参考来源：《数据管理术语标准》]
查询共享 query sharing
使用方在需要时主动发起请求，由提供方即时返回结果的数据共享方式。
[参考来源：《数据管理术语标准》]
订阅共享 subscription sharing
使用方通过建立订阅关系，按照预设周期或触发条件，持续获取由提供方提供的数据的共享方式。
[参考来源：《数据管理术语标准》]
推送共享 push sharing
当触发条件满足时，由提供方主动向使用方传输数据的数据共享方式。
[参考来源：《数据管理术语标准》]
文件交换共享 file exchange sharing
通过传输双方约定格式的数据文件，批量实现数据交换的数据共享方式。
[参考来源：《数据管理术语标准》]
基本原则
数据共享应遵循以下原则：
——合法合规、权责清晰：严格遵守国家法律法规（如《数据安全法》《个人信息保护法》）及相关政策要求，确保数据来源合法、使用合规、责任可溯。明确数据提供方、使用方和管理方的权利与责任，落实数据共享全过程的合规管理。
——安全可控、分类分级：基于数据分类分级结果实施差异化安全管理，对核心数据、敏感个人信息等高风险数据采取强化保护措施。贯穿数据全生命周期，防范泄露、篡改、丢失等风险，确保共享过程可管控、可审计、可追溯。
——最小必要、目的限定：共享范围应以实现特定业务目标为限，仅提供必要的最小数据集，避免过度采集与超范围共享。数据使用须严格限定于约定用途，未经重新授权不得用于其他目的。
——质量可靠、全程可溯：保障共享数据的准确性、完整性、时效性与一致性，提升数据可信度与可用性。建立全流程操作日志与数据血缘追踪机制，实现“来源可查、去向可追、责任可究”。
——协同高效、共建共享：以业务需求为导向，推动跨部门、跨单位的数据协同与资源共建。优化共享流程，降低协作成本，提升数据利用效率和综合价值，促进组织数字化能力整体提升。
共享场景
概述
数据共享服务场景基于数据使用目的、时效性要求、业务交互模式可划分为以下两类：分析型场景和事务型场景。

图 1 共享场景分类
分析型场景
分析型场景指跨系统、跨部门数据关联查询分析，包括离线和实时（例如：业务决策与经营监控、精准营销与用户运营、风控与合规管理、产品创新与运营优化‌）；高复用单系统数据查询分析（离线）。该类场景由数据中台统一支撑。
事务型场景
事务型场景指增、删、改业务数据操作（本系统以及跨系统），查询业务操作（数据要求实时变化）。该类场景由业务系统负责支撑。
共享方式
概述
数据共享方式按照不同的划分逻辑可有多种分类，如按技术实现机制可分为接口调用、文件交换、数据库直连等，按数据流转模式可分为推送、订阅、拉取等。本文件以业务场景需求和使用者视角为核心出发点，聚焦数据共享的实际应用形态，将其分为以下四类：查询共享、订阅共享、推送共享和文件交换共享。
查询共享
适用于数据使用方按需获取数据、查询条件动态变化、无需长期存储数据的场景。需要在不直接访问底层数据源的前提下，快速获取精准结果，且调用频率不固定、单次数据量较小。查询共享应通过标准化API服务实现，并支持访问控制与审计。
订阅共享
适用于数据使用方需要长期、周期性获取结构化数据，且需基于共享数据进行本地二次加工、分析建模或报表开发的场景。订阅共享通过周期性更新的库表实现，数据使用方完成审批流程后获取指定库表的访问权限，可选择全量或增量的方式将数据同步至使用方的数据环境。
推送共享
适用于对时效性要求较高的业务场景，通过系统主动将数据实时或准实时地发送至接收方，实现快速响应与即时处理。推送共享通过消息队列等方式实现，数据使用方需明确数据推送的目标对象，并配置对应的接收渠道获取数据。
文件交换共享
适用于大批量离线数据传输的场景，适配单次传输数据量大、对实时性要求低、数据格式灵活多样的业务需求。文件交换共享通过标准化文件服务与专用传输通道实现，同时支持精细化权限管控、全链路版本管理与数据传输校验，保障数据共享的安全性、一致性与可追溯性。

查询共享
查询共享使用API服务作为技术实现方式。
（1）接口遵循OpenAPI3.0规范，统一JSON响应格式与错误码体系；​
（2）支持字段级筛选，单次返回结果不超过1000条；​
（3）支持访问权限控制。
订阅共享
订阅共享使用离线的结构化库表作为技术实现方式。
（1）数据同步支持全量与增量两种方式；​
（2）库表按业务主题分区，字段遵循数据元目录标准，主键唯一；​
（3）支持访问权限控制，支持库表级/字段级只读授权。
推送共享
推送共享使用消息队列等作为技术实现方式。
（1）消息格式支持JSON/Protobuf，包含消息ID、来源、时间戳、数据级别等固定头部；​
（2）主题命名包含：业务域、数据类型，支持优先级划分；​
（3）消费端支持ACK确认机制，支持回溯消费。
文件交换共享
文件交换共享使用文件服务等作为技术实现方式。
（1）支持文件格式：CSV、Parquet、JSON、日志文件，单文件≤100GB；​
（2）文件名命名包含：数据类型、时间戳、版本号；​
（3）传输采用SFTP协议，支持分片（≤100MB/片）与断点续传。
数据安全
概述
数据共享的安全性是保障系统稳定运行和合规使用的重要前提。为此，需要从多个层面构建全方位的安全措施：通过身份认证确保调用主体可信，通过权限控制实现细粒度的数据访问管理，通过加密与传输安全保障数据在流转过程中的机密性与完整性，并通过日志审计与合规管理实现全过程的可追溯与符合法规要求。
身份认证
所有接口调用应采用双因素或多因素认证机制。认证令牌宜基于JWT，令牌有效期不应超过15分钟。
权限控制
访问控制应基于最小权限原则，并支持属性级细粒度授权。敏感数据应进行脱敏处理。
传输安全
数据传输应启用 TLS 1.3，禁用弱加密算法。跨安全域传输应通过DMZ并进行双向证书认证。
数据完整性
数据传输前后应进行哈希校验，推荐使用SHA-256。
日志与审计
所有共享操作应记录日志，日志应保存不少于180天，并具备快速检索能力。
审计追溯
应建立数据血缘关系，确保共享数据来源、去向可追溯。
合规性要求
数据共享应满足以下合规性要求：
系统应符合网络安全等级保护要求，能源业务不应低于三级；
涉及能源交易的数据应符合国家能源监管要求；
数据共享应遵守数据安全法、网络安全法和个人信息保护法；
涉及跨境数据传输的，应按照国家有关规定进行安全评估并签署合规协议。
