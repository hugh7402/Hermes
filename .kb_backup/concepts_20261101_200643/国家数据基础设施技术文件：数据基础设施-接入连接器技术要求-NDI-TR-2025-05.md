II
前
言
本技术文件用于指导各地方各行业各领域的数据基础设施建设。文件围绕接入连接器的总体框架、
功能架构、标准能力、扩展能力、安全保障能力提出具体要求，为构建推动形成横向联通、纵向贯通、
协调有力的国家数据基础设施提供标准支撑。
本技术文件试用期6个月，将在试行试用中不断迭代优化，后续将推动形成数据领域国家标准。

数据基础设施接入连接器技术要求
1
范围
本文件规范了接入连接器的标准能力要求、扩展能力要求、安全保障要求以及互操作要求，用于指
导接入连接器的设计和开发、异构接入连接器的对接和测试。
本文件适用于数场、可信数据空间、数联网、数据元件、隐私保护计算、区块链等技术体系支撑的
各类层级的数据基础设施建设，包括区域、城市、行业、企业、个人等数据基础设施。
2
规范性引用文件

3
术语和定义
下列术语和定义适用于本文件。
3.1
接入连接器access connector
连接接入主体与接入主体或接入主体与业务节点的规范化软硬件系统，数据供需双方均可通过接入
连接器接入数据基础设施。
3.2
访问策略access policy
指可在接入连接器内自动化解析执行的机器可读的指令语言，用于控制接入连接器在许可范围内访
问、使用数据资源。
3.3
数据使用控制策略data usage control policy
用于管理和约束数据使用方在处理、流通、销毁等各阶段内使用数据的一系列方法和技术。

5
总体框架
数据基础设施接入连接器的能力主要包括标准能力、扩展能力、安全保障能力。
接入连接器应支持对接区域/行业功能节点，实现接入连接器的身份注册、身份认证和运行状态信
息上报。
接入连接器应支持对接业务节点，实现运行状态信息上报和控制指令信息获取。
接入连接器应支持对接数据提供方、数据使用方本地应用、数据库，实现数据接入与获取，接入连
接器在业务节点的协调下，可实现点对点相互连通，并按照控制指令信息完成数据传输。

能力要求
6.1
功能架构
接入连接器标准能力包括身份认证、网络接入、数据交付、数据访问控制、日志记录、运行状态上

接入连接器扩展能力包括数据产品目录服务、数据使用控制、隐私保护计算能力集成、高速数据网
接入以及其他关键技术组件扩展能力等。

接入连接器可以多种形态体现，如Ukey、软件系统、软硬件结合的终端等，不同形态的连接器具备

6.2
标准能力
6.2.1
身份认证
接入连接器应支持可信身份凭证的管理，可信身份凭证应符合NDI—TR—2025—03的要求。
接入连接器应支持基于可信身份凭证实现接入连接器用户身份认证。
6.2.2
网络接入
接入连接器应支持不同类型的网络接入，包括但不限于互联网、专线等，以连接业务节点、其它接
入连接器，实现不同网络接入主体的数据参与方快速连通。
6.2.3
数据交付
接入连接器应支持API数据接口、批量数据流等方式进行数据交付；
接入连接器可提供API数据接口、批量数据流鉴权信息等配置能力；
接入连接器可支持本地数据源维护，管理数据源访问地址等信息。
6.2.4
数据访问控制
在数据交付过程中，数据提供方接入连接器应通过获取、解析数据交易控制指令（参照
NDI—TR—2025—02）识别待交付数据产品、数据访问控制策略等信息，并根据策略对数据使用方的
访问进行权限检查，确保按权限访问数据。
6.2.5
日志记录
接入连接器应支持记录系统日志、操作日志、业务日志等信息，支撑审计、运维工作；
接入连接器应支持按照用户定义的规则记录数据调用次数、使用时长、使用量等信息；
日志的留存时间应满足国家相关法律法规要求，不低于六个月。
6.2.6
运行状态上报

6.3
扩展能力
6.3.1
数据产品目录服务
接入连接器可支持数据提供方创建、管理数据产品目录；
接入连接器可在无需平台参与的情况下提供连接器之间的数据产品目录服务，以供其他接入连接器
查询。
6.3.2
数据使用控制
接入连接器可支持加载解析数据使用控制策略并按策略执行，以支持数据提供方通过使用次数限制、
使用周期限制等策略，约束数据使用方使用数据。
6.3.3
隐私保护计算能力集成
接入连接器可通过对接隐私保护计算节点，将控制指令信息同步给该节点，并将隐私保护计算过程
中需要交互的信息在各接入连接器间、接入连接器与业务节点间传输。
6.3.4
高速数据网接入
接入连接器可通过维护下一跳网络地址、高速数据网接入服务地址等配置，快速接入高速数据网。
6.3.5
其他关键技术组件扩展
接入连接器可通过接口配置、能力集成等方式，根据用户需求动态扩展各类关键技术组件。
7
互操作要求
7.1
连接器身份认证要求
7.1.1
连接器间身份认证
接入连接器应支持基于可信身份凭证实现连接器之间的双向认证，双向认证应符合
NDI—TR—2025—03的要求。
7.2
数据产品目录查询要求
7.2.1
数据产品目录检索服务
接入连接器之间进行数据产品目录检索时应遵循统一的参数要求。
——请求参数应包含检索关键字、排序规则、开始偏移量、限制条数、目标连接器ID、发起连接
器ID、发起时间、扩展信息等。应符合附录A.1。
——响应参数应包含状态码、消息描述、消息体、所有页记录总数、本页结果、数据产品唯一标

7.2.2
数据产品详情查询服务
接入连接器之间进行数据产品详情查询时应遵循统一的参数要求。
——请求参数应包含数据产品唯一标识、数据产品名称。应符合附录A.3。

7.3
数据接口要求
7.3.1
API 数据接口方式
接入连接器间API数据接口应符合统一的传输协议、请求参数和返回参数要求。
7.3.1.1 传输协议
接入连接器间应支持HTTPS作为API接口传输协议，应支持restful类型的接口。
7.3.1.2 请求头参数
请求头中应包括请求唯一标识、目标连接器、发起连接器、数据产品唯一标识、控制指令编号等参
数；可包括请求内容摘要、鉴权信息、X-Forwarded-For等参数。API接口请求头参数详见附录B.1。
——请求唯一标识：使用方32 位随机字符串。用于核对调用请求，进行故障排查。
——连接器唯一标识：发起请求的接入连接器唯一标识，用于明确请求来源。
——连接器鉴权信息：根据数据使用方与数据提供方协商的身份验证手段生成，可选数字证书签
名、app 调用凭证等，用于向请求目标证明接入连接器的请求合法性。
——请求内容摘要：由发起请求的接入连接器生成，使用哈希加密算法对请求Body 参数进行摘要
计算，用于验证请求内容的完整性。
——数据产品唯一标识：从控制指令信息中获取。数据使用方接入连接器调用时传递，用于提供
方接入连接器确定被调用产品。
——控制指令编号：从控制指令信息中获取。数据使用方接入连接器调用时传递，用于提供方接
入连接器执行访问控制。
——X-Forwarded-For：RFC 7239（Forwarded HTTP Extension）标准定义的HTTP 扩展头字段，表
示HTTP 请求端真实IP。
7.3.1.3 Body 参数
API接口请求Body体参数由数据产品提供方自主定义，传递参数为中文字符时，应使用UTF-8方式
进行编解码。
7.3.1.4 返回参数
API接口调用结果应通过返回码反馈。返回码类别详见附录C，返回码定义详见附录D。
API接口调用返回参数应包含状态码、消息描述、原始API响应头和原始API响应报文等信息。API
接口响应参数详见附录B.2，调用返回报文示例详见附录E。
7.3.2
批量数据流方式
接入连接器间批量传输数据时应遵循统一的参数要求。
——请求参数应包含目标连接器ID、发起连接器ID、发起时间、数据产品标识、数据产品名称等
信息。详见附录B.3、B.5。
——响应参数应包含状态码、消息描述、消息体、连接器ID 等信息。详见附录B.4、B.6。
7.3.3
数据传输协商
使用方和提供方未从控制指令信息中获取足够的数据传输协议或参数的情况下，可先协商再传输，
协商分为两步：
——使用方连接器通过数据传输协商接口向提供方连接器协商数据传输协议、授权码、地址等详
细传输参数。
——协商完成后，双方使用达成一致的数据传输标准协议等进行数据传输。

安全保障
8.1
标识和鉴别
接入连接器应基于数字证书实现双向身份验证、唯一标识比对等方式核验所对接的接入连接器身份，
确保对接连接器的身份可信；
接入连接器可支持对用户的多因素认证（如动态口令、短信验证码等）和密钥核验等方式，验证用
户身份的真实性，确保只有授权用户能够访问系统；
应保障用户和接入连接器自身的标识和鉴别信息在传输和存储过程中的保密性和完整性；
使用口令鉴别方式时，应提供用户身份鉴别信息复杂度验证功能和定期更换设置功能，并支持首次
管理接入连接器时强制修改默认口令或设置高强度口令。
8.2
访问控制
对接入连接器的用户分配账户和权限，区分管理员角色，实现管理权限相互制约；
对接入连接器自身应支持通过配置ACL策略、白名单管控等方式，控制网络访问权限；
应配备必要的网络安全能力，防止被攻击或入侵。
8.3
系统安全
支撑接入连接器的软件代码应经过严格的安全审计，不应包含已公开的中、高风险漏洞；
应定期检查和更新依赖的第三方库、框架等组件，防止因组件漏洞导致的安全风险；
接入连接器的运行环境应具备安全防护机制，防止恶意软件入侵或未经授权的访问。在启动与升级
部署过程中，应具备版本完整性校验功能，防止软件被篡改。
8.4
数据安全
采用加密协议（如TLS/SSL）保障网络通信的安全与可信，防止数据在传输过程中被窃取或篡改；
接入连接器可通过报文签名、数据加密等方式，保障对接、传输过程中的数据安全，防止传输的数
据被篡改、泄漏；
接入连接器应支持在识别到数据存在风险时终止交付。
8.5
用户信息安全
接入连接器仅收集实现功能所必需的用户信息；
在涉及个人信息传输和存储的过程中保障个人信息的保密性和完整性；
在涉及个人信息存储时提供对超出保存期限个人信息的处理功能。
