## 一、数据治理
数智消防建设框架思路明确：国家局统筹建设国家局和总队两级数据治理系统和服务总线系统，国家局系统通过与应急部服务总线接入部大数据资源池，未建设的总队复用国家局数据治理软件工具，已经建设的总队级单位按标准接入。（此部分是概要不用编写）
### （一）政策分析
政策分析（政策名称 - 核心内容 - 支撑依据对应关系）
国家战略要求：深入贯彻《数字中国建设整体布局规划》与“数据要素×”三年行动计划，落实《政务数据共享条例》，推动消防数据作为核心生产要素在实战中的价值释放。
行业标准指引：依据《高质量数据集构建指引》及应急管理部相关数据治理规范，强调数据的标准化、鲜活性与安全性。
消防现状需求：针对当前消防系统（如OA、执法、119、后勤等）存在的“数据孤岛、多头录入、跨网交互难”等痛点，亟需通过“十五五”规划实现从“业务驱动数据”向“数据驱动业务”的转型。
  《数字中国建设整体布局规划》 ：坚持数字赋能行业转型，推动跨层级、跨部门数据互联互通，构建集约化、一体化的数据治理体系，实现 “数据驱动业务” 升级   
契合消防 “集约化建设” 要求（2025 年 11 月应急部数字化消防整体思路），解决当前 OA、执法、119 等系统 “数据孤岛、多头录入” 痛点；
支撑国家局统筹建设两级数据治理系统，未建总队复用、已建总队按标准接入的一体化架构；
 呼应 “十五五” 规划中消防从 “业务驱动数据” 向 “数据驱动业务” 转型的核心目标  
  《“数据要素 ×” 三年行动计划》  ： 激活数据要素核心价值，推动高质量数据集构建，强化数据在行业实战场景中的深度应用，建立数据全生命周期管理机制   
支撑消防六大核心高质量数据集（力量调派、火灾防控、监督执法等）构建，服务灭火救援、风险评估等实战场景；
契合数据治理系统 “接入 - 处理 - 管控 - 服务” 全流程设计，提升数据价值密度（与 2019 任务书数据处理、管控功能要求一致）；
指导社会面数据 “按标准剥离、仅接收不管理” 的治理模式，聚焦核心数据要素应用  
  《政务数据共享条例》   ：明确政务数据跨部门、跨层级共享的义务与标准，要求建立统一的共享交换平台，实现数据 “一数一源、按需共享”   
支撑国家局与应急部、总队与国家局、总队与地方政务平台的三级共享交换（与 2019 任务书 “跨业务、跨应用、跨部门共享” 要求一致）；
规范已建总队（11 个）按标准接入国家局服务总线，未建总队（20 个）复用系统的数据共享机制；
 指导消防与自然资源、水利、气象等部门的横向数据对接，通过政务共享交换平台获取外部数据资源  
  《高质量数据集构建指引》   ：规定数据集标准化、结构化、鲜活性建设要求，明确数据清洗、整合、标注的流程规范，支撑 AI 模型训练与行业应用  
指导消防数据处理子系统的 ETL、去重、补全、关联融合功能开发（呼应 2019 任务书数据处理核心要求）；
解决执法系统新旧两期数据未汇总、OA 系统非结构化文档迁移等存量数据质量问题；
为数据标注子系统提供规范依据，保障大模型训练样本的高质量（如火灾现场视频、数字化预案的结构化标注）  
  《应急管理部数据治理相关规范》   要求应急系统数据全生命周期管控，建立统一数据资源池、服务总线，实现部省两级数据贯通与业务协同  
明确国家局数据治理系统接入应急部大数据资源池的技术路径（与 2019 任务书 “部省两级数据共享交换” 要求一致）；
 规范数据资源池 “原始库 - 资源库 - 主题库 - 专题库” 四级架构（契合 2019 任务书数据资源池建设标准）；
 支撑机动总队（10 个）通过多租户模式复用国家局工具，符合应急管理部 “统建复用” 的集约化要求  
  《数据安全法》 ：  强调数据分类分级保护，规范跨网络、跨部门数据传输的安全机制，明确敏感数据的管控边界   
指导消防指挥网（涉密）与政务外网（非密）的跨网安全交换机制设计，避免敏感数据泄露；
支撑社会面数据 “运维厂商清洗剥离、消防局仅接收” 的管控模式，明确数据安全责任边界；
保障灭火预案、三维建筑模型、119 接警数据等敏感数据的全生命周期安全（契合 2019 任务书数据管控中安全管理要求）  
基础支撑约束
网络环境约束：需严格遵循《数据安全法》《应急管理部数据治理相关规范》，针对消防指挥网（涉密 / 敏感）与电子政务外网（非密 / 互联网交互）的物理隔离特性，建立符合安全标准的跨网数据交换机制，确保数据传输过程可追溯、可管控。
存量系统约束：依据《高质量数据集构建指引》《政务数据共享条例》，兼顾老旧系统（早期三级部署的 OA 系统、2020 年前执法系统）的历史数据清洗与迁移，通过前置库中转方式接入数据，规避对在用业务系统的性能影响，同时解决 “一数多源、数据分散” 问题。
合规管理约束：遵循《政务数据共享条例》中 “一数一源” 要求，统一消防数据编码标准与资源目录，确保已建总队（11 个）按标准对接、未建总队（20 个）复用系统的数据一致性，符合应急管理部数据目录同步要求。
### （二）建设内容与集成关系
应用技术
充分采用成熟可靠与前沿创新相结合的技术路线，以 2019 年应急部数据治理技术架构为基座，引入面向 AI 的新技术：
核心技术：分布式大数据存储与计算（Hadoop/Spark）、流式计算（Flink）、数据虚拟化、API 网关技术（满足 2019 任务书数据接入、计算、服务层技术要求）。
增强技术：引入数据标注技术（为大模型训练提供高质量样本）、可信数据空间技术（保障社会面数据安全交互，符合《数据安全法》要求）、服务总线技术（实现 “1+3+56” 纵向数据汇聚与横向交互，契合《政务数据共享条例》跨层级共享要求）。
建设功能及发挥的作用

数据治理系统由数据接入、数据处理、数据资源池、数据管控、数据服务、数据共享交换、数据标注等功能构成。本系统采用分层解耦架构，核心功能模块及作用如下：
数据接入子系统：
功能：提供数据探查、断点续传、数据对账、任务管理、数据分发功能（延续 2019 任务书核心功能，补充适配多源数据场景）。支持批量采集、实时采集、一键智采；涵盖结构化、半结构化、非结构化及接口数据；支持 MySQL、Hive、Kafka、达梦、GBASE 等多种主流信创数据源；提供采集安全配置，支持 SM2/SM4 等国密算法加密与脱敏。
作用：建立数据 “前置库”，实现对内部系统（执法、119、后勤装备）、外部共享（水利、气象、自然资源）、社会及感知数据（舆情、物联网）的全量接入。针对社会面数据，按《高质量数据集构建指引》建立标准规范，由运维厂商清洗后剥离接入，减轻局端管理压力。通过目录源管理、资源变更预警、统一调度监控，实现数据采集过程的可视、可管、可控。
数据处理子系统：
功能：具备 ETL（抽取、转换、加载）、数据清洗、去重、补全、关联融合、数据比对、数据标识能力（全面覆盖 2019 任务书数据处理要求）。提供工程开发、任务调度、模型管理；支持 SQL、Shell、Spark 等多种脚本类型；
作用：解决多源异构数据（如执法系统新旧两期数据差异、OA 非结构化文档）的标准化问题，提升数据质量，为高质量数据集构建奠定基础（符合《高质量数据集构建指引》要求）。通过可视化流程编排与智能调度，实现数据从采集、清洗、稽核到入库的全链路自动化处理。
数据资源池：
架构：建设原始库（原样存储）、资源库（标准化清洗）、主题库（应急环境、救援资源、火灾事故、管理对象等）、专题库（自然灾害监测、安全生产监管、火灾防控等）（与 2019 任务书资源池架构一致，补充消防特色主题 / 专题）。支持数据、维度建模、标签管理、指标管理、数据开发，支撑主题与专题数据组织。
作用：形成统一的消防数据资产底座，支持跨业务域（监督管理、监测预警、指挥救援、决策支持、政务管理）的数据调用，契合《“数据要素 ×” 三年行动计划》数据价值释放要求。通过资源目录、标签体系、指标市场，实现数据资产的分类、检索、订阅与共享。
数据管控子系统：
功能：涵盖数据标准管理、元数据管理、数据质量监控、资源目录管理、数据字典管理、数据运维管理、数据血缘管理（延续 2019 任务书管控核心功能，强化全生命周期管控）。提供数据标准稽核、元数据采集与血缘分析、数据质量规则库、数据认责流程、数据生命周期管理、系统级租户与权限管理
作用：实现数据全生命周期的 “可视、可控、可管”，确保数据符合《政务数据共享条例》《高质量数据集构建指引》的标准化、合规化要求。通过全链路血缘追踪、影响分析、孤岛识别、质量评分与告警，提升数据可信度与治理效率。
数据标注子系统（新增）：
功能：提供文本、图像、视频的智能化标注工具（适配大模型训练需求）。支持多模态标注工具，覆盖文本、图像、音频、视频等多种数据类型，配备智能辅助标注功能；集成预标注能力，结合AI模型实现自动化初标，提升标注效率；支持标注流程模板配置，如双盲、多轮复核等标准化流程；具备标注任务分发机制，支持按角色、技能进行任务分片与动态调度；提供知识抽取智能算子，从非结构化数据中提取实体、关系等知识要素，辅助结构化标注；配备质量控制域，通过质量评测任务管理、多维度评测指标库及可视化评测报告，对标注结果进行闭环质量保障。
作用：为 “消防大模型” 提供高质量训练样本（如火灾现场视频识别、预案文本结构化、三维模型标注），符合《“数据要素 ×” 三年行动计划》中数据支撑 AI 应用的要求。通过运营管理域的流程审批、角色权限与算子管理，实现标注流程的规范化与人员协同；通过个人工作域的任务派发、工作台与消息提醒，提升标注人员的操作效率与任务管理能力；通过可信保障域的数据分类分级、敏感信息识别与脱敏、访问审计等能力，确保标注数据在全生命周期的安全与合规使用，构建从“采、治、构”到“知、测、用”的闭环数据生产流水线。
数据服务与共享交换：
功能：基于服务总线提供 API 接口、数据目录订阅、数据授权、数据索引、数据可视化、交换中心管理、资源发布订阅服务（整合 2019 任务书服务与共享交换功能）。支持统一服务管理（表转服务、Restful 注册、服务编排）、数据服务门户、商业智能分析、智能报表管理、应用方管理与链路追踪。
作用：对上接入应急部大数据资源池，对下服务总队 / 支队，横向对接地方政务数据平台，实现跨层级、跨部门数据共享（完全契合《政务数据共享条例》核心要求）。通过服务超市、接口开发、用数申请流程、数据产品上架、数据沙箱等机制，构建“数据—服务—应用”闭环，支持数据安全可控共享与价值释放。
系统集成关系
纵向集成：
国家消防救援局：统建数据治理系统核心版与服务总线，以多租户模式直接支持 10 个机动总队（业务较少，无需独立建设）及未建设数据治理平台的总队（约 20 个），符合《应急管理部数据治理相关规范》“统建复用” 要求。
消防总队：已建平台总队（约 11 个）通过标准接口对接国家局服务总线，按《政务数据共享条例》要求实现数据同步；未建平台总队（约 20 个）直接复用国家局提供的软件工具，部署于本地政务云。
城市支队：通过总队级系统的多租户功能开通权限，不单独建设数据节点，契合集约化建设思路。
横向集成：
与应急管理部：作为独立节点接入应急部数据湖，按《应急管理部数据治理相关规范》实现目录同步与数据反哺。
与地方政务：在政务外网部署，通过政务共享交换平台获取自然资源、建筑图纸（住建）、气象等外部数据，符合《政务数据共享条例》跨部门共享要求。
数据治理服务
（1）信息资源规划：全面梳理消防信息资源目录，按《政务数据共享条例》《应急管理部数据治理相关规范》编制 “一数一源” 清单，统一数据编码标准，解决 “数出多门” 问题；定期与部级数据治理系统的资源目录实现同步，为数据接入、汇聚、交换、应用提供技术约束。
（2）数据治理服务实施：组建专业数据治理团队，开展历史数据清洗（特别是 OA 文档非结构化数据、执法系统两期分散数据）、存量数据迁移、数据质量常态化监测服务；遵循《高质量数据集构建指引》，建立数据质量考核机制，确保数据鲜活性、准确性。
（3）支撑高质量数据集构建：重点构建以下六大核心数据集，支撑实战与 AI 应用（契合《“数据要素 ×” 三年行动计划》要求）：
力量调派数据集（车辆、人员、物资实时状态）
火灾防控数据集（隐患排查、重点单位画像）
监督执法数据集（双随机检查、行政处罚案卷）
火灾风险评估数据集（城市火灾风险模型因子）
灭火救援预案数据集（数字化预案、三维建筑模型）
队伍管理数据集（人员训练、晋升、健康档案）
### （三）建设模式投资测算
国家局层面要以多租户方式支持机动总队，总队层面需要多租户支持支队。
模式一：国家局统建数据治理系统、服务总线，获得软件产权，为未建设的总队（约 20 个）部署数据治理系统。
投资构成：软件研发费用（含核心功能、多租户模块、服务总线）、部署实施费用（20 个总队政务云部署适配）、数据治理服务费用（历史数据清洗、资源规划、数据集构建）、安全合规适配费用（跨网交换、数据加密）。
政策依据：契合《数字中国建设整体布局规划》《应急管理部数据治理相关规范》的集约化建设要求，降低未建总队单独建设成本，保障数据标准统一。
模式二：采购成品软件模式。国家局和未建设的总队（约 20 个）分别通过采购成品软件授权方式进行建设。
投资构成：国家局成品软件采购及定制化改造费用（适配消防业务场景、对接应急部资源池）、20 个总队软件授权费用、本地化部署适配费用、数据治理服务外包费用。
政策依据：需确保采购软件符合《政务数据共享条例》《高质量数据集构建指引》的技术标准，支持多租户架构、跨部门数据交换，满足消防数据全生命周期管控要求。
本项目预计总投资为2000万元。

### （一）政策分析

### （二）建设内容与集成关系
应用技术
核心技术：依托久安大模型基础底座（自然语言处理、计算机视觉、多模态融合），采用微调训练、提示工程、模型压缩等技术，适配消防垂类场景。
支撑技术：分布式 GPU 算力调度技术、知识库构建与更新技术（知识图谱、语义检索）、跨网数据安全传输技术（符合《数据安全法》要求）、模型部署轻量化技术（适配总队 / 支队终端设备）。
建设功能及发挥的作用
消防垂类大模型核心功能：
火灾防控大模型：基于火灾防控数据集，实现火灾隐患智能识别（图像 / 文本分析）、重点单位风险分级、防控建议生成，支撑非现场监管。
灭火救援大模型：基于灭火救援预案、力量调派数据集，实现警情智能研判、调度方案生成、三维场景模拟推演，提升 119 指挥效率。
监管执法大模型：基于监督执法数据集，实现执法文书智能生成、法条精准匹配、执法流程指引，减轻执法人员负担。
队伍管理大模型：基于队伍管理数据集，实现人员训练方案个性化推荐、晋升趋势分析、健康风险预警。
辅助功能：
智能体开发平台：支持总队按需定制业务智能体（如专项执法智能体、区域救援智能体）。
模型管理平台：实现模型训练、部署、迭代、监控的全生命周期管理，确保模型性能稳定。
系统集成关系
纵向集成：国家局统筹建设消防垂类大模型核心版与行业知识库，通过 API 接口向各总队 / 支队提供服务；总队基于本地业务需求，通过模型微调工具优化适配，不单独建设大模型底座（契合集约化要求）。
横向集成：
与消防数据治理系统：从数据治理系统的高质量数据集、标注子系统获取训练 / 推理数据，实现 “数据 - 模型 - 应用” 闭环。
与久安大模型平台：按思路一在久安知识库构建消防大模型专区，通过服务总线实现数据交互（符合《“人工智能 +” 行动计划》统筹复用要求）。
与业务系统集成：对接 119 指挥系统、监督执法系统、OA 系统，嵌入模型能力，实现智能功能无缝嵌入业务流程。
跨网集成：针对指挥网使用需求，采用 “政务外网模型推理 + 指挥网结果反馈” 的跨网方案，通过安全传输通道实现数据交互，符合《数据安全法》《应急管理部数据治理相关规范》。
### （三）建设模式
国家局统筹主导模式：国家局依托久安大模型平台，统一建设消防垂类大模型核心底座与行业知识库，承担模型研发、算力投入、知识库更新等核心成本。
总队层面：各总队通过申请接口授权，结合本地业务数据（经数据治理系统标准化后）进行模型微调，提出功能优化需求，无需单独投入算力与研发资源。
投资构成：国家局层面（模型研发费、算力租赁费、知识库建设费、跨网安全适配费）；总队层面（接口授权费、本地微调适配费、业务对接改造费）。
政策依据：契合《“人工智能 +” 行动计划》《应急管理部人工智能应用专项规划》的统筹复用要求，降低地方建设成本，保障模型标准统一。
国家局 + 地方协同模式：国家局建设大模型基础框架与通用知识库，地方总队（有条件的）结合区域特色（如化工园区救援、高层建筑火灾）投入算力与数据，联合开展专项模型训练。
投资构成：国家局（基础框架研发、通用知识库建设）；地方总队（专项场景数据标注、算力租赁、联合研发）。
政策依据：兼顾统一标准与区域特色，符合《生成式人工智能服务管理暂行办法》中行业场景适配要求，提升模型实战针对性。
